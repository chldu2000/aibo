# 会话与工作区只读侧栏 · 首期交付规格

Status: ready-for-agent

## Problem Statement

用户看到输入框上方的终端或子 Agent 数量时，想知道哪个任务在运行、做了什么、发生了什么错误。当前需要在消息流里翻找工具调用。要判断 Agent 对工作区做了什么，还得离开会话，另外打开目录或 Git 工具。同一文件先暂存、随后又被修改时，用户尤其需要知道自己看到的是哪一次改动。

## Solution

用户从会话标题的详情入口主动打开右侧栏，或从活动徽章直接进入相应类别。一项活动可直达详情，多项活动提供选择。新活动只更新徽章。终端输出和子 Agent 步骤来自当前会话的可核实记录；工作区文件、Git 状态与差异在用户查看时读取。同一工作区切会话保留文件浏览和差异选择，跨工作区切换则显示相应工作区。四个场景可分步交付。

## User Stories

1. 作为主窗口用户，我希望从会话标题打开和收起详情，以便在会话旁检查信息。
2. 作为正在等候结果的用户，我希望点击终端或子 Agent 徽章后直接看到对应活动，以便少翻找消息。
3. 作为正在写草稿的用户，我希望活动通知只更新徽章，以便继续输入。
4. 作为独立窗口用户，我希望窄窗口也能从列表进入单项、返回并收起，以便继续编辑原草稿。
5. 作为同时运行多项任务的用户，我希望每项活动归到正确会话和调用，以便准确选择目标。
6. 作为查看命令的用户，我希望看到已知的命令、目录和输出，以便理解 Agent 的操作。
7. 作为排查失败的用户，我希望识别拒绝、失败、截断、尚无结果和状态未知，以便判断下一步。
8. 作为回看历史的用户，我希望任务结束或重开工作台后仍能查阅已存结果，以便还原当时的情况。
9. 作为查看委派的用户，我希望能看到任务、已记录的子工具及回复，以便了解子 Agent 的进展。
10. 作为使用不同 Agent 的用户，我希望区分父工具返回、子任务结束和仅有部分记录，以便正确理解一条工具卡。
11. 作为浏览文件的用户，我希望逐级展开当前工作区的目录，以便在普通目录或 Git 仓库中找到文件。
12. 作为切换会话的用户，我希望同一工作区保留已展开目录和选中的差异，另一工作区显示自己的数据，以便继续原先的阅读。
13. 作为阅读代码的用户，我希望点选后再加载文本并可复制，以便检查 Agent 使用的文件。
14. 作为浏览异常条目的用户，我希望能区分二进制、超限、已删除、无权打开及越界链接，以便知道预览为何不可用。
15. 作为浏览大型目录的用户，我希望看到空目录及读取受限的提示，以便判断列表是否完整。
16. 作为审查工作区的用户，我希望看到分支、分离 HEAD、尚无提交或干净工作树，以便确定当前版本状态。
17. 作为审查部分暂存改动的用户，我希望同一路径的暂存项和未暂存项可分别选中，以便核对两次变化。
18. 作为普通目录的用户，我希望分清目录未使用 Git、Git 不可用和读取失败，以便继续浏览或解决问题。
19. 作为查看差异的用户，我希望正确比较已提交版本、暂存版本和磁盘内容，以便确认实际改动。
20. 作为审查新增、删除、改名或冲突的用户，我希望看到相关路径及可展示的内容，以便理解变更性质。
21. 作为持续审查的用户，我希望后台刷新保留选中的比较，条目消失时得到提示，以便避免误读其他改动。
22. 作为打开多个窗口的用户，我希望同一工作区的数据读取可复用，各窗口各自保留选择，以便并排审查不同文件。
23. 作为在外部修改文件或暂存改动的用户，我希望能刷新可见页面，以便在监听遗漏或失效时仍看到最新状态。
24. 作为使用支持增强能力的 Agent 的用户，我希望按需查看实时输出、经确认的后台状态或原生子历史，以便在有证据时获得更完整的信息。

## Implementation Decisions

- **归属和入口已确认。** 详情入口保留原有会话信息。终端与委派按会话归属，目录与 Git 按工作区归属。主窗口和独立窗口各自维护导航、焦点与选择。
- **导航默认方案。** 宽窗口并排显示会话和右侧栏；空间不足时在侧栏内切换列表与详情，保留返回路径。关闭后可继续输入。具体宽度、是否提供拖宽，以及窄窗口转场仍可通过原型调整。
- **活动数据。** 通过工作台读取已记录的工具输入、结果和嵌套消息。按确切归属绑定并发事件，沿用输出截断信息。调用完成、执行失败、后台存活和子任务结束各自取证。恢复历史时只把有当期证据的活动计入运行状态。首期不要求迁移旧会话才能查看已有记录。
- **适配器。** 两家分别交付已能验证的层级。新增协议读取走用户已安装的原生 CLI；打开只读视图不发起新轮次。数据缺失时展示当时记录到的事实及原因。跨会话迟到的响应只更新原请求所属的数据。
- **文件浏览默认方案。** 以会话所属工作区为根，默认遵循 Git 忽略规则并略过 Git 管理目录，按目录展开和文件选择读取。文件提及的跨工作区搜索范围与忽略项开关仍归输入框。只读预览处理链接、特殊文件、权限和大小上限；触及上限时标记截断。
- **Git。** 从本机 Git 获取可机器解析的状态，区分分支、索引和工作树。暂存差异比较 HEAD 与索引，未暂存差异比较索引与工作树，未跟踪文本以空内容与工作树比较。路径和变化类别共同标识选中项。Git 调用失败与普通目录、干净工作树分别呈现。
- **刷新默认方案。** 窗口共享同工作区、同一内容的读取结果和进行中的请求。可见时合并变化通知，重新激活及手动刷新可发现仅索引或分支发生的变化。后台读取可取消，旧结果不得替换新选择；文件系统与外部 Git 调用在工作台锁外完成。具体缓存期限和尺寸阈值由实测确定。
- **已有约定。** 工作台提供界面所需的业务行为。适配器解释协议，外壳负责中英文文案和可访问控件标签；Agent 原文按原样展示。查看文件和子步骤不会向 Agent 发送文件提及，也不会创建会话引用。

## Testing Decisions

- 用户已确认以工作台作为主要业务测试边界。用现有假 Agent、临时工作区、临时 Git 仓库和工作台的公开操作，验证收到的记录、可见状态和实际读取次数。优先断言用户可观察的结果。
- 沿用现有命令工具、嵌套消息、会话生命周期、工作区文件检索和双窗口共用读取的测试方式。关键对照包括两个并发调用、恢复历史后的状态、同一文件部分暂存、同工作区双窗口查看和跨工作区迟到结果。
- MyGO Tester 只测交互，包括徽章直达、从详情查看历史、窄窗口返回、焦点和草稿、多窗口选择隔离及中英文标签。Windows 与 macOS 验收记录区分已测与待测。
- 已有协议行为优先用现有脱敏样本回放。每项新协议能力保留目标 CLI 版本的真实样本，增加离线回放及显式启用的真实 CLI 契约测试。无法证实的能力继续使用已验收的基础展示。

## Out of Scope

首期为只读查看。向终端发送输入、终止进程、向子 Agent 追问或恢复其执行、编辑文件、暂存、提交和其他 Git 写操作留给后续产品决策。增强工单可以独立排期。

## Further Notes

Codex CLI 0.172.0 的父线程用 `subAgentActivity` 的 `kind=started` 和 `agentThreadId` 标识本次创建的子线程。真实样本包含并发委派、父轮结束、重启后的直接父级核对和分页。打开历史及翻页只发出 `thread/read` 和 `thread/turns/list` 两种线程请求。Claude Code 保留已存委派步骤。[脱敏子线程实录](../../internal/agent/codex/testdata/sidebar-children-0.172.0.jsonl)

Codex CLI 0.172.0 的后台清单只覆盖当前连接已加载的线程。Windows 样本记录了父轮结束后仍在运行的任务、从清单消失、审批拒绝，以及新连接查询失败；断线或缺少真实快照时显示未知。Claude Code 沿用命令记录。[脱敏后台实录](../../internal/agent/codex/testdata/sidebar-background-0.172.0.jsonl)

Windows 上的 Codex CLI 0.172.0 已验证并发命令按线程、轮次和条目分段报告输出。完成事件提供聚合文本时替换增量，没有输出的命令可返回 null。[脱敏协议实录](../../internal/agent/codex/testdata/sidebar-command-0.172.0.jsonl)

[规划地图](../session-workspace-sidebar/map.md)记录了用户确认的原则及尚待评审的细节。本规格将布局、历史降级和刷新行为写成可测试的交付默认值，原规划中的四张未决票继续保留。协议依据见[终端活动](../session-workspace-sidebar/research/terminal.md)、[子 Agent 消息](../session-workspace-sidebar/research/children.md)和[工作区文件与 Git](../session-workspace-sidebar/research/workspace.md)。
