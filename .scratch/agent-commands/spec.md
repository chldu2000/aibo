# 调用 Agent 命令

Status: ready-for-agent

## Problem Statement

用户在 Claude Code 或 Codex 自己的终端里，习惯用 `/review`、`/init`、`/context`，或者用项目里写好的命令和 skills 来干活。到了 aibo 里，只要消息以 `/单词` 开头就会被拦下，提示“不支持 Agent 自己的斜杠命令”。用户不知道当前 Agent 有哪些命令，也没法用这些命令。想用的话，只能回到 Agent 自己的终端，或者把命令的内容手动抄成一段提示词。

之所以拦下，是因为 `/clear`、`/model` 这类命令会改 Agent 的状态，aibo 的记录就和 Agent 的实际状态对不上了。但一刀切地拦下，也挡住了大部分本来没有问题的命令。

## Solution

用户在输入框开头打出 `/`，会弹出当前 Agent 报告的命令清单：内置命令、项目或用户定义的命令，以及 skills。每项显示名称、参数提示和一行说明。选中一项后，输入框开头变成一个命令 chip，后面的文字是参数。手打的名字或别名只要在清单里，也会变成 chip。发出后，会话时间线上显示 chip 和参数（如 `[/review] src/`），Agent 照它自己的方式执行。

每条命令在 aibo 里的表现，都和它在 Agent 自己终端里的一样（ADR 0007）：

- **Agent 能自己执行的**（提示词型命令、skills、只读的本地命令）：原样交给 Agent。本地命令的输出标为“命令输出”。
- **改状态、但 aibo 已有控件的**（`/model`、`/effort`、`/compact`、`/rename`、Codex 的 `/permissions`）：改由 aibo 的控件执行，aibo 显示的状态始终与 Agent 一致。
- **`/clear`**：两家都表现为上下文重置。会话里加一条重置标记，aibo 会话本身不变。
- **复现不了的、终端专用的、没测过的内置命令**：不出现在面板里。手打时提示“`/xxx` 不是 <Agent> 的可用命令”，并告诉用户：想原样发给模型，就在开头加个空格。

`/Users/...` 这样的路径和句中的斜杠不受影响。

## User Stories

1. 作为用户，我想在输入框开头打出 `/` 时看到当前 Agent 的可用命令，这样不用去翻 Agent 的文档就知道能用什么。
2. 作为用户，我想在面板的每一行看到命令名、灰色的参数提示和一行说明，这样能看出命令是干什么的、要带什么参数。
3. 作为用户，我想在 `/` 后面接着打字来筛选：名称或别名前缀匹配的排在前面，包含匹配的排在后面，同一级按 Agent 给的顺序，这样能快速找到命令。
4. 作为用户，我想用别名找到命令（如 `/cost` 找到 `usage`），选中后显示正式名，这样记不住正式名也能用。
5. 作为 Codex 用户，我想在面板上看到每个 skill 的来源（用户、仓库、系统、管理员），这样能分清同名 skill 来自哪里。
6. 作为 Claude Code 用户，我希望 aibo 不去猜命令的来源（不解析说明里的 `(project)`），这样显示的信息都是 Agent 自己给的。
7. 作为用户，我想用键盘在 `/` 面板里上下选择、回车确认、Esc 关闭，这样不用离开键盘。
8. 作为用户，我想选中命令后，输入框开头变成一个命令 chip，光标停在 chip 后面等我输入参数，这样能看出哪部分是命令、哪部分是参数。
9. 作为用户，我想手打 `/review ` 时，只要名字在清单里，它自动变成 chip，这样不用非得从面板里选。
10. 作为用户，我想用退格删掉 chip，回到普通文字，这样能改主意。
11. 作为用户，我希望一条消息最多一个命令，而且只能放在开头，这样两家 Agent 的行为一致、可以预期。
12. 作为用户，我想在带命令的消息里照常提及文件和附图片，这样 `/review` 可以对着我指定的文件做。
13. 作为用户，我想打出清单里没有的 `/单词` 时被拦下，并得到“`/xxx` 不是 <Agent> 的可用命令”的提示，这样不会把命令误当文字发给模型、让模型假装执行了。
14. 作为用户，我想在被拦下时知道：在开头加个空格就能原样发出，这样我确实想发 `/` 开头的文字时也有办法。
15. 作为用户，我希望 `/Users/me/x.go` 这样的路径和句中的斜杠不会被当成命令，这样平常写消息不受打扰。
16. 作为用户，我想在新会话还没发过消息、或者旧会话还没恢复时，打出 `/` 就能拿到命令清单，这样第一条消息就能用命令。
17. 作为用户，我希望清单是在我打出 `/` 时才去取，而不是一新建会话就取，这样不用命令的会话不会提前启动 Agent。
18. 作为用户，我想在清单加载时先看到上次缓存的清单，同时后台在刷新，这样面板打开得快。
19. 作为用户，我想在拿不到清单时看到失败原因和“重试”，这样知道出了什么事、能怎么办。
20. 作为用户，我希望拿不到清单时手打的 `/单词` 也被拦下，提示暂时拿不到命令清单，这样不会误发。
21. 作为用户，我想在新建 skill 或命令文件、Agent 报告清单变化后，面板跟着更新，这样新命令马上能用。
22. 作为用户，我希望同一工作区里同一种 Agent 的多个会话共用一份清单缓存，这样切换会话时不用重新等待。
23. 作为用户，我希望换了 Agent 的安装或登录状态后，清单重新获取，这样不会看到不属于当前状态的命令。
24. 作为用户，我想在会话时间线上看到我发的命令显示为 chip 加参数，这样回看时能认出那是一条命令。
25. 作为用户，我想把鼠标悬停在时间线的命令 chip 上，看到发送时这条命令的说明，这样过了很久也知道它是干什么的。
26. 作为用户，我希望时间线不假装显示命令展开后的提示词，这样看到的都是真实记录。
27. 作为用户，我想用 `/review`、`/init` 等提示词型命令和自定义命令、skills，让 Agent 像在终端里一样执行，需要审批的照常审批，这样体验与 Agent 自己一致。
28. 作为 Claude Code 用户，我想用 `/context`、`/usage` 查看信息，输出以等宽浅色的“命令输出”显示、不带模型名，这样能和模型的回复分开。
29. 作为用户，我希望命令执行完既没有回复也没有报错时，看到一行“命令已执行”，这样知道命令确实跑过了。
30. 作为用户，我希望命令出错时走现有的失败显示，Agent 的原话（如“isn't available in this environment”）原样显示，这样能看到真实原因。
31. 作为用户，我想用 `/model 名字` 换模型，效果和在模型菜单里换一样，模型控件显示 Agent 报回的实际模型，这样控件始终准确。
32. 作为用户，我想只打 `/model` 不带参数时打开模型菜单，这样能从列表里选。
33. 作为 Claude Code 用户，我想用 `/effort 级别` 改推理强度，效果和在控件里改一样，这样控件与实际一致。
34. 作为用户，我想用 `/compact` 压缩上下文，效果和点压缩按钮一样，时间线上照常出现压缩标记。
35. 作为用户，我想用 `/rename 标题` 改 aibo 会话的标题，这样不用去找重命名菜单。
36. 作为 Codex 用户，我想用 `/permissions 模式` 切换权限模式，不带参数时打开模式菜单，这样效果与 Codex TUI 一致。
37. 作为用户，我希望 `/model`、`/compact` 这类改走控件的命令有轮次在跑时被拒绝，提示和控件被拒绝时一样，这样规则统一。
38. 作为用户，我想用 `/clear`（Claude 还有 `/reset`、`/new` 两个别名，Codex 还有 `/new`）清空上下文，时间线上出现一条上下文重置标记，会话还是同一个，这样之前的记录还在，Agent 从头开始。
39. 作为用户，我希望 `/clear` 之后 aibo 记下 Agent 的新原生会话，之后恢复会话时接上的是重置后的那个，这样不会把旧上下文带回来。
40. 作为 Codex 用户，我想用 `/review` 让 Codex 用它自己的审查模式审查改动，这样效果与在 Codex TUI 里一样。
41. 作为用户，我希望会改全局配置的、会断开 aibo MCP 服务器的、会自己发起轮次的、只在终端里能用的内置命令不出现在面板里，这样不会把会话弄坏。
42. 作为用户，我希望 Agent 升级后新出现的内置命令默认不提供，等测过了再放开，这样不会遇到行为不明的命令。
43. 作为用户，我希望 Codex 的 `!命令` 不被提供，这样不会绕过沙箱执行命令。
44. 作为维护者，我想在契约测试里发现 Agent 新增的、还没裁定的内置命令并得到报告，这样能及时补上裁定。
45. 作为维护者，我想让每条内置命令的裁定（放行、改走控件、上下文重置、拦下）集中写在各自的适配器里，这样 Agent 升级时只改一处。
46. 作为用户，我想用会话引用读取别的会话时，看到其中的命令消息写成 `/review src/`，并附上发送时的说明，这样读者明白那条消息做了什么。
47. 作为用户，我希望旧会话里没有命令字段的消息照旧按文字显示，这样升级不影响历史记录。
48. 作为用户，我希望命令清单不写进数据库，这样不会存下过期的清单。
49. 作为用户，我希望为了取清单提前启动的 Claude 进程，在我没发消息时照常在空闲 30 分钟后回收，这样不占资源。
50. 作为用户，我希望为了取清单提前启动 Claude 进程时，不会多跑一次项目的 SessionStart hook，也不会凭空多出一个原生会话记录，这样取清单没有副作用。
51. 作为用户，我想在命令清单还没取到时，界面里的文字都用我设定的语言显示，Agent 给的命令名和说明则原样显示，这样和其他界面的规则一致。
52. 作为用户，我希望选中命令之后、发出之前，如果命令被删掉了，消息照发，出错就走普通的错误显示，这样不会因为罕见情况卡住。

## Implementation Decisions

### Agent 层的命令模型（适配器接口）

- 新增“Agent 命令”类型：正式名、说明、参数提示、别名、来源（只在 Agent 给出时填，如 Codex 的 `scope`）、是否内置，外加适配器私有的数据（如 Codex skill 的 `path`；工作台只保管，不解读，做法同 `Rule.Data`）。
- 每条命令带一个**处理方式**，由适配器按它的裁定表给出：
  - 交给 Agent；
  - 改走控件，并注明是哪个控件：模型、推理强度、压缩、重命名、权限模式；
  - 上下文重置。
  被裁定拦下的命令，适配器不报告。工作台只按处理方式行事，不认识具体的命令名，也不认识具体的适配器。
- 裁定表放在各自的适配器里，采用白名单：
  - Claude 的条目只要带 `builtin: true` 且不在表里，就不报告。非内置的（自定义命令、skills、插件条目）一律交给 Agent。
  - Codex 的 skills 一律交给 Agent。Codex 的内置命令全部由适配器合成，只合成裁定过的几条。
  - 逐条裁定照录“每条内置命令放行、改走控件还是拦下”（03 号 issue）。
- `Turn` 增加可选的 `Command{Name, Args}`。适配器的翻译：
  - Claude：拼成 `/名字 参数` 作为用户消息的文字，放在文件提及之前。
  - Codex skill：文本 `$名字 参数`，外加 `{type:"skill", name, path}` 输入项。
  - Codex `/clear`、`/new`：适配器调用 `thread/start`。
  - Codex `/review`：适配器调用 `review/start`。
- 新增事件：
  - `CommandsChanged{Commands}`：整份清单。Claude 的会话在 `initialize` 应答后发一次，收到 `commands_changed` 时再发。Codex 的会话收到 `skills/changed` 后重新调用 `skills/list`，再发。
  - `ContextReset`：Claude 收到 `conversation_reset` 时发，随后照常发新 ID 的 `NativeSessionStarted`。Codex 适配器在 `thread/start` 成功后发，同样随后发 `NativeSessionStarted`。
- 回复事件加一个“命令输出”标志。Claude 的 `<synthetic>` 回复（本地命令的输出）带上它。
- 可选接口“命令清单”（没有原生会话也能取清单的 Agent）：传入工作区，返回清单。Codex 实现它，在共用的 app-server 上调用 `skills/list`，传 `cwds:[工作区]`，不建线程。Claude 不实现，它的清单只能从会话自己的进程拿到。
- 假 Agent 支持：脚本化的命令清单（两种获取方式都要能模拟）、`CommandsChanged`、`ContextReset`、带命令输出标志的回复，并记下收到的 `Turn.Command`。
- ACP 的 `available_commands_update` 不在本规格里接入，但上面的命令模型要能直接容纳它：名称、说明、输入提示映射到同样的字段，处理方式一律为“交给 Agent”。

### 工作台

- `Outgoing` 增加可选的命令（名称、参数）。`SendMessage` 的规则：
  - **带命令**：用最新的清单核对名称（别名换成正式名），按处理方式分流：
    - 交给 Agent，或上下文重置：作为一个轮次发出。用户消息存下命令快照，再把 `Turn.Command` 交给适配器。
    - 改走控件：不发轮次，不记用户消息，调用工作台已有的方法：模型 → `SetModel`（参数为模型，推理强度保持不变）；推理强度 → `SetModel`（保持当前模型）；压缩 → `Compact`；重命名 → 重命名会话；权限模式 → `SetMode`（参数按模式的 ID 或名称匹配）。这些方法原有的错误（如 `ErrTurnRunning`）照常返回。不带参数的模型和权限模式命令返回一个专门的哨兵错误，外壳据此打开对应的菜单。参数对不上时，也返回带类型的错误，由外壳措辞。
    - 名称在清单里找不到（选中后被删掉了）：照发，交给 Agent。
  - **不带命令、但文字以 `/单词` 开头**：继续返回 `ErrSlashCommand`。错误改为带类型的，附上 Agent 名称，并区分“不在清单里”和“暂时拿不到清单”，由外壳按 `words.go` 的做法措辞。开头带空格的文字照原样发出（当前的修剪逻辑要保证这点，见 Further Notes）。
- 用户消息新增命令快照：命令名、参数、发送时的说明。消息存为 JSON，加字段不需要迁移。旧消息没有这个字段，照旧显示文字。
- 回复消息新增“命令输出”标志，来自事件上的标志。
- 轮次结束时，如果这条命令消息之后既没有回复也没有工具调用，也没有失败，就在用户消息上记一个“命令已执行”的状态，供外壳显示那行兜底文字。
- 收到 `ContextReset`：加一条重置标记，复用现有的 `Reset` 标记种类。随后的 `NativeSessionStarted` 由现有逻辑记下新的原生会话 ID。
- **命令清单**：新增一个方法，按会话返回清单，形态和需求档位仿照 `ModelList`（只读缓存 / 加载 / 失败后重试）：
  - 缓存只放在内存里，键是“Agent 种类 + 工作区 + 安装与登录状态（沿用 `ModelSource`）”。
  - 会话有原生会话时，以会话收到的 `CommandsChanged` 为准，同时写回缓存。
  - 没有原生会话时：Agent 实现了命令清单接口（Codex），就调用接口；否则（Claude）提前启动这个会话自己的原生会话（新会话直接启动，旧会话带 ResumeID 续接），等它的第一条 `CommandsChanged`。启动不经过轮次，也不记任何消息。这个原生会话之后发消息时直接用，空闲回收照常进行。
  - 每次取到新清单都 `notify`，所有窗口一起刷新。失败时记下错误，由外壳显示原因和重试。
- 并发约定照旧：提前启动原生会话、调用适配器，都在锁外进行。

### 外壳

- 输入框开头打出 `/` 时打开命令面板，与 `@` 文件面板并列，复用其异步加载和键盘交互。匹配和排序规则见用户故事 3、4。
- 命令 chip 显示在输入框开头，文件提及和附件照常可带。
- 时间线：用户消息显示命令 chip 加参数，悬停 chip 显示快照里的说明。带“命令输出”标志的回复用等宽浅色显示，不显示模型名。有“命令已执行”状态的消息，下方显示一行兜底文字。
- 收到“不带参数的模型和权限模式命令”的哨兵错误时，打开对应的菜单。
- 所有新增文字写进 `locales/`，中英两种语言同时写。错误的措辞放在 `words.go`。

### 会话引用

- 读取工具遇到带命令快照的用户消息时，写成 `/名字 参数`，后面附上“<Agent 名> 命令：<说明>”。这段给 Agent 读的文字放在 `internal/refs`。

## Testing Decisions

- 好的测试只看外部行为：通过工作台的公开方法发消息、取清单，再检查记下的消息、标记、错误，以及假 Agent 收到的 `Turn`。不检查内部的数据结构和锁。
- **工作台**（主接缝，用假 Agent），新测试按领域放在一个新的测试文件里。覆盖：
  - 带命令的消息：假 Agent 收到 `Turn.Command`；用户消息存下名称、参数和说明快照；别名换成正式名。
  - 清单外的 `/单词` 和拿不到清单时的 `/单词`，各自返回对应的带类型错误；开头带空格的照发；路径不受影响。
  - 改走控件的每一种：没有轮次、没有用户消息，效果与直接调用控件相同；有轮次在跑时被拒绝；不带参数时返回打开菜单的哨兵错误。
  - 上下文重置：出现 `Reset` 标记，记下新的原生会话 ID，aibo 会话不变；之后恢复时用的是新 ID。
  - 命令输出标志的保存与读出；“命令已执行”的兜底状态；失败时不出现兜底。
  - 清单：两种获取方式（Agent 级的清单接口；提前启动原生会话，取它的 `CommandsChanged`）；提前启动的原生会话在下一条消息时被复用；`CommandsChanged` 整份替换清单并写回缓存；缓存按来源区分；失败与重试；多个会话共用一份缓存。
  - 会话引用：命令消息的读取结果。
  - 旧消息（没有命令字段）读出不变。
  - 先例：`compaction_test.go`（标记）、`models_test.go`（清单缓存与需求档位）、`attachments_test.go` / `files_test.go`（`Outgoing` 的附加字段）、`references_test.go`。
- **适配器**（已有接缝），用 testdata 回放加解析单测：

  - Claude：清单字段；只做 `initialize` 时不产生原生会话 ID、不写会话记录、不执行 SessionStart hook；续接的进程在 `initialize` 应答里同样带清单；`/clear` 换 ID；发现白名单外的新内置命令时报出来。

      - `initialize` 时就会写一个会话记录文件，里面只有元数据（`session-owner`、`derived-from`），发出第一条消息后才有对话内容；
      - SessionStart hook 在进程启动时就跑，第一条消息时不再跑。每个进程只跑一次，只是提前了，不是多跑一次。
      
      所以，提前启动后用户没有发消息，就会留下一个只有元数据的记录文件，并且 hook 已经跑过一次。契约测试按实测行为断言。

    - `/review` 不带参数时审查未提交的改动，带参数时把参数当作自定义说明（`custom`）。审查在原线程里作为一个轮次进行，结论以一条回复出现。
    - 会话进行中新增 skill，会推送 `skills/changed`；没有会话在运行时会不会推送，没有验证。
  - 先例：现有的 `contract_test.go`。
