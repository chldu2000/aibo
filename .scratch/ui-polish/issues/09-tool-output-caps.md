# 09: 展开的工具调用限高

Status: resolved

**What to build:** 展开一个工具调用不会把会话撑得很长：参数和小输出都有最大高度，终端和子 Agent 的大输出可以挪到详情面板看。

现状（`internal/shell/render.go`）：
- 展开后参数以完整 JSON 显示，不限高。
- 输出不到 4KB（`bigOutput`）时整段作文本显示，可能上百行；超过时用只读编辑器，高度固定 320，不能调。

- [x] 参数：先显示 `gist` 一行，“显示参数”再展开完整 JSON；JSON 区域最大约 160，超出滚动
- [x] 小输出：最大约 240，超出在区域内滚动
- [x] 大输出：编辑器保持 320；终端和子 Agent 的调用旁边加“在详情面板打开”，打开对应活动页的单项（`openActivities` 加 `selected`），在详情面板里占满高度
- [x] 其他调用（Read、Grep 等）的大输出照旧用 320 高的编辑器
- [x] 子 Agent 的嵌套调用同样限高
- [x] Tester：100 行输出展开后高度不超过上限；“在详情面板打开”打开对应项

## 决定

- “在详情面板打开”只给终端和子 Agent（2026-11-27）。不新增通用的“调用”页。

## 实现说明

- 常量在 `internal/shell/render.go`：`argsHeight = 160`、`textHeight = 240`、`outputHeight = 320`。`readOutput` 多了一个高度参数，会话里传 320，详情面板里传 `inspectorOutputHeight`，也就是窗口高度减 240，最少 320。
- 展开后先显示一行 `gist`，下面是折叠的“显示参数”，展开后 JSON 在 160 高的滚动区里。原来的“参数”标题不再用，`toolArgs` 这个文案删掉了。
- 小输出放进最大 240 的滚动区。子 Agent 的嵌套调用走同一个 `s.tool`，限高一样。
- `s.tool` 多了一个 `id` 参数，就是活动 ID：顶层是 seq，子调用是 `父ID.序号`（从 1 开始），和 `workbench.Activities` 一致。
- 终端和子 Agent 的调用（`workbench.ActivityOf` 不为空）在“结果”一行右边有一个图标按钮，点击后调用 `openActivity`，打开详情面板对应的活动页并选中这一项。
- 按钮做成图标，标签是“在详情面板打开 #ID”。同屏可能展开好几个调用，标签带上 ID 才不会重复。
- 测试 `TestToolCallCaps`：100 行输出展开后，到下一条消息的距离不超过 480，去掉限高时是 789；子 Agent 里的步骤同样受限；“显示参数”能展开；两个按钮分别打开顶层调用和子调用。

## 没有验证

- 嵌套滚动的手感：输出框滚到头以后，滚轮是否接着滚动会话，只能在真机上看。
- 详情面板里的大输出“占满高度”是按窗口高度估的，面板上方内容多时（子 Agent 的提示词很长）会多出一段需要滚动。要精确贴合，需要把活动详情页的主体从滚动区改成列布局，涉及子 Agent 页的记录列表，没有做。
- 同时展开多个调用时，“显示参数”的折叠标签会重复，和原有的“思考”一样。
