# 03: 详情面板可以拖动宽度

Status: resolved

**What to build:** 宽窗口里并排显示的详情面板能拖动左边缘改变宽度，宽度在重启后保持。

现状：并排时宽度写死为 `min(400, width*0.42)`（`internal/shell/view.go:103`），面板绝对定位在会话区右侧，没有可拖的边缘。400 看差异太窄，看概览又偏宽。

- [x] 面板左边缘做成可拖的把手（光标变成左右箭头），拖动改变 `rail`
- [x] 下限 300，上限为会话区宽度减去消息列的最小可读宽度（建议 360）
- [x] 宽度只存一档，所有标签页共用（`Pref`）
- [x] 双击把手回到默认值（400）
- [x] 窄窗口（叠在消息上的模式，`width < 720`）不受影响
- [x] Tester：拖动后宽度变化，重建 Shell 后保持

## 决定

- 只存一档（2026-11-27）。用起来发现看差异时总要来回拖，再改成按页分档。

## 实现时查清

- MyGO 是否有现成的可拖边缘控件，还是用 `Split` 改写会话区布局（把详情面板放进 Split 的第二格）。后者更省事，但要处理窄窗口叠放模式。

## 实现说明

- 没有改用 `Split`。面板仍是绝对定位，只在它左边缘叠一条 6 宽的透明把手（`railEdge`），光标是左右箭头，用 MyGO 的 `Element.Dragged` 读拖动量，`DoubleClicked` 还原。这样窄窗口的叠放模式完全不用动。
- **宽度规则**（`railFor`）：
  - 下限 300（`railMin`），上限是会话区宽度减 360（`messagesMin`），默认 400（`railWidth`）；
  - 这里的宽度含面板右侧 12 的边距，与原来的 `rail` 一致；
  - 窗口缩小时只临时收窄，保存的值不变。
- **保存**：宽度存在偏好 `inspectorWidth`，所有页共用。拖动停下 300ms 后保存，和侧栏一样；关窗时还没存的也会存。
- **窄窗口**：宽度小于 720 时，面板仍叠在消息上，没有把手。
- 测试 `TestInspectorWidth`：拖宽、拖到上限、拖到下限、再拖，重建 Shell 后保持，双击回到 400。

## 没有验证

- 把手只有 6 宽，叠在面板圆角边缘上，在真机上是否好抓没有看过。
- 拖动时面板内容（比如编辑器）每帧重新排版，大文件预览时拖动是否流畅没有测。
