# 24: 详情面板里的大输出贴合面板高度

Status: resolved

**What to build:** 在详情面板打开终端或子 Agent 的单项时，大输出正好填满面板剩下的高度，不会在下面多出一段要滚动的空间。

现状：`inspectorOutputHeight`（`internal/shell/activities.go:38`）按窗口高度减 240 估出输出框的高度，最少 320。面板上方的内容多时（比如子 Agent 的提示词很长），输出框加上上面的内容会超出面板，下面多出一段要滚动。09 的“没有验证”里已经记下这一点。

- [x] 活动详情页的主体从滚动区改成列布局：上方的内容（标题、命令或提示词、状态）照常排，输出框 `Grow(1)` 占满剩下的高度
- [x] 提示词很长时，提示词放进限高的滚动区（例如最高 160），保证输出框至少还有 `outputHeight`：改为整个上方区域一起滚动，见实现说明
- [x] 子 Agent 页的记录列表跟着改，长记录仍然能滚动
- [x] 去掉 `inspectorOutputHeight` 的估算（或者只留作下限）
- [x] Tester：子 Agent 的提示词有 40 行时，面板里不出现外层滚动，输出框底边贴着面板底边

## 来源

09 的“没有验证”。用户 2026-11-28 确认要做。

## 实现说明

- 详情面板选中一个调用时（新的 `selectedActivity`），主体不再是 `ui.Scroll`，改成列（`details.go` 的 `inspector`），和打开文件、差异时一样。
- `activityPage` 的单项分成上下两段：
  - 上段是一个 `Shrink(1)` 的滚动区，放调用状态、命令和所在目录，或者子 Agent 的描述、提示词、记录的步骤、子历史。内容少时按原高度显示，多时缩小并在区内滚动。
  - 下段是结果。大输出的编辑器 `Grow(1).MinHeight(outputHeight)`，占满剩下的高度，最少 320。
  - `commandDetail`、`delegationDetail` 不再自己画结果，由 `activityPage` 统一画在下段。打开子历史时 `delegationDetail` 返回 false，不显示结果，和原来一样。
- 提示词没有单独限高 160：整个上段已经能滚动，输出至少还有 320，再给提示词加一层滚动就嵌套了三层。
- `readOutput` 的高度传 0 时表示“占满剩下的高度”。会话里仍然传 320。子 Agent 记录里每一步的结果也固定 320，因为它们在上段的滚动区里。
- 小输出（不到 4KB）照旧最高 240，不撑满。
- 删掉了 `inspectorOutputHeight`。
- 测试 `TestInspectorOutputFits`：命令和子 Agent（40 行提示词）的大输出在详情面板里可见高度都不少于 320，底边离面板内容底边不超过 4，提示词仍然可见。用改动前的代码跑，子 Agent 那一段失败，输出被挤出面板，可见高度为 0；命令那一段改动前也能通过，因为上方内容少时原来的估算正好够。

## 没有验证

- 没有在真机上看。上段滚动区和输出编辑器上下挨着，滚轮在两者之间切换的手感没有看过。
- 窄窗口里面板叠在消息上，底边让出输入区，面板可能很矮。面板内容不到 320 加上段时，输出会被面板裁掉一截，原来整页还能滚动。
- 小输出在大面板里仍然只有 240 高，下面留白。
