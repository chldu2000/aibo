## 实测（2026-11-28）

用临时测试在 Tester 里测每帧耗时（Windows，无界面，不含绘制；连续 20 帧取平均）：

| 场景 | 改前 | 改后 |
|---|---|---|
| 会话本身（1000 条调用折成一组） | 0.12 ms | 0.15 ms |
| 命令记录页，1000 条 | 5.7 ms | 0.73 ms |
| Git 页，2000 个未跟踪文件 | 6.9 ms | 0.37 ms |

改前的耗时和条数成正比，千条左右在 60 fps 的预算（16 ms）之内，但再长就不够了。每组只显示前 100 条之后，耗时基本不随条数增长，所以没有做 `ui.List` 虚拟化。

“真实的大会话和大仓库”用的是生成的数据，没有用真实的。

## 实现说明

- 新文件 `internal/shell/lists.go`：
  - `listShows = 100`；
  - `shownOf` 算出显示几条；
  - `moreLine` 是列表下面那一行“还有 N 个”，展开后变成“收起”。它的 Label 带上列表的名字（“命令记录还有 51 个”“未跟踪还有 20 个”），同屏唯一。
- 终端、子 Agent 页（`activityPage`）：
  - 顶部是过滤框（“按命令或描述过滤”），按调用的摘要（`gist`：命令、路径、描述等）不分大小写匹配；
  - 终端页多一个“只看失败的”开关：出错或退出码非零的算失败，点旁边的文字也能切换；
  - 运行中的调用置顶，其余保持 `Activities` 的顺序（父调用最新在上）；
  - 没有匹配时显示“没有符合条件的调用”；
  - 过滤状态放在 `detailsUI.list`，换页（`showPage`）时清空。
- Git 页：每组的标题改用 `fold`（“未跟踪 · 120”），可以折叠。折叠和“全部显示”按工作区、按组记在 `workspacePanel`，不跨重启保存。
- 新文案：`moreItems`、`moreItemsLabel`、`fewerItems`、`fewerItemsLabel`、`filterCalls`、`failedOnly`、`noMatchingCalls`。
- 测试：
  - `TestLongCommandList`：150 条命令加一条运行中的；运行中的在最上面；只显示 100 条，“还有 51 个”展开后能收起；只看失败的；按文字过滤，没有匹配时有提示；
  - `TestLongGitGroups`：120 个未跟踪文件只显示前 100 个，展开看到全部，标题能折叠和展开。

## 没有验证
