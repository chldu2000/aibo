# 14: 序号列只在需要时显示

Status: resolved

**What to build:** 消息左侧的 `#seq` 列平时不显示，悬停在消息上、处于选择模式或有高亮时才显示，把宽度还给正文。

现状：每行固定 44 宽的 `#%d`（`internal/shell/view.go` 的 `messages`），`working` 和 `divider` 也按 44/58 对齐。窄窗口里很占地方。

- [x] 平时不占宽度；悬停时在消息左上角浮出序号（不推动布局）
- [x] 选择模式和有高亮时照常显示序号列，方便对照引用的范围
- [x] `working`、`divider`、命令标记的缩进随之调整
- [x] Tester：选择模式下序号可见；Tester 依赖序号文字查找元素的地方改用别的 Label

## 决定（2026-11-27）

- 平时隐藏，悬停浮出。只有引用时才需要对照序号，而引用时会进入选择模式或出现高亮。

## 实现说明

- `messages` 里的 `gutter` 等于“选择模式或者有高亮”。为真时照旧画 44 宽的序号列；否则不占宽度，正文左移 54。
- **悬停**：`sessionView.hover` 记下上一帧指针所在消息的 seq（`Hovered()` 只报告上一帧），有变化时用 `c.After(0)` 再画一帧。悬停的消息在**右上角**浮出一个小牌子“#seq”，用 Absolute 定位，不推动布局。
  - 和工单不一样：工单写的是左上角，但没有序号列时，左边只有列表 20 的内边距，放不下“#123”；放在左上角又会压住正文。12 的悬停按钮也打算放进右上角这个位置。
- **元素身份**：浮出的序号画在正文之后，正文列加了 `Key("body")`。一开始放在正文前面，导致后面所有元素的位置身份跟着变，按下和松开落在“不同”的按钮上，审批卡片的测试因此失败。
- `working`、`divider`（含“命令已执行”和 11 的“用时”）都改成接收 `indent`：平时是 4，有序号列时是 58。
- 测试 `TestSeqGutter`：平时看不到序号；悬停回复时只出现它的“#2”，正文位置不变；选择模式下全部出现，正文右移；取消后消失；`Reveal` 高亮时出现。
- 原有测试里按序号查找元素的地方（`references_test`）都在选择模式下，不用改。

## 没有验证

- 浮出的小牌子在很短的消息上会不会压住文字，比如单行的用户消息气泡靠右时。只在测试里确认了布局不动，没有在真机上看。
- 测试里发现 Esc 退不出选择模式，只能点“取消”。这是原有的行为，不在这张工单的范围，没有改。

## 后续：Esc 退出选择模式（2026-11-28）

- 选择栏处理 Esc，一层一层往外退：先关预览，再关目标列表，最后退出选择模式（`selectionBar`）。详情面板在选择模式下本来就不处理按键，所以不冲突。
- `TestSeqGutter` 补了检查：打开目标列表后第一次 Esc 只关列表，第二次退出选择模式。
