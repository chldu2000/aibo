# 25: 复制后给出“已复制”反馈

Status: resolved

**What to build:** 点了“复制”以后有一个短暂的反馈，让用户知道内容已经写进剪贴板。

现状：消息悬停工具栏的“复制”（`internal/shell/actions.go:26`）和选择模式的“复制”（`internal/shell/selection.go:163`）都只调用 `c.WriteClipboard`，界面上没有任何变化。12 的“没有验证”里已经记下这一点。文件预览的复制路径（`path_actions.go`）、概览里复制会话 ID（`details.go:369`）也一样。

- [x] 点击后按钮的图标换成对勾（`checkmark`）约 1.5 秒，Tooltip 改为“已复制”，然后恢复；用 `Shell.later` 定时
- [x] 选择模式的“复制”同样处理；如果复制后退出了选择模式，就在原位置用一个淡出的“已复制”小提示代替
- [x] 所有调用 `WriteClipboard` 的按钮用同一个辅助函数，不各写一套
- [x] 按钮的 Label 不随状态变化，Tester 仍能按原 Label 找到
- [x] “已复制”文案进 `locales`
- [x] Tester：点复制后出现“已复制”，过一会儿恢复

## 来源

12 的“没有验证”。用户 2026-11-28 确认要做。

## 实现说明

- 新文件 `internal/shell/copy.go`。`Shell.copied` 记下最后点击的复制按钮（按 Label 区分）和点击的时间。
  - `copyButton` 是图标按钮。1.5 秒内图标换成 `checkmark`，Tooltip 改为“已复制”。
  - `copyTextButton` 是文字按钮。1.5 秒内文字改为“已复制”。
  - 两种按钮都用 `.Label` 固定原来的 Label，所以 Tester 仍按原名找到它们。
- 定时没有用 `Shell.later`。`later` 是把后台结果交回主线程用的；这里只需要到点重画一次，所以用 `c.Now()` 和 `c.After(剩下的时间)`。Tester 的 `Advance` 也能推动它。
- 改用这两个辅助函数的地方：
  - 消息悬停工具栏的复制；
  - 选择模式的复制（复制后不会退出选择模式，所以不需要另做淡出提示）；
  - 文件预览的复制相对路径；
  - 概览的复制原生会话 ID；
  - 登录提示的复制命令。
- 文件树右键菜单的“复制相对路径”仍直接写剪贴板：菜单点完就关了，没有地方显示反馈。
- 新文案 `copied`，新图标的后备图形 `checkmark`。
- 测试 `TestCopyFeedback`：
  - 悬停回复，点“复制 #2”：剪贴板里是回复原文，出现对勾，Label 不变，2 秒后对勾消失；
  - 选择模式全选后复制：出现“已复制”，2 秒后恢复。
  - 已确认去掉反馈时测试失败。

## 没有验证

- 没有在真机上看对勾和文字切换的效果；Windows 上的对勾用的是后备图形。
- 文字按钮从“复制”变成“已复制”时变宽，同一行后面的按钮会往右挪一点。
