# 17: 工作区分组可折叠，长列表收起

Status: resolved
Blocked by: 15

**What to build:** 会话多的时候侧栏仍然好找：工作区分组能折叠，每组默认只显示最近几个会话。

现状（`internal/shell/sidebar.go` 的 `workspaceGroups`）：每个工作区下列出全部未归档会话，没有上限；只有“已归档”能折叠。

- [x] 工作区标题可点击折叠/展开（前面加箭头），状态按工作区用 `Pref` 保存
- [x] 每组默认显示最近 8 个，下面一行“显示更多（N）”，点开显示全部，再提供“收起”
- [x] 当前会话、运行中、待审批、未读（15）的会话总是显示，即使排在 8 个之后（未读依赖 15）
- [x] 折叠的工作区里有运行中或待审批的会话时，标题上显示计数
- [x] Tester：12 个会话的工作区只显示 8 个加“显示更多”；折叠后重建 Shell 保持折叠

## 待定

- 8 这个数要不要放进设置：倾向不放。

## 实现说明

- **折叠**：
  - 工作区标题前面加了箭头，点“箭头 + 名字”这一块就能折叠或展开。标签是“收起 X”或“展开 X”。新建会话按钮在这块外面，点它不会误触折叠。
  - 折叠状态按工作区 ID 存进偏好 `foldedWorkspaces`（一个 map），重启后保持。
- **长列表**：
  - 每组默认显示前 8 个（`groupShows`）。下面一行“显示更多（N）”，展开后变成“收起”。
  - “显示全部”的状态只放在内存里。
  - 这一行的标签带上工作区名，比如“显示更多（3） · 002”。几个工作区同时有这一行时，标签不会重复。
- **总是显示**：当前会话、运行中、待审批、未读的会话，排在 8 个之后也照样显示，也不计入“更多”的数目。
  - 会话按最近活跃排序（工作台 `Sessions` 的顺序），所以跑完一轮或有新回复的会话本来就会排到前面。实际上会落在 8 个之外的主要是当前打开的旧会话。
- **折叠时的计数**：折叠的工作区如果有会话在运行或待审批，标题上显示“N 个运行中”和“待审批 N”。
- 不做设置项，8 写死成常量，按“待定”里的倾向。
- 新增 `chevron.right` 图标的后备图形。
- **测试** `TestSidebarLists`：
  - 12 个会话只显示最近 8 个，并有“显示更多（4）”；
  - 跑完一轮的旧会话排到前面；
  - 显示全部后打开一个旧会话，收起后它仍然显示，计数变成 3；
  - 折叠后看不到会话，标题显示“1 个运行中”；
  - 新建 Shell 后仍然折叠；展开后会话又出现。

## 没有验证

- “总是显示”里的运行中、待审批、未读三种，因为排序的缘故很难落在 8 个之后，没有单独写测试，只测了当前会话。
- 箭头和计数在窄侧栏里会挤占工作区名字的宽度，没有在真机上看过。
