# 12: 消息的悬停操作

Status: resolved

**What to build:** 鼠标悬停在一条消息上时，右上角出现几个小按钮：复制、引用这条；用户消息还可以“放回输入框”。

现状：消息只能选中文字后复制；引用要先点标题栏按钮进入选择模式（`startSelecting`）再勾选。

- [x] 复制：Agent 回复复制 Markdown 原文，用户消息复制原文，工具调用复制输出
- [x] 引用这条：直接把这一条作为引用加进当前会话的草稿（等价于选择模式只选一条后确认）
- [x] 放回输入框：把用户消息的文字、提及和附件放回草稿（不撤销已发出的那条）
- [x] 选择模式下不显示悬停操作
- [x] 按钮的 Label 带上序号，保持画面内唯一
- [x] Tester：悬停出现按钮，复制写入剪贴板，引用这条后草稿出现引用芯片

## 决定（2026-11-27）

- 不做“编辑并重发”：要原生会话能回退，各家不一样，以后单独立项。
- “引用这条”和标题栏的“引用”（进入选择模式选一段）并存：一个引用单条，一个选范围。

## 实现说明

- 新文件 `internal/shell/actions.go`。指针所在消息的右上角浮出一条小工具栏，替换了 14 里单独的序号牌子。
  - 工具栏里先是序号，有序号列时不再显示；后面依次是复制、引用、放回输入框（只有用户消息有）。
  - 按钮是图标，标签带序号，比如“复制 #2”“引用 #2”“放回输入框 #1”。
- **复制**：Agent 回复复制 Markdown 原文，用户消息复制原文（调用了命令的写成“/命令 文字”），工具调用复制输出，计划复制它的文字。
- **引用这条**：`ReferenceRange(本会话, seq, seq, 本会话)`，草稿里出现“本会话 · #2（1 条）”的引用芯片。只对已经结束的消息提供，因为还在输出的消息不能引用。
- **放回输入框**：
  - 草稿为空时直接放入文字，不为空时另起一行接在后面，不覆盖已有内容；
  - 提及和附件按路径或文件去重后加进草稿；
  - 原消息调用过命令、草稿里还没有命令时，带上命令；
  - 原消息附带的引用不放回；
  - 附件和已发出的消息共用同一个文件。从草稿里移除时，`DiscardAttachment` 会看到消息还在用这个文件，不会删除它。
- 选择模式下不显示工具栏。有高亮时显示，但不带序号，因为序号列已经有了。
- 测试 `TestMessageActions`：悬停回复出现复制和引用、没有“放回输入框”，其他消息没有按钮；复制写入剪贴板；引用后草稿里出现芯片；放回后输入框里是原文（直接读文本框的值）；选择模式下不出现。已确认去掉放回逻辑时测试会失败。
- 新图标的后备图形：`text.quote`、`arrow.uturn.backward`。

## 没有验证

- 工具栏盖在消息首行的右端，长的工具调用标题或很宽的回复首行会被挡住一截，没有在真机上看。
- 复制以后没有“已复制”提示，和选择模式的“复制”一样。
- “引用这条”只引用到本会话。引用给别的会话仍走选择模式。
