# 10: 改文件的调用显示差异

Status: needs-triage

**What to build:** Agent 改文件的工具调用（Claude Code 的 Edit/Write/MultiEdit，Codex 的 apply_patch 或文件变更，ACP 的 diff 内容）在会话里显示为“文件名 +N −M”，展开是统一格式的差异，而不是原始 JSON。

现状：所有工具调用一视同仁，标签是“名字 · gist”，展开是参数 JSON 和输出（`internal/shell/render.go` 的 `tool`）。

- [ ] 先调研（`research` 技能）三类适配器各自用什么工具名、参数和事件表达文件修改，有没有可直接用的旧/新文本或补丁；按约定附真实抓取数据
- [ ] 适配器或工作台把它们归成同一种结构化信息（如 `model.ToolCall` 上的文件改动：路径、旧文本、新文本或补丁），外壳不认具体工具名
- [ ] 外壳：标签显示文件名和增删行数；展开用 `editor.DiffView`（Git 页已在用），限高同 09
- [ ] 点文件名在详情面板的文件页打开该文件
- [ ] 契约测试和单元测试用抓取数据

## 待定

- 结构化信息放在适配器（每家自己解析）还是工作台（按工具名识别）：前者符合“工作台不认识具体适配器”，倾向前者。需要记 ADR 吗？取决于调研结论。
