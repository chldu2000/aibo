# 11: 一轮结束后留下耗时

Status: resolved

**What to build:** 每轮结束后，回复末尾留一行淡色的“用时 1m 05s”；被中断的轮次写明已停止。

现状：运行中最后一行显示“Agent 工作中 · 时长”（`internal/shell/view.go` 的 `working`），轮次结束后这一行消失，什么也不留。

- [x] 先核实工作台是否记录每轮的开始和结束时间（`Status.Since` 只在运行中有）；没有的话在工作台记下，持久化到消息或标记（store 迁移只能追加）
- [x] 外壳在一轮最后一条消息下显示用时，样式同 `divider` 的淡色小字
- [x] 恢复的历史会话：有记录就显示，没有就不显示
- [x] 工作台测试：用假 Agent 跑一轮，用时被记录并能读出
- [x] Tester：一轮结束后出现用时

## 不做

- token 用量：适配器暂不报告，另行调研。

## 实现说明

- 工作台原来没有记每轮的用时：`Status.Since` 只在运行中有，结束时只写日志。
- 现在每轮结束时（`endTurn`，正常结束、停止、原生会话自己退出都走这里）加一个 `model.TurnEnded` 标记，记下 `Took`（从开始到结束）和 `Stopped`（以中断结束）。
- 存储：沿用 markers 表，追加一次迁移，加 `took_ms` 和 `stopped` 两列。
- 工作台把这类标记单独放在 `s.turns`，由新的 `TurnEnds(id)` 读出，`Markers(id)` 不包含它们。这样原来依赖 `Markers` 的逻辑（比如判断“命令没有输出”）和测试都不受影响。
- 外壳把 `TurnEnds` 和 `Markers` 一起交给 `messages`，`divider` 画成一行淡色小字：“用时 1m 05s”，或者“已停止 · 用时 3s”。缩进同“命令已执行，没有输出”（58），14 改序号列时再一起调。
- 以前的会话没有这类标记，就不显示，不从消息时间去推算。
- 测试：工作台 `TestTurnEnds` 用假时钟跑一轮 65 秒和一轮停止的 3 秒，检查记录、重新打开后仍在、不混进 `Markers`；Tester `TestTurnSummary` 检查结束后出现“用时”，停止后出现“已停止”。另外 store 的 `TestLevelsBecomeModes` 原来写的是“上一个版本”，现在指明是权限模式迁移之前的版本。

## 没有验证

- 重试（`Retry`）也算一轮，会单独留一行用时。
- 压缩上下文作为单独一轮时，分隔线下面也会多一行用时。
- 以上两种情况我认为保留是合理的，但没有在真机上看过效果。
