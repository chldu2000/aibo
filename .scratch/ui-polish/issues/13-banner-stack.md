# 13: 输入区上方的横幅合并

Status: resolved
Blocked by: 19

**What to build:** 同时出现多个横幅时，它们不会在输入区上方叠成一大块。

现状：`banners`（`internal/shell/view.go`）依次画失败、恢复失败、登录、工作区目录丢失、已归档、通知、高亮，最多七种可同时出现，每种一块玻璃。再加未开始的审批卡和徽章行，输入区能占去半个窗口。

- [x] 已归档不再用横幅：标题栏标题旁显示“已归档”标记，取消归档在“…”菜单里（19）
- [x] 定优先级：需要用户做决定的（恢复失败、登录、目录丢失）在前并完整显示；说明性的（失败、通知、高亮）在后
- [x] 超过两个时，只完整显示最高优先的一个，其余折成一行“还有 N 条提示”，点开展开
- [x] 能关掉的（通知、高亮）保留关闭按钮
- [x] Tester：构造四种横幅，只占两块高度；点开后全部可见；已归档会话的标题旁有标记

## 决定（2026-11-27）

- 已归档改成标题旁的标记；目录丢失继续用横幅，因为它带着必须做的“重新定位”。

## 实现说明

- `banners`（`internal/shell/view.go`）先把要显示的横幅收集成一个按优先级排好的列表，再画出来。
  - 需要用户做决定的在前：恢复失败、未登录、工作区目录不存在。
  - 说明性的在后：失败、通知、高亮。
- **折叠**：
  - 不超过两条时全部显示。
  - 超过两条时只显示第一条，下面一行“还有 N 条提示”，点击后全部展开，末尾变成“收起提示”。
  - 展开状态记在 `sessionView.bannersOpen`，降到两条以内时复位。
  - 每条横幅都带 Key，折叠和展开时元素身份不变。
- **能关的照旧能关**：通知和高亮保留关闭按钮，折起来时要先展开才能关。
- **已归档**：不再用横幅。标题栏的标题旁边显示一个“已归档”小标记，悬停提示原来那段说明；取消归档在“…”菜单里（19）。
- **小重构**：
  - 未登录的判断提成了 `signedOut`，横幅列表和 `loginBanner` 共用；
  - 新增 `chevron.down`、`chevron.up` 两个图标的后备图形。
- **测试**：
  - 新增 `TestBannerStack`，用真实条件造出四条横幅：假 Agent 报未登录和失败，删掉工作区目录（`IdleCheck` 设短，让工作台发现），`Reveal` 加高亮。检查了：
    - 折叠时只有“未登录”和“还有 3 条提示”；
    - 展开后四条都在，且顺序是未登录、目录不存在、失败；
    - 收起后恢复折叠；
    - 展开后关掉高亮，再收起，变成“还有 2 条提示”；
    - 归档后标题旁有标记，没有横幅。
  - `TestComposerClearance` 原来靠归档横幅把输入区撑高，改为直接以输入框的上沿为准。

## 没有验证

- 折叠时被藏起来的是失败和通知这类说明，而决定类的横幅只显示第一条：恢复失败和未登录同时出现时，未登录会被折起来。这种组合实际很少见。
- 标题旁“已归档”标记的样子，没有在真机上看过。
