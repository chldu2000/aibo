# 22: 空会话的引导

Status: resolved
Priority: 最低，排在本组最后

**What to build:** 新会话不只是一行“开始对话”，而是告诉用户这是哪个 Agent、在哪个工作区，并给出几个可点的起手动作。

现状：没有消息时列表中间只有一行淡色文字（`locales.StartConversation`）。

- [x] 中间显示 Agent 图标、名字、工作区路径、当前模型和模式
- [x] 下面几个起手动作：@ 提及文件、引用其他会话、Agent 的常用命令（`/` 面板里的前几个）
- [x] 点击动作等同于在输入框里做对应操作
- [x] Tester：新会话显示 Agent 名和工作区；点“提及文件”打开 @ 面板

## 决定

- 保留，排在最后（2026-11-27）。

## 实现说明

- 新文件 `internal/shell/empty_session.go`。没有消息时，列表中间依次显示：
  - Agent 图标；
  - Agent 名字；
  - 工作区路径；
  - 一行“模型 · 模式”；
  - 原来的“发一条消息开始对话”；
  - 一排起手动作。
- 模型名和输入区的模型芯片用同一个函数（`modelInUse`），只读已知的列表（`PeekModels`），不额外加载。模型列表还没取到时显示“默认模型”，和芯片一致。
- 模型和模式合成一行文字（“fake-default · Ask”），不分开写“模型：x”：会话里的文字会先于输入区被 Tester 找到，和芯片同名会让别的测试点错地方。
- 起手动作：
  - “@ 提及文件或会话”：等于点输入区的 @ 按钮（`openPull`）。清单里的“@ 提及文件”和“引用其他会话”合成了这一个，因为 @ 面板本来就同时搜文件和会话，分成两个按钮效果完全一样。
  - Agent 的前三个命令，显示为“/名字”，Tooltip 是命令说明，Label 是“以 /名字 开始”（“使用 /名字”已经是 `/` 面板里的 Label）。点了等于在面板里选这个命令：草稿里出现命令芯片，不发送。
  - 点完焦点回到输入框。
- 命令只读已知的清单（`PeekCommands`），不为它启动 Agent：ACP 的清单要先启动会话的进程才能拿到，Cursor 启动又慢。用户在这个工作区用过一次 `/`，或者 Agent 自己报告过以后，起手动作里就会出现命令。
- 新文案：`starterMention`、`starterCommand`。
- 测试 `TestEmptySession`：显示 Agent 名、工作区路径、模型和模式；只给前三个命令；点命令后草稿里出现芯片，什么也没发出；点“@ 提及文件或会话”打开 @ 面板。
