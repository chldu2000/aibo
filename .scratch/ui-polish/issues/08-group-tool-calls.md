# 08: 连续的工具调用合成一组

Status: needs-triage
Type: prototype

**What to build:** Agent 一轮里连续的工具调用合成一行摘要（例如“读了 5 个文件，搜索 2 次，运行 1 条命令”），点开再看每一条；正在运行、等待审批、失败或被中断的调用始终单独露出。

现状：每个工具调用是 `messages` 列表里的一行 `Collapsible`（`internal/shell/render.go` 的 `tool`），一轮跑十几个 Read/Grep 时会话里就是十几行，回复正文被挤散。

- [ ] 先做原型（`prototype` 技能），按下面的决定看措辞和视觉效果
- [ ] 原型定稿后补实现清单，状态改为 ready-for-agent

## 决定（2026-11-27）

- 分组边界：两段正文之间的所有工具调用合成一组，不分类型。
- 摘要按 `workbench.ActivityOf` 的类别计数。
- 运行中、等待审批、失败、被中断的调用不进组，单独显示在组后。
- 选择模式下所有组自动展开，按条选；引用的单位仍是 `seq`。
- 高亮（`reveal`、`v.highlight`）落在组内时组自动展开。分组只改显示，不改消息和 `seq`。

## 原型后再定

- 摘要的具体措辞和样式；运行中的组怎样表现进度。

## 原型（2026-11-28）

- **位置**：分支 `prototype/08-tool-groups`（提交 `5f95922`），不合并进 main。
- **运行**：`git checkout prototype/08-tool-groups && go run ./cmd/prototype-toolgroups`
  - 用临时数据目录，关窗就删。
  - 会话里预先跑了两轮（explore、fix），在输入框里发 `live`（慢慢一条条调用）或 `wait`（停在一个待审批的命令上）可以看进行中的样子。
  - 右上角的切换条，或 ←/→，切换变体；也可以用 `AIBO_PROTO_TOOLGROUPS=B` 指定起始变体。
- **三个变体**：
  - **A 摘要行**：整组折成一行“9 个工具调用 · 读了 5 个文件 · 搜索 3 次 · 运行 1 条命令”，点开后左边一条竖线，下面逐条列出原来的调用行。进行中时箭头换成转圈，写“正在调用工具 · 已完成 N 个”。
  - **B 图标串**：每个调用一个按类别着色的小图标，后面跟计数和摘要。点一个图标只展开那一条，点摘要文字展开全部。进行中时末尾转圈。超过 24 个显示“+N”。
  - **C 只露最后一条**：一张玻璃卡片，上面一行“展开前面 N 个调用”加摘要，下面完整显示最近的那个调用。进行中时，最近一条会跟着变。
- **原型里先定下的规则**（按“决定”一节）：
  - 两段正文之间连续的工具调用成组；只有一个正常结束的调用时不成组。
  - 运行中、待审批、出错、被中断的不进组，排在组后。
  - 选择模式不分组；高亮落在某段里时，这段不分组。
- **待定**：
  - **分类**：摘要需要比 `ActivityOf` 更细的分类。原型里按工具名分成读、搜索、修改、命令、子 Agent、网页、其他七类（`protoKindOf`）。实现时要么扩展 `ActivityOf`，要么另加一个只给显示用的分类函数。
  - **等审批时的显示**：等待审批时，组不显示进度（不转圈），因为 Agent 在等人，而不是在调用。
- **截图**：
  - 分支上的 `TestPrototypeToolGroupShots` 在设了 `AIBO_PROTO_SHOTS=<目录>` 时，会把每个变体折叠和展开的样子存成 PNG。
  - 分支上的 `TestNoTextInCode` 会失败，因为原型的文字直接写在代码里，这是有意的。
