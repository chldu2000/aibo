# 05: 精确引用范围与发往新会话

**What to build:** 用户在源会话里进入选择模式：点击设起点，Shift+点击扩展，或者用“选中整轮”“选中整个会话”。选区不连续时，aibo 把它补齐为连续范围，提示“已补齐中间的消息”，并显示“#a–#b · n 条”。发出前可以预览概要。目标可以是已有会话（包括当前会话），也可以是新会话（选择 Agent 和工作区）。接收方 Agent 可以分页读取长引用，并用 `read_message` 读完整的单条消息。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（选区规整、工作台 MCP server · 分页）。原型：`prototype/reference-ux` 分支（方案 A）。

**Blocked by:** 04（把整个会话推送为引用）

**Status:** resolved

- [x] 选择模式基于整条消息多选，支持点击、Shift 扩展、拖选、选中整轮、选中整个会话；选中样式是自定义的
- [x] 不连续选区规整为“最小序号到最大序号”，并展示规整结果
- [x] 发出前能预览概要；能发往新会话（选 Agent 和工作区）或已有会话
- [x] 按整条消息选中后可以复制，内容从数据模型取
- [x] `read_reference` 每页约 8k token，页内单条工具输出最多约 2k token，页尾写明剩余条数和 cursor；支持 `from_seq`
- [x] `read_message` 读取单条消息，每页约 25k token；越界时报错并写明有效范围
- [x] `include_thinking` 默认不含思考内容，为 true 时包含
- [x] 主接缝测试覆盖选区规整、分页边界、cursor 续读和越界错误

## Comments

- 实现说明：
  - 04 的“引用整个会话”按钮改为进入选择模式；选择栏里有“选中整个会话”“选中整轮”“复制”“发给…”。“发给…”先选目标（已有会话，或某工作区里某个 Agent 的新会话），再预览概要，确认后才创建引用；预览里的引用 ID 是占位符，其余与最终概要完全一致。
  - 选择用 MyGO `ListState.Selection` + `DragSelect`（点击、Shift、Cmd、拖选、Cmd+A）。选中样式改为浅蓝染色加正文颜色：只在选择模式里覆盖列表的 accent。选择模式下消息内容不接收输入，按下任何位置都是选中这一行。
  - 选区不连续时直接把中间的消息加进选区，并提示“已补齐中间的消息”，提示保留到选区下一次变化。
  - token 用估算：CJK 字符每个算 1 token，其余每 4 字节算 1 token。三个预算在 `workbench.Options.Budgets` 里，设置界面见任务 14。
  - cursor 的格式：`read_reference` 是 `s<序号>`，`read_message` 是 `o<字符偏移>`，Agent 照页尾给出的原样传回即可。
  - 分页时，工具调用超过约 2k token 的部分截掉；其他消息超过一页预算时也截断，页尾提示改用 `read_message` 读全文。
- 测试：
  - `include_thinking` 的测试是直接往存储里写入带思考内容的消息：假 Agent 还不会发思考事件，思考事件在任务 02 里加。
  - Tester 不允许点击“不接收输入”的文字，所以界面测试按序号标签所在的位置点击，效果等同于用户点在那一行上。
