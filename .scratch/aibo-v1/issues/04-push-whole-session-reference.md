# 04: 把整个会话推送为引用（假 Agent 读取）

**What to build:** 用户在一个会话里选择“引用整个会话 → 发给已有会话”，选好接收方会话。接收方的输入框里出现引用草稿胶囊，可以移除，也可以和自己写的话一起发出。发出后，接收方的会话记录里显示一张蓝色引用卡片：一行写明 Agent、标题、范围和条数，展开后是 Agent 实际收到的 `<aibo-reference>` 文本。接收方 Agent（此时是假 Agent）通过 MCP 工具读取引用，会话里显示“读取了 #a–#b”，点击可以跳回源会话并高亮被引用的范围。

这一条打通引用服务和工作台 MCP server：进程内的 streamable HTTP（127.0.0.1 随机端口），每个会话一个 bearer token，先提供 `list_references` 和 `read_reference`（暂不分页）。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（引用服务与引用概要、工作台 MCP server）。

**Blocked by:** 01（工作台骨架：用假 Agent 跑通一个会话）

**Status:** resolved

- [x] 引用有全局唯一的短随机 ID，记录源会话、起止序号、接收方会话、概要、状态（草稿或已交付）
- [x] 只有已结束的消息能被引用；引用是快照，源会话后来的内容和改名不影响已发出的引用
- [x] 概要按规则生成：首条用户消息和末条 Agent 回复各截 200 字以内，被中断的标注“（已中断）”，缺一种时取首尾两条；每块不超过 1500 字；创建时固定
- [x] 发送时引用块按顺序放在用户正文之前；存储里用户消息只保存原文和引用列表
- [x] 一个会话可以先后收到多个引用，相互独立
- [x] MCP server 校验 `Origin` 和 bearer token；每个会话只能读到交给自己的引用，其他引用 ID 一律拒绝
- [x] `read_reference` 返回给大模型读的文本，每条消息以 `### [序号] 角色 · 时间` 开头，工具调用写成工具名、参数摘要和结果
- [x] 源会话被删除后，读取返回“引用的源会话已被删除”
- [x] 主接缝测试用一个 MCP 客户端按真实 Agent 的方式调用工具，覆盖创建、概要、快照语义、读取边界和读取记录

## Comments

- 实现说明：
  - MCP server 用 go-sdk 的无状态模式（Stateless）：每个请求只靠 token 找到对应会话的 server，不会接入别的会话的 MCP 会话。中间件拒绝非回环地址的 `Origin`。每次连接 Agent 都签发新 token，旧 token 作废；会话的原生进程结束或会话被删除时，token 也作废。
  - 读取记录由 MCP server 一侧记下，存进数据库，显示在引用卡片里（“Agent 读取了 #a–#b”），点“在源会话中查看”跳回源会话，高亮被引用的范围。
  - 只有引用、不写正文的消息也可以发出；这种消息不会被拿来当会话标题。
  - 概要里“可用工具”目前只列 `read_reference` 和 `list_references`，任务 05、07 加上其他工具时一并补上。
  - 跨工作区时，概要和读取结果开头都写源工作区，这部分规则顺带做了；Agent 实际能否读源工作区的文件见任务 09。
- 暂时的限制：
  - 引用给会话自己暂时会报“暂不支持”，留给任务 12。
  - 删除会话目前只有核心层的操作（测试用），界面上的删除见任务 16。
  - 侧栏里过长的会话标题被直接截断，没有省略号，留给任务 16/17。
