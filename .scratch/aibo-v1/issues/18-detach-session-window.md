# 18: 把会话拆出独立窗口

**What to build:** 用户点击会话标题栏上的“在新窗口打开”，这个会话就拆到一个单独的窗口里，方便同时盯着两个会话。拆出的窗口只显示会话区（标题栏、消息列表、输入框），不带侧栏。优先级低。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（工作台外壳 UI · 拆出独立窗口）。

**Blocked by:** 17（Liquid Glass 外壳与输入框）

**Status:** resolved

- [x] 点击“在新窗口打开”后，会话出现在新窗口里，只显示会话区
- [x] 两个窗口里的同一个会话状态一致（流式输出、审批卡片、徽标）
- [x] 关闭独立窗口不会中断会话；主窗口里仍能打开它
- [x] 系统通知跳转到审批卡片时，会话已在独立窗口里打开的，激活那个窗口

## Comments

- 实现说明：
  - 每个独立窗口有自己的一个外壳（`Options.Only` 设为会话 ID），和主窗口共用同一个工作台，各自订阅变化。所以两个窗口的流式输出、审批卡片、徽标、运行状态都一致，在任一窗口里审批都会同步。
  - 独立窗口只显示会话区：
    - 没有侧栏、不发系统通知（通知由主窗口发）、不显示“在新窗口打开”；
    - 标题栏左侧让出 84，给红绿灯按钮；
    - 重命名和删除的弹窗照常可用；会话被删除后，窗口里写“这个会话已被删除”。
  - 要切到别的会话时（引用到新会话、在源会话中查看），交给主窗口显示并激活主窗口（`ShowInMain`），独立窗口始终停在原来的会话上。
  - 同一个会话只开一个独立窗口，再点“在新窗口打开”会激活已有的那个。窗口关闭时外壳取消订阅，会话照常运行，主窗口里仍然能看。
  - 点击系统通知时，如果会话有独立窗口，就激活那个窗口，否则在主窗口里打开。
- 测试：界面测试 `TestSessionWindow` 覆盖了以下几项：
  - 打开时调用 `OpenWindow`；
  - 独立窗口里不出现侧栏内容；
  - 两个窗口同时显示回复、审批卡片和徽标，在独立窗口里批准后两边都消失；
  - 打开别的会话交给主窗口；
  - 关闭后主窗口不受影响；
  - 删除后有提示。
- 没有验证：
  - 通知跳转只有打包后的 app 才能试。
  - 重命名后，独立窗口的系统标题还是打开时的标题，没有跟着更新（窗口内标题栏会更新）。
- 真机检查（用户确认）：在真实 app 里打开、聚焦、关闭独立窗口都正常。
