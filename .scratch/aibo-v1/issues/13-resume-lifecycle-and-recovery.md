# 13: 续接生命周期与续接失败兜底

**What to build:** aibo 启动时不启动任何 Agent 进程，用户在某个会话里发出第一条消息时才续接原生会话；会话闲置 30 分钟后自动断开。原生会话丢失或不兼容、续接失败时，会话顶部出现橙色横幅，附上 Agent 返回的错误原文，提供三个选项：新开原生会话并引用之前的内容（推荐）、新开原生会话但不带引用、暂不处理（会话只读）。选择新开后，会话里出现“已切换到新的 Agent 原生会话”的分隔线。退出 aibo 时如果有会话在运行，先提示用户。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（会话运行时）。

**Blocked by:** 02（在 aibo 里和 Claude Code 对话）、03（在 aibo 里和 Codex 对话）、12（上下文压缩与自引用）

**Status:** resolved

- [x] 发首条消息时才续接；闲置 30 分钟断开（Claude 结束进程，Codex 卸载 thread）；有待审批的会话不断开
- [x] 每次续接都重新生成 MCP token，旧 token 立即作废；同时重新带上额外可读目录和放行规则
- [x] Claude 的 `--resume` 报错或进程退出、Codex 的 `thread/resume` 返回错误，都判定为续接失败；不预先检查 Agent 的本地存储
- [x] 三个选项按规格执行；“带引用”时生成一个自引用草稿，范围是重置之前的全部消息
- [x] 新开原生会话时记录上下文重置标记，原生会话 ID 历史里追加新 ID
- [x] 退出时，进行中的轮次以“已中断”保存，未处理的审批视为拒绝
- [x] 主接缝测试覆盖闲置断开、有待审批时不断开、token 轮换、续接失败后的三种选择
- [x] 界面测试覆盖续接失败横幅

## Comments

- 实现说明：
  - 续接失败的判断：`agent.ErrResumeFailed` 包着 Agent 自己的原话返回。
    - Claude：`Start` 等 `initialize` 的回应。续接一个找不到的会话时，Claude 会在回应之前就报错退出，stderr 是 “No conversation found with session ID: …”；正常续接 0.2 秒内就会回应（2.1.318 实测）。
    - Codex：`thread/resume` 返回的错误，如 “no rollout found for thread id …”。
  - 发消息时改为先续接、再记录用户消息：续接失败时这条消息不会写进会话，输入框里的文字也保留着。续接失败后，发消息和压缩都会被拒绝，直到用户在横幅上选择怎么处理。
  - 三个选项：
    - “新开原生会话并引用之前的内容（推荐）”：记一个上下文重置标记，并在输入框里放一个自引用草稿，范围是重置之前的全部消息。
    - “新开原生会话（不带引用）”：只记标记。
    - “暂不处理”：会话只读，横幅缩成一行，仍可随时选择新开。
  - “新开原生会话”的实现方式：在原生会话 ID 历史里追加一个空 ID，下次启动就不续接、从头开始，重启 aibo 后也照样生效；新的原生会话 ID 拿到后照常追加。
  - 闲置断开：30 分钟没有轮次运行、也没有待审批的会话，会结束 Agent 进程（Codex 是退订 thread），下次发消息时自动续接。时长现在在 `workbench.Options` 里，设置项见任务 14。每次续接都会换新的 MCP token，测试验证了旧 token 随即失效。
  - 退出：有会话在运行时先弹窗确认。确认退出后，进行中的回复保存为“已中断”，未处理的审批标为“未处理”，不会执行。
- 测试：
  - 工作台：续接失败（不记录消息、拒绝发送和压缩）、只读、两种新开方式、重启后仍然新开、闲置断开（有待审批时不断开）、token 轮换。
  - 界面：横幅的三个选项。
  - 契约测试：用不存在的原生会话 ID 续接，两家都返回 `ErrResumeFailed` 并带上原话，本机已通过。
- 没有验证：退出确认弹窗要在真实的 app 里才能触发，没有自动化测试。
