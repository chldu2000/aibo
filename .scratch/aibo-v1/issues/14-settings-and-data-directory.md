# 14: 设置弹窗与数据目录

**What to build:** 用户通过侧栏底部的齿轮或 ⌘, 打开全局设置弹窗，里面有“通用”和“高级”两页（“Agent”页见“Agent 的发现、版本与登录”）。用户可以把数据目录改到自己方便找的位置，aibo 会迁移数据，目标在 iCloud Drive、Dropbox 这类同步盘上时给出警告。自定义的数据目录不可用时，显示“重试 / 重新选择位置 / 退出”，绝不悄悄换成一个空库。aibo 同一时间只运行一个实例，再次启动时直接激活已打开的窗口。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（会话模型与存储 · 存储、工作台外壳 UI · 设置）。

**Blocked by:** 01（工作台骨架：用假 Agent 跑通一个会话）

**Status:** resolved

- [x] 设置是全局弹窗，面板用 glass；通用页有数据目录、新会话默认审批档位、待审批系统通知；高级页有两个分页预算、单条工具输出保留长度、闲置断开时长
- [x] “数据目录在哪里”固定保存在默认位置的小配置文件里；项目目录里不写任何文件
- [x] 更改数据目录前必须先关闭所有会话；新目录为空时复制、校验、再删除旧数据；新目录已有 aibo 数据时直接使用；同步盘给出警告
- [x] 数据目录不可用时显示三个选项，不新建空库
- [x] 对数据目录加文件锁；第二个实例启动时激活已有窗口后退出
- [x] 数据库结构有版本号，升级前先备份数据库文件
- [x] 主接缝测试覆盖迁移、目录不可用、单实例锁、升级前备份

## Comments

- 实现说明：
  - 新包 `internal/appdata`：
    - 默认位置的配置文件 `config.json` 只记“数据目录在哪里”。
    - 解析数据目录：自定义目录不在时报 `ErrUnavailable`，绝不新建；默认目录不存在时自动创建。
    - 数据目录上的 `flock` 文件锁（`aibo.lock`）。
    - 识别同步盘：iCloud Drive、`~/Library/CloudStorage` 下的各家云盘、Dropbox、Google Drive、OneDrive、Box。
    - 搬移：目标已有 aibo 数据就直接使用、不复制；目标是空文件夹就流式复制，逐个比对文件大小，再对数据库跑 SQLite 的 `integrity_check`，都通过后才删掉原位置的数据；目标有别的文件就拒绝。配置文件和备份始终留在原处。
  - 其他设置（新会话默认审批档位、通知开关、三个分页预算、闲置时长）存在数据库的 `settings` 表里（数据库结构版本 7），会随数据一起搬走，改了立即生效。
  - 数据库结构升级前，先用 `VACUUM INTO` 把旧库完整备份为 `aibo.db.v<旧版本>-<时间>.bak`。
  - 设置弹窗：侧栏底部的齿轮或 ⌘, 打开，面板用 glass（改用 `DialogBase`，避免 Modal 自带的面板再套一层）。“通用”页有数据目录（在 Finder 中显示、更改）、默认审批档位、通知开关；“高级”页有三个预算、闲置时长，以及“恢复默认”。超出范围时会提示允许的范围。
  - 更改数据目录：有会话在运行时不允许。选好文件夹后，先说明这次会发生什么（直接使用已有数据，还是复制过去再删除原数据），在同步盘里还会额外警告；确认后关闭工作台、搬移、写配置，然后用 `App.Relaunch` 在新位置重新启动。搬移失败时什么都不改，照原位置重启。
  - 启动流程：先用 MyGO 的单实例锁（`RequestSingleInstanceLock`），再次启动只会激活已开的窗口；再解析数据目录、加文件锁、打开工作台。不可用时弹窗给出“重试 / 重新选择位置 / 退出”；重新选择的文件夹里没有数据时，要确认“从空白开始”。被另一个 aibo 占用时给出“重试 / 退出”。
  - 开发时仍可用 `AIBO_DATA_DIR` 指定数据目录，此时设置里不能更改。
- 测试：
  - appdata：配置文件、不可用、锁、同步盘识别、三种搬移情况。
  - store：升级前备份，且只备份一次。
  - workbench：设置的保存、生效、范围校验、重启后仍在。
  - 界面：设置弹窗，包括同步盘警告、已有数据、运行中不能更改、高级页保存和报错。
  - 实际运行了一次：第一个实例启动后持有锁文件，第二次启动立即退出。
- 没有自动化测试：启动时的几个对话框、搬移后的 Relaunch，都要在真实 app 里点。
- “Agent” 页留给任务 15。
