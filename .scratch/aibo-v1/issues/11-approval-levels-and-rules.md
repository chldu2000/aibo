# 11: 审批档位、会话规则与后台提醒

**What to build:** 用户可以给每个会话选择审批档位：每次询问、自动接受工作区内修改、全部自动（需要二次确认，选中后持续显示警示）。“本会话内始终允许”的规则在 Agent 进程重启或续接后依然有效，并且能在会话详情里查看和撤销。后台会话出现待审批请求时，侧栏显示标记并发送 macOS 系统通知，点击通知直接跳到审批卡片；有待审批的会话不会因为闲置被断开。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（审批 · 档位映射、提醒）。

**Blocked by:** 10（审批卡片与原生选项）

**Status:** resolved

- [x] 三档审批按规格的映射表传给两家 Agent；输入框底部的审批档位按钮可以切换
- [x] 档位和放行规则记入会话元数据
- [x] Codex 下由 aibo 自动回复与已记规则同类的请求；Claude 下在下次启动时通过 `--allowedTools` 带上规则
- [x] 会话详情里列出始终允许的规则，可以撤销；撤销后不再自动放行
- [x] 后台会话有待审批时，侧栏显示标记并发系统通知；点击通知跳到对应卡片
- [x] 主接缝测试覆盖档位和规则在进程重启后重新生效

## Comments

- 实现说明：
  - 审批档位和规则存在会话元数据里（数据库结构版本 5），新会话默认“每次询问”（默认值的设置见任务 14）。启动或续接时传给适配器；中途切换时，会话进程在运行就立刻生效。
  - 规则：“本会话内始终允许”这个选项本身带着规则，规则内容由适配器自己定义；工作台记下这些规则，下次启动时交回给适配器。撤销后，Agent 进程不会忘掉已给的规则，所以空闲时会结束原生会话，下次发消息时续接，不再带这条规则；如果撤销时正在回复，就等这一轮结束再重启。
  - Claude：
    - 档位映射：每次询问 → `--permission-mode manual`（2.1.318 的模式里没有 default），自动接受工作区内修改 → `acceptEdits`，全部自动 → `bypassPermissions`。
    - 始终带上 `--allow-dangerously-skip-permissions`，它只是允许中途切到全部自动，并不直接开启。
    - 中途切换档位用 control 的 `set_permission_mode`。
    - 规则在启动时带回：`Tool(content)` 加到 `--allowedTools`，目录加到 `--add-dir`，“自动接受修改”会把每次询问提升为 `acceptEdits`。规则只会放宽、不会降低档位。
  - Codex：
    - 档位映射到 thread 的 `approvalPolicy` + `sandbox`；中途切换时，下一轮在 `turn/start` 上覆盖 `approvalPolicy` + `sandboxPolicy`。“每次询问”和“自动接受工作区内修改”对 Codex 来说是同一组设置，和规格一致。
    - 规则：命令按原样精确匹配，文件修改要求路径都在规则范围内。重启后由 aibo 对匹配的请求自动回复 `acceptForSession`，让 Codex 自己的会话缓存也重新记住。
  - 界面：
    - 输入框底部的审批控件显示当前档位和规则数，点开后选档位；选“全部自动”要二次确认，之后输入框上方一直显示警示，可以一键改回。规则列在同一个面板里，可以撤销。
    - 侧栏有待审批的会话显示“待审批 N”。
    - 不在当前屏幕上的会话出现新的审批请求时发系统通知（`Shell.Options.Notify`），点通知打开那个会话。
- 实测：
  - Codex 默认的 `workspace-write` 沙箱本来就允许写 `$TMPDIR` 和 `/tmp`。任务 10 的契约测试往临时目录写，Codex 碰巧还是询问了，属于侥幸通过；现在改成写到家目录下的临时目录，用完删除。
  - 契约测试（`AIBO_CONTRACT=1`，本机已通过）：两家的档位（含中途切回每次询问），以及规则在重启后生效。
- 没有验证 / 暂不包含：
  - 系统通知只在打包后的 app 里可用（MyGO 的限制），直接运行编译出的程序时没有通知，这部分只用界面测试的回调验证过。
  - 关闭通知的设置开关见任务 14。
  - “有待审批时不会闲置断开”依赖的闲置断开本身要到任务 13 才有。
