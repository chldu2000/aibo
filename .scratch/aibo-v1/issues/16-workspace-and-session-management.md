# 16: 工作区与会话管理

**What to build:** 用户可以通过选择文件夹或把文件夹拖进窗口来添加工作区，也可以移除工作区（它下面的会话转为归档，数据保留）。工作区目录被移走或删除时显示“目录不存在”，会话仍可浏览和被引用，并且能“重新定位”到新路径。会话可以重命名、归档和取消归档、按标题和正文搜索、删除（删除前提示“该会话被 N 个引用使用，删除后这些引用将失效”）。侧栏按工作区分组、按最后活跃时间排序，最下方是“已归档”；每个会话条目显示 Agent 图标、标题和状态标记（运行中、待审批、未连接、出错、收到的引用数）。在工作区分组上点“＋”，选好 Agent 和模型后新建会话。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（用户故事 1–13、会话模型与存储 · 删除）。

## Comments

- 实现说明：
  - 核心：
    - 会话可归档、工作区可移除（数据库结构版本 8）。移除工作区时，它的会话转为归档；再次添加同一个文件夹会恢复原来的工作区，会话仍保持归档；对它的某个会话取消归档，工作区也会一起回来。
    - 目录是否丢失在启动时和每个闲置检查周期（1 分钟）检查一次。丢失后，会话可以浏览、搜索、被引用，但发消息、压缩、重试都会被拒绝；“重新定位”后，原生会话在新路径上续接。
    - 重命名：留空时恢复为第一条消息的开头；已发出的引用保留创建时的标题。
    - 搜索：匹配标题和消息正文，包含已归档的会话；标题命中的排在前面，正文命中的附一段片段。
    - `ReferencesTo` 统计其他会话对它的引用数，供删除时提示。
    - 两家都能列出模型：Claude 用一个短进程的 `initialize`，Codex 用 `model/list`；默认模型排在第一个。
  - 修了一个竞态：有几处会结束会话的原生进程（闲置断开、撤销规则、重新定位）。原来只是关闭进程，留到事件泵退出时才清掉引用，这段间隙里发出的消息会落到已关闭的进程上；而且旧进程的事件泵退出时，会把新进程正在进行的轮次也结束掉。现在统一用 `detach`：先清掉引用、作废 token，再关闭进程；已脱离的进程发来的事件一律忽略。
  - 界面：
    - 侧栏：顶部有搜索框；工作区标题右键可以重新定位、在 Finder 中显示、移除；会话右键可以重命名、归档或取消归档、删除（被引用时提示“该会话被 N 个引用使用”）；底部有可折叠的“已归档”；状态标记有待审批、运行中、出错、收到的引用数；长标题显示省略号。
    - 把文件夹拖进窗口即添加为工作区。
    - 新建会话：先选 Agent，再选模型；只有一个 Agent 时直接进入选模型这一步。
    - 会话区：目录丢失时有横幅和“重新定位”；已归档的会话有横幅和“取消归档”。
    - @ 面板可以搜到已归档的会话，以及已移除工作区里的会话。
- 和规格的出入：规格侧栏状态里的“未连接”，没有单独做标记（大部分会话平时都没有连着进程，单独标出来只会是噪音），续接失败和未登录都归入“出错”。
- 测试：
  - 工作台：移除与恢复（移除后引用照样能读）、丢失与重新定位、重命名、归档、搜索、引用计数。
  - 界面：侧栏管理的完整流程，包括右键菜单、拖入文件夹、选模型、丢失横幅和重新定位。
  - 契约测试：两家真实的模型列表。
