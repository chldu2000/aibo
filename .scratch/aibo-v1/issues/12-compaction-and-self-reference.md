# 12: 上下文压缩与自引用

**What to build:** Agent 压缩上下文时（自动或由用户手动触发），会话里在对应位置出现一条分隔线，例如“上下文已压缩 · 自动 · 19.7k → 6.3k tokens”，分隔线上方的消息照常显示。用户可以在会话菜单或快捷指令里手动压缩。用户可以把压缩之前的一段内容引用回同一个会话，让 Agent 找回细节。输入 `/clear` 这类 Agent 自带的斜杠命令时，aibo 不转发，提示“暂不支持”。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（会话运行时 · 斜杠命令、压缩事件；引用概要 · 自引用）。

**Blocked by:** 02（在 aibo 里和 Claude Code 对话）、03（在 aibo 里和 Codex 对话）、04（把整个会话推送为引用）

**Status:** resolved

- [x] Claude 的 `compact_boundary`（带 trigger 和前后 token 数）和 Codex 的 `contextCompaction` 条目（只有时间戳）都转换为压缩标记，挂在“第 N 条消息之后”，不占序号
- [x] 手动压缩：Claude 发送 `/compact`，Codex 调用 `thread/compact/start`
- [x] 以 `/` 开头的 Agent 斜杠命令不转发，提示“暂不支持”
- [x] 可以把引用发给当前会话自己；自引用概要的首句改为“这是本会话较早的一段内容，你的上下文中可能已不再保留其细节”，省略来源和源工作区两行
- [x] 读取工具的输出不包含压缩标记
- [x] 主接缝测试覆盖压缩标记的位置、自引用的概要和读取
- [x] 契约测试（环境变量开启）覆盖两家的压缩事件

## Comments

- 实现说明：
  - 适配器接口新增 `Compacted` 事件和 `Session.Compact`（作为单独的一轮运行，以 `TurnEnded` 结束）。工作台把压缩记成标记（新表 `markers`，数据库结构版本 6），挂在“当时最后一条消息之后”，不占序号；任务 13 的上下文重置标记用同一张表。
  - Claude：`system/compact_boundary` 转成标记，带触发方式和压缩前后的 token 数；手动压缩发送 `/compact`。压缩后跟着的摘要和 `<local-command-stdout>` 这两条用户文本不会被当作会话消息。
  - Codex：`contextCompaction` 条目转成标记，不带 token 数；适配器自己发起的压缩记为“手动”。手动压缩调用 `thread/compact/start`。
  - 斜杠命令：消息以 `/单词` 开头时（如 `/clear`、`/model sonnet`）不发出，并提示“暂不支持”；`/Users/...` 这样的路径和句中的斜杠不受影响。
  - 自引用：引用可以发给源会话自己。概要首句改为“这是本会话较早的一段内容……”，省略“来源”和“源工作区”两行；卡片上写作“本会话 · #a–#b”。选择模式的“发给…”里新增“本会话（找回之前的内容）”。
  - 界面：标记显示为横贯会话的分隔线；输入框底部新增“压缩上下文”按钮。
- 实测（Claude Code 2.1.318、codex-cli 0.169.0）：两家手动压缩后都能继续对话，也都能通过自引用找回压缩前说过的暗号，契约测试已通过。
- 暂不包含：规格里“会话菜单里的压缩”和“快捷指令胶囊”放在任务 17（会话详情面板、徽标与快捷指令）一起做，这次先用输入框里的按钮。
