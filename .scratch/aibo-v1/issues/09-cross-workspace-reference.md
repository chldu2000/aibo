# 09: 跨工作区引用

**What to build:** 用户把工作区 A 里的会话引用给工作区 B 里的会话时，界面上会提示这是跨工作区引用。接收方 Agent 可以只读访问源工作区的文件，读取结果开头写明源工作区的绝对路径，并提醒“文件可能已在引用之后被修改”。这份授权在会话的整个生命周期内有效，会话详情里能看到“可读的源工作区”。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（会话运行时 · 跨工作区引用、引用概要规则）。

**Blocked by:** 08（真实 Agent 读取引用）

**Status:** resolved

- [x] 概要里只在跨工作区时出现“源工作区”一行；路径不改写
- [x] 读取工具的输出开头带源工作区路径和“文件可能已修改”的提醒
- [x] Claude：会话中途收到跨工作区引用时，先用 `--resume` 加 `--add-dir` 重启进程，再发送消息；`--add-dir` 放在提示词之后
- [x] Codex：不把源工作区加入可写目录
- [x] 验证 Claude 能否按路径禁止对源工作区 Edit/Write（规格待验证项 2）：能做到就加规则；做不到就在规格里记下结论，由“审批卡片与原生选项”负责标注“写入其他工作区”
- [x] 额外可读目录记入会话元数据，续接时重新带上
- [x] 契约测试（环境变量开启）：两家真实 Agent 都能读到源工作区里的文件

## Comments

- 实现说明：
  - 概要里的“源工作区”一行，以及读取结果开头的源工作区路径和“文件可能已修改”的提醒，在任务 04 就已经做了。
  - 会话收到别的工作区的引用时，这些工作区记为会话的“可读的源工作区”（存在会话元数据里，数据库结构版本 9），之后每次启动或续接都会带上。审批控件的面板里列出了它们（会话详情面板见任务 17）。
  - Claude：每个可读目录加 `--add-dir`，并加 `--disallowedTools "Edit(//<路径>/**)" "Write(//<路径>/**)"`；路径和它解析后的真实路径都写上，因为 macOS 上 `/tmp` 实际是 `/private/tmp`。会话中途收到新的跨工作区引用时，先断开原生会话，再用 `--resume` 带上新目录启动，然后发送。（`agent.DirsAtStart` 接口标明需要这样重启；Codex 不实现它。）
  - Codex：不把源工作区加入可写目录。它的 `workspace-write` 沙箱本来就能读任意位置、不能写工作区以外的地方，所以不需要重启。
- 实测（Claude Code 2.1.318、codex-cli 0.169.0）：
  - 规格待验证项 2 已回填：Claude 按路径禁止 Edit/Write 有效；往那里写文件的 Bash 命令也会被拒；在全部自动（`bypassPermissions`）下依然有效。
  - 契约测试已在本机通过：两家都读到了源工作区里的文件；尝试在源工作区写文件，都被拒绝，也没有弹出审批。
- 限制：Codex 设为“全部自动”时用的是 `danger-full-access`，沙箱不再限制写入，源工作区就没有只读保护了。审批卡片上的“写入其他工作区”标注只在会询问的档位里起作用。
