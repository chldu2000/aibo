# 17: Liquid Glass 外壳与输入框

**What to build:** aibo 的外观达到“像 macOS 原生应用”的程度：左侧是浮动的 Liquid Glass 侧栏，和会话区之间留缝；会话区顶部是浮动的 glass 标题栏（Agent 图标、标题、工作区，以及“在新窗口打开”和“会话详情”两个图标按钮），消息列表在标题栏下方滚动并渐隐；会话详情以 glass 面板浮出。输入框是一张 glass 卡片，底部是一排图标按钮，右侧是圆形的发送／停止按钮；上方是染色 glass 徽标，显示终端进程数、运行中的子 Agent 数、待审批数和收到的引用数，以及“压缩上下文”“引用会话”两个快捷指令。所有文字和图标都跟随系统的浅色、深色模式。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（工作台外壳 UI）。原型：`prototype/window-layout` 分支（最终版 main.go 和截图）。

**Blocked by:** 02（在 aibo 里和 Claude Code 对话）、03（在 aibo 里和 Codex 对话）、10（审批卡片与原生选项）

**Status:** ready-for-human（只剩真机检查待验证项 5）

- [x] 窗口 `Transparent` + `VibrancySidebar` + `TitleBarHiddenInset`；侧栏用系统 Liquid Glass，圆角，四周留 8 的边距（在外层加 padding）
- [x] 会话详情面板包含 Agent 和模型、工作区、原生会话、审批档位、始终允许规则、可读的源工作区，以及压缩、重命名、归档、删除操作
- [x] 输入框底部的图标按钮：附件、@ 引用、模型（只显示）、审批档位；发送和停止共用一个圆形按钮
- [x] 徽标数量为 0 时隐藏；验证终端进程数和子 Agent 数能否从事件流实时统计（规格待验证项 3），做不到时只显示“有／无”，并回填规格
- [x] 审批卡片和提示横幅用橙色染色 glass，引用卡片用蓝色染色 glass
- [x] 颜色规范：文字和图标颜色都取自主题；染色 glass 浅色透明度约为深色的 45%；彩色 SVG 用 `ui.Image`，单色图标用 SF Symbols 或 `ui.Icon`
- [ ] 真机检查浅色和深色模式下系统材质上的文字是否清晰（待验证项 5），以及代码块长行能否横向滚动（待验证项 6），结论回填规格
- [x] 一万条消息的长会话滚动流畅（可用 `MYGO_FRAME_STATS` 验证）

## Comments

- 实现说明：
  - 窗口、侧栏、浮动标题栏、审批卡片和横幅的染色 glass，这些在之前的任务里已经做好了。这次新增的有：
    - 标题栏右侧的两个按钮：“在新窗口打开”，在 `Options.OpenWindow` 接上之前（任务 18）不显示；“会话详情”。
    - 标题和工作区路径只占一行，路径过长时省略中间部分。
  - 会话详情：从标题栏下方浮出的 glass 面板，内容如下：
    - Agent 和模型、工作区（目录不存在时会注明）；
    - 原生会话：最新的 ID、这是第几个、进程是否在运行；
    - 审批档位：分段控件用短名称，下面写这一档的含义，选“全部自动”时要确认；
    - 始终允许的规则，可以撤销；可读的源工作区；
    - 操作：压缩、重命名、归档或取消归档、删除。重命名和删除沿用侧栏的弹窗。
  - 输入框上方：
    - 左侧是染色 glass 徽标：终端进程（蓝）、子 Agent（紫）、待审批（橙）、收到的引用（绿），数量为 0 时不显示；
    - 右侧是快捷指令：“压缩上下文”，以及“引用会话…”（进入选择模式）。
  - 输入框底部：附件（灰显，暂不支持）、@ 引用、模型（只显示）、审批档位。“压缩”从这一排移到了上面的快捷指令里。
  - 序号列加宽到 44，并限制为一行：之前到 #9995 这样的序号会折成两行。
- 实测（无头渲染，窗口 1180×780）：
  - 一万条消息的会话：首帧 0.45 ms，滚动时平均每帧 3.2 ms。消息列表只布局看得见的行，所以首帧和消息数量基本无关。这是无头渲染的数据，`MYGO_FRAME_STATS` 的真机数据还没有测。
  - 代码块长行：可以横向滚动，并显示滚动条。已回填待验证项 6。
  - 终端进程数和子 Agent 数：可以从事件流实时统计。已回填待验证项 3，并注明后台运行的不计入。
  - 浅色和深色模式下，会话详情、徽标和输入框都看过：文字清晰，审批档位控件不再被截断。
- 没有验证：
  - 真实窗口里系统材质上的文字是否清晰（待验证项 5），需要你看。
  - 代码块的复制按钮是 MyGO 自带的英文 “Copy”，没有汉化。
- 试用反馈后的补充：
  - 现象：一个收到引用的 Codex 会话一直显示运行中，没有回复。
  - 原因：不是 aibo 卡住了，而是 Codex 连不上 OpenAI：WebSocket 的 TLS 握手失败，改走 HTTP 也超时，Codex 自己按退避重试了约 8.5 分钟，之后才正常完成。重试期间 app-server 每次都发出带 `willRetry` 的 `error` 通知，但 aibo 原来把这种通知丢掉了，所以界面上什么也看不到。
  - 修复：
    - 新增事件 `Retrying`。Codex 带 `willRetry` 的 error 通知、Claude 的 `system/api_retry`（字段取自 2.1.318 的二进制）都映射成它。
    - 工作台在会话状态里记录 `Retrying` 和 `Since`；Agent 一有其他进展，重试状态就清掉。
  - 会话区：轮次运行时，消息流最后多一行运行状态，内容是转圈图标和“X 正在工作 · 用时”；有待审批时写“在等你审批”。连不上模型时，下面再用橙色写出重试原因。
  - 没有验证：Claude 的 `api_retry` 只有解析测试，没有在真实断网的情况下跑过。
