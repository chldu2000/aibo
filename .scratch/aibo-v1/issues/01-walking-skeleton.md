# 01: 工作台骨架：用假 Agent 跑通一个会话

**What to build:** 打开 aibo 后出现一个窗口，左边是侧栏，右边是会话区。用户可以添加一个工作区，用假 Agent 新建会话，发出消息后看到 Markdown 回复以流式显示。关掉 aibo 再打开，工作区、会话和消息都还在。

这一条要把各层都打通一遍，后面的任务都在它上面扩展：

- Agent 适配器统一接口，加一个按脚本输出事件的假 Agent；
- 会话存储（SQLite 放在数据目录，会话只追加，消息按序号编址）；
- 会话运行时的最小版（发送一个轮次、接收事件、写入存储）；
- 外壳 UI 的基础版（窗口、侧栏按工作区分组、会话列表、输入框）。

外观按规格做出基本结构即可，Liquid Glass 的细节放到“Liquid Glass 外壳与输入框”。

规格：[aibo v1 规格](../../multi-agent-workbench-v1/spec.md)（总体架构、Agent 适配器、会话模型与存储、测试决策）。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 用 `CGO_ENABLED=0` 能构建并启动；窗口里有侧栏和会话区
- [x] 能通过选择文件夹添加工作区，工作区以绝对路径识别
- [x] 能在工作区下用假 Agent 新建会话；标题默认取自第一条用户消息的开头
- [x] 发出消息后，回复以流式 Markdown 显示，完成后改为静态渲染；列表随新消息跟随到底部
- [x] 消息在会话内按单调递增的序号编址，用户消息只保存原文
- [x] 重启后，工作区、会话和消息都能从数据目录恢复
- [x] 主接缝测试框架就绪：测试通过工作台核心对外的操作驱动，适配器换成假 Agent，SQLite 放在临时目录；至少覆盖“发消息、流式回复、重启后历史仍在”

## Comments

- 实现说明：
  - 适配器接口目前只有 Start / Send / Interrupt / Close 和五种事件（原生会话 ID、回复增量、回复结束、轮次结束、出错）。压缩、审批、能力探测，以及工具调用、思考、计划等事件，留给需要它们的任务再加，避免先写用不上的接口。
  - 输入框：Enter 发送，Shift+Enter 换行。
  - 开发时可以用 `AIBO_DATA_DIR` 指定数据目录；正式的数据目录设置见任务 14。
  - 演示版只接入假 Agent（`fake.Demo`），真实 Agent 见任务 02、03。
- 测试：
  - 主接缝测试在 `internal/workbench`，界面测试（无窗口 Tester）在 `internal/shell`。
  - 本机 CLT 链接器读不了 macOS 27 SDK，所以界面包没法开竞态检测（`-race` 需要 cgo）；核心包可以，已开竞态检测连跑多遍通过。
