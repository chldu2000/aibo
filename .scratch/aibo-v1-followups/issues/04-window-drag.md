# 04: 窗口可以拖动

**What to build:** 主窗口和独立的会话窗口都能像普通 macOS 窗口一样拖动：按住侧栏顶部（红绿灯所在的那一条）、浮动标题栏的空白处拖动，窗口跟着走；双击这些地方，按系统设置缩放或最小化窗口。按钮、标题文字的选择、消息列表的拖选不受影响。

现状：两种窗口都是 `TitleBarHiddenInset` + `Transparent`（`cmd/aibo/main.go` 的两处 `mygo.NewWindow`），系统标题栏让给了内容，但内容里没有一处标成可拖动区域，所以窗口拖不动。MyGO 原生界面用 `ui.Element.DragWindow` 标记拖动区域（见 `WindowOptions` 的 `TitleBarStyle` 注释，以及 `ui.Context.TitleBar` 取标题栏高度和红绿灯位置）。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 侧栏顶部到红绿灯下沿的一条、会话区浮动标题栏（图标按钮以外的部分）标为 `DragWindow`；高度取 `ui.Context.TitleBar`，不写死
- [x] 独立会话窗口没有侧栏，浮动标题栏同样可拖
- [x] 没有选中会话时（空白页、设置页）也有可拖动的区域
- [x] 双击拖动区域，行为跟随系统“双击窗口标题栏以…”设置（如果 MyGO 的 `DragWindow` 不处理，记进实现说明，另开任务）
- [x] 拖动区域里的按钮照常可点；消息列表的 `DragSelect` 不受影响
- [x] 界面测试：标题栏和侧栏顶部的元素带有拖动标记（如果 Tester 能看到）；真机上把两种窗口各拖一次，结论写进实现说明

## 实现说明

- 侧栏：顶部那一列（红绿灯下方的留白、“aibo”标题行、搜索框）整列标为 `DragWindow`。上边距从写死的 40 改为 `TitleBar().Bottom + 6`（至少 10；全屏时红绿灯隐藏，`Bottom` 为 0）。搜索框和“添加工作区”按钮是可交互元素，按下时归它们自己，不拖窗口（MyGO 只在最先命中的可交互元素就是拖动区域时才拖）。
- 会话区：浮动标题栏本身标为 `DragWindow`；标题栏上方 12pt 的空隙也可拖。独立会话窗口里，标题栏左侧到红绿灯的那一角也可拖，标题栏左边距从写死的 84 改为 `max(16, TitleBar().Left + 12)`。标题栏两侧的其余部分没有标成拖动区域：那里下面是消息列表，盖上拖动区域会挡住滚轮。
- 空白页：整条顶部（`max(TitleBar().Height, 58)` 高）可拖，下面没有可滚动的内容。
- 设置弹窗：弹窗盖住了侧栏和标题栏，所以把弹窗自己的标题行（“设置”）标为可拖。
- 双击：MyGO 的 `DragWindow` 在 macOS 上读 `AppleActionOnDoubleClick`（缩放、最小化或不处理），不需要另开任务。
- 消息列表的 `DragSelect` 不受影响：消息列表区域没有标成拖动区域。
- 测试：`TestTitleBarBand` 设一个模拟的红绿灯区域（`Tester.SetTitleBar`），检查侧栏标题在红绿灯下方、独立窗口的标题栏在红绿灯右侧，标题栏和侧栏头部里的按钮、搜索框照常可用。

## 真机验证

- 2026-11-22 用户在真机上验证：主窗口和独立会话窗口都能拖动，设置弹窗标题行可拖，双击行为正常，侧栏顶部和独立窗口标题栏的位置没有错位。

## 没有验证

- Tester 看不到窗口拖动和标题栏双击（MyGO 只在私有字段里记下），所以界面测试没有直接断言“带有拖动标记”。
