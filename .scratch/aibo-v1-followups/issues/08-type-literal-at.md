# 08: 输入框里打不出“@”

**What to build:** 用户能在输入框里正常打出“@”（例如写邮箱、装饰器、`@types/node`），同时 `@` 仍然能打开引用面板。

现状：`internal/shell/pull.go` 的 `typedAt` 只要发现新插入的文字以“@”结尾，就把它从草稿里删掉、打开 @ 面板。所以打出来的“@”总被吞掉，只能从别处粘贴。

建议的行为（和常见编辑器一致）：
- 只有在行首或空白之后打出“@”才打开面板；紧跟在字母、数字后面（`a@b`）就当普通字符。
- 打开面板时“@”留在草稿里。在面板里选中一项，就用引用标记替换这个“@”；按 Esc 或点面板外关掉，“@”原样留下。
- 粘贴的文字里带“@”，不打开面板（现在粘贴一段以“@”结尾的文字也会触发）。

**Blocked by:** None (can start immediately)。07（文件引用）会改同一个面板，先做这个

**Status:** resolved

- [x] `typedAt` 的规则改成上面这样，有单元测试：行首、空格后、字母后、粘贴、输入法提交
- [x] 关掉面板时“@”留在草稿里；选中引用时替换这个“@”
- [x] 输入框底部的 `@` 按钮照旧直接打开面板，不往草稿里插字
- [x] 界面测试：打 `a@b` 草稿就是 `a@b`；打空格加 `@` 打开面板，Esc 后草稿里留着 `@`

## 实现说明

- `typedAt(before, after)` 改为返回“@”在草稿里的字节位置：新插入的文字以“@”结尾，且“@”前面是行首或空白（`unicode.IsSpace`，含全角空格）才打开面板。不再从草稿里删掉“@”。
- 粘贴：输入框挂了 `OnPaste`，只记一个 `sessionView.pasted` 标记、不接管粘贴；下一帧看到这次改动时跳过，然后清掉标记。
- 面板记住打开它的“@”在哪（`pull.at`、`pull.in`）。插入引用成功后，用 `dropAt` 去掉草稿里的这个“@”；如果那个位置已经不是“@”（用户改过草稿），草稿保持原样。点 `@` 按钮打开时 `at = -1`，不动草稿。
- 测试：`pull_internal_test.go` 覆盖 `typedAt`（行首、空格后、字母后、数字后、汉字后、输入法提交、全角“＠”、删除）和 `dropAt`；`TestTypeLiteralAt` 在界面里依次测 `a@b`、空格加 `@`、Esc 后“@”留在草稿里、粘贴带“@”的文字、输入法组字时不打开、提交后打开，最后检查 Agent 收到的正文。原来的 `TestPullReferenceWithAt` 不改断言也能通过，选中引用后“@”被替换掉了。

## 没有验证

- 没在真机上用系统输入法试过，只用 Tester 的 `Compose`/`Type` 模拟了组字和提交。
- 紧跟在汉字后面打“@”（例如“按这个写@”）按规则算普通字符，不打开面板。中文里不习惯打空格，这一点可能需要用户再定。
- 全角“＠”一律当普通字符。
