# 07: 在消息里引用工作区内的文件

**What to build:** 写消息时，用户能把工作区里的文件或目录指给 Agent：输入 `@` 后接着打字，面板里按路径模糊匹配文件，选中后在输入框里插入一个文件标记；发送后 Agent 拿到的是路径，自己去读。

现状：输入 `@` 或点 `@` 按钮打开的是会话引用面板（`internal/shell/pull.go`），只能引用其他会话。附件按钮灰显，暂不支持。

**Blocked by:** 08（输入框里打不出“@”），两者改同一个面板

**Status:** resolved

已定的设计（用户决定，2026-11-21）：
1. **发给 Agent 的只有路径**：工作区内的相对路径，Agent 自己读，不做内容快照。这和会话引用“创建时固定的快照”（ADR 0002）不同，所以要起一个新术语，避免和“会话引用”混淆（暂称“文件提及”，写进 `GLOSSARY.md`）。
2. **`@` 同时打开两种引用**：同一个面板，上面是文件匹配，下面是“引用会话…”。打字时两边一起过滤。
3. **范围**：默认遵守 `.gitignore`；设置里有一个开关，可以改成列出被忽略的文件。
4. **源工作区**：会话可读的源工作区（跨工作区引用后得到的只读权限）里的文件也列出来，标明属于哪个工作区。工作区外的文件不能用相对路径，给 Agent 的是绝对路径；具体写法在实现时定，写进实现说明。

需要实测的协议问题（结论附抓取数据，回填规格）：

- Codex app-server 的 `turn/start` 输入有没有表示文件的条目类型（例如 mention），还是只能写进文字？
- 两家都只认文字时，统一写成路径加一句说明即可。

## 实现说明

- 实测：[07 实测](../research/07-file-mentions.md)。Claude Code 认输入里的 `@路径`，自己读文件；Codex 的 `mention` 条目不会把文件交给模型，只能拿路径自己读。取舍写在 `docs/adr/0004-file-mentions-are-paths.md`；`GLOSSARY.md` 加了“文件提及”；规格加了第 71 条用户故事、适配器的轮次输入、输入框、待验证项 9。
- 源工作区的写法（任务里留给实现时定的）：给 Agent 绝对路径。本工作区给相对路径。界面上源工作区的文件显示为“工作区名/相对路径”，面板里另标“（源工作区）”。
- 新包 `internal/files`（不依赖别的内部包，已加进依赖方向测试，工作台可以引用）：
  - `List`：在 git 仓库里用 `git ls-files --cached --others --exclude-standard`，所以遵守 `.gitignore`；不在仓库里，或要求列出全部时，遍历目录（跳过 `.git`）。目录也列出来，以 `/` 结尾；最多二十万项。
  - `Match`：按顺序包含查询的字母即算匹配，文件名正好、开头、包含查询的排前面，再按路径长短；十万个路径匹配一次约 9 毫秒（`BenchmarkMatch`）。
- 存储与模型：`model.Mention`（绝对路径、所在工作区、是否目录），存在消息的 `detail` JSON 里，不需要迁移。`agent.Turn.Files` 是交给 Agent 的形式（绝对路径和相对路径）。
- 工作台：
  - `MatchFiles` 列出会话工作区和可读的源工作区（本工作区的排前面），每个文件夹的列表缓存 30 秒，用单独的锁，不占工作台的锁。
  - `SendWithFiles` 检查每个提及都在这两类文件夹里，否则返回 `ErrNotReadable`；只有提及、没有文字也能发。`Send` 和 `SendWithFiles` 一起拆在 `turns.go`。
  - 设置 `MentionIgnored`，界面上是“文件引用时包括被 .gitignore 忽略的文件”，默认关。
- 适配器：
  - Claude 在文字后面写“提到的文件：”，每个提及一行 `@路径`，带空格加引号。最初写在全角冒号后面时 Claude 没有读到文件（契约测试发现），改成每个一行后读到了。
  - Codex 写“提到的文件（需要时请自己读取）：”加路径列表，目录标“（目录）”。
- 界面（新文件 `internal/shell/mention.go`）：
  - `@` 面板改名“引用文件或会话”，搜索框的 Label 改成“搜索文件或会话”（原来和侧栏的“搜索会话”重名）。同一个搜索框过滤上面的“文件”（最多 8 个，在后台匹配，旧的结果晚到会被丢掉）和下面的“会话”。
  - 选中文件后关掉面板，用一个文件徽标替换打开面板的那个“@”。徽标显示在输入框上方，和会话引用的徽标在一起，可以整体删除，悬停看完整路径。
  - 发出的消息在用户消息上方显示同样的徽标（不能删）。
  - 输入框底部的 `@` 按钮的 Label 改成“引用文件或会话（@）”。
- 测试：
  - `files`：遵守 `.gitignore`、列出全部、不在仓库里、模糊匹配的顺序。
  - 工作台 `TestFileMentions`：本工作区和源工作区的匹配（源工作区在收到引用后才列出）、目录、发给假 Agent 的形式、消息里存下的提及、只有提及也能发、工作区以外的文件被拒。
  - 适配器 `TestTurnWithFiles`（两家）。契约测试 `TestContractFileMention`（两家），2026-11-22 通过：Claude 不用工具就答出了带空格文件名里的暗号；Codex 自己读文件后答对。
  - 界面 `TestMentionFile`：打 `@` 加几个字、同一面板里文件和会话都在、选中文件、输入框里是徽标、“@”没有留在文字里、发送后假 Agent 收到相对路径、消息里显示文件。

## 没有验证

- 没在真机上用过；没在十万个文件的真实仓库里试过打字（只有匹配的基准测试，列出文件的耗时没测）。
- 没有 git 时（或 macOS 没装命令行工具时，`/usr/bin/git` 会弹出安装提示）退回遍历目录，此时不遵守 `.gitignore`。
- 文件改名或删除后，历史消息里的提及仍显示原路径。
- 附件按钮仍灰显，图片等附件不在这个任务里。
