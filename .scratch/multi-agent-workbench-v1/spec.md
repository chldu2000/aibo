# aibo v1 规格：多 Agent 工作台

Status: ready-for-agent

来源：[多 Agent 工作台 v1 路线图](map.md)（全部 18 个任务已解决）。下文所有术语都以 `GLOSSARY.md` 为准，例如会话、消息、轮次、会话引用、引用范围、引用概要、工作区、源工作区、Agent 上下文、上下文压缩、上下文重置、原生会话、审批请求、审批档位、归档。

## Problem Statement

我同时使用多个编码 Agent（Claude Code、Codex CLI），它们各有所长。常见的情况是：在一个 Agent 里讨论出了方案，想交给另一个 Agent 去实现；或者一个 Agent 的思路走偏了，想让另一个 Agent 接着做。

现在只能手动复制粘贴对话。粘贴整段对话会撑爆对方的上下文；自己写摘要又会丢失细节，而且费时间。各家的桌面客户端都只管自家的 Agent，没有一个地方能同时托管不同的 Agent，并在它们之间传递会话。

## Solution

aibo 是一个 macOS 原生的桌面工作台，用 Go 加 MyGO 原生 UI 构建，采用 Liquid Glass 风格。它托管用户本机安装的 Claude Code 和 Codex CLI，用工作台自己的界面渲染会话。

核心能力是**会话引用**：把一个会话中的一段连续消息（引用范围），以“句柄加引用概要”的形式交给另一个会话。

- 接收方 Agent 不会收到整段对话的副本，而是在需要时，通过 aibo 提供的 MCP 工具读取被引用的内容。
- 引用是创建时的快照，可以跨 Agent，也可以跨工作区，还可以引用给会话自己（用来找回被压缩掉的内容）。

aibo 保存的会话记录，是“发生过什么”的完整、只追加的记录，与 Agent 自己的上下文相互独立。

## User Stories

### 工作区与会话

1. 作为用户，我想通过选择文件夹或把文件夹拖进窗口来添加工作区，这样就能在这个项目里启动 Agent。
2. 作为用户，我想在侧栏里看到按工作区分组、按最后活跃时间排序的会话列表，这样能快速找到最近在做的事。
3. 作为用户，我想在每个会话条目上看到 Agent 图标、标题和状态标记（运行中、待审批、未连接、出错、收到的引用数），这样不用逐个打开也能知道每个会话的情况。
4. 作为用户，我想在工作区分组上点“＋”，选好 Agent 和模型后新建会话，这样能马上开始工作。
5. 作为用户，我想在新建会话时看到不可用的 Agent 显示为灰色，并注明原因，这样知道该怎么修。
6. 作为用户，我想给会话重命名，这样标题能反映它的真实内容。
7. 作为用户，我想让会话标题默认取自第一条用户消息的开头，这样不用每次都手动起名。
8. 作为用户，我想把会话归档，让它从分组里隐藏，但仍然可以被引用、被搜索，这样侧栏保持整洁，资料也不会丢。
9. 作为用户，我想取消归档，把会话放回原来的分组。
10. 作为用户，我想按标题和消息正文搜索会话，这样能找到很久以前的讨论。
11. 作为用户，我想删除会话；删除前要提示我“该会话被 N 个引用使用，删除后这些引用将失效”，这样不会误删别人还在用的内容。
12. 作为用户，我想在移除工作区时，它下面的会话自动转为归档、数据保留，这样整理侧栏不会顺带删掉数据。
13. 作为用户，我想在工作区目录被移走或删除时看到“目录不存在”，会话仍可浏览和被引用，并且能“重新定位”到新的路径，这样挪动项目目录后不会失去历史。

### 与 Agent 对话

14. 作为用户，我想在 aibo 里给 Claude Code 或 Codex 发消息，并实时看到流式输出的 Markdown 回复（包括代码高亮、表格和 diff），这样不用切回终端。
15. 作为用户，我想看到 Agent 的工具调用：调用和结果合成一条消息，默认折叠，可以展开；超大的输出在只读编辑器里显示，这样会话既清晰又不卡顿。
16. 作为用户，我想看到 Agent 的思考内容附在对应的回复上，这样能理解它的推理过程。
17. 作为用户，我想看到 Agent 的计划（Codex 的 plan、Claude 的 TodoWrite）作为一条单独的消息显示。
18. 作为用户，我想看到子代理的工作折叠在父工具调用里面，这样主时间线不会被淹没。
19. 作为用户，我想随时停止正在输出的回复，停止后这条回复以“已中断”保存，这样方向不对时能及时纠正。
20. 作为用户，我想在输入框上方看到染色 glass 徽标，显示终端进程数、运行中的子 Agent 数、待审批数和收到的引用数，这样一眼就知道会话的运行状态。
21. 作为用户，我想通过快捷指令胶囊一键执行常用操作（压缩上下文、引用会话），这样少点几下。
22. 作为用户，我想在会话菜单里手动压缩上下文，这样能主动控制 Agent 的上下文长度。
23. 作为用户，我想在压缩发生的位置看到一条分隔线（“上下文已压缩 · 自动 · 19.7k → 6.3k tokens”），线上方的消息照常显示，这样我知道 Agent 已经不记得那些细节了。
24. 作为用户，我想在输入 `/clear` 这类 Agent 自带的斜杠命令时看到“暂不支持”，而不是让它悄悄执行，这样 aibo 的记录不会和 Agent 的状态对不上。
25. 作为用户，我想在一个包含上万条消息的长会话里依然流畅滚动，并且新消息到来时自动跟随到底部。
26. 作为用户，我想按整条消息选中一段内容并复制，这样能把讨论贴到别处。

### 会话引用

27. 作为用户，我想在源会话里进入选择模式，点击设起点、Shift+点击扩展、或“选中整轮”“选中整个会话”来选定引用范围，这样能精确地交出想要的那段讨论。
28. 作为用户，我想在选区不连续时看到它被补齐成连续范围，并提示“已补齐中间的消息”，以及规整后的“#a–#b · n 条”，这样不会意外交出过多内容。
29. 作为用户，我想在发出引用前预览引用概要，这样知道接收方会看到什么。
30. 作为用户，我想把引用发到一个新会话（选择 Agent 和工作区）或一个已有会话（包括当前会话本身），这样可以灵活地分派工作。
31. 作为用户，我想在接收方的输入框里输入 `@`，搜索源会话，在时间线上选起点和终点，同时实时预览概要，然后插入引用，这样能从接收方主动拉取上下文。
32. 作为用户，我想让引用以草稿卡片的形式放进输入框，发送前可以移除，并且可以和我自己写的话一起发出，这样能顺带补充说明。
33. 作为用户，我想在接收方的会话记录里，把引用显示为卡片：一行写明 Agent、标题、范围和条数，展开后看到 Agent 实际收到的完整文本，这样做到完全透明。
34. 作为用户，我想看到接收方 Agent 读取引用的记录（“读取了 #a–#b”），并能一键跳回源会话、高亮被引用的范围，这样能核对它看到了什么。
35. 作为用户，我想让引用固定为创建时的快照，源会话后来的内容和改名都不影响已发出的引用，这样结果可以复现。
36. 作为用户，我想在跨工作区引用时看到提示，并让接收方能只读访问源工作区的文件，这样它能打开讨论里提到的文件，但不会误改别的项目。
37. 作为用户，我想把压缩之前的一段内容引用回同一个会话，这样 Agent 能找回被压缩掉的细节。
38. 作为用户，我想在一个会话里先后收到多个引用，它们互相独立，这样能汇集多方面的上下文。
39. 作为接收方 Agent，我想通过 `list_references` 看到交给我的所有引用及其概要，这样知道手上有哪些上下文。
40. 作为接收方 Agent，我想通过 `read_reference` 分页、按顺序读取引用范围内的消息，这样不会一次撑爆上下文。
41. 作为接收方 Agent，我想通过 `read_message` 读取单条消息的完整内容（比如在分页里被截断的工具输出），这样能看到需要的细节。
42. 作为接收方 Agent，我想通过 `search_reference` 用关键词或正则查找引用里的内容，这样能快速定位。
43. 作为接收方 Agent，我想在读取结果的开头看到源工作区的绝对路径，以及“文件可能已在引用之后被修改”的提醒，这样不会搞错路径，也不会误以为文件还是当时的样子。
44. 作为接收方 Agent，我想在读取越界或读取已删除的引用时得到清楚的错误信息（写明有效范围，或说明源会话已被删除），这样能正确地应对。

### 审批

45. 作为用户，我想在 Agent 请求执行命令、修改文件或调用 MCP 工具时，在对应的工具调用下面看到审批卡片，卡片上有命令全文、diff 或工具参数，这样能在知情的前提下决定。
46. 作为用户，我想看到写入源工作区以外路径的醒目标注“写入其他工作区”，这样能识别越界操作。
47. 作为用户，我想有这些选项：批准本次、本会话内始终允许、永久允许（只在 Agent 提供时出现，并写明写入位置、需要二次确认）、拒绝（可附说明）、拒绝并停止这一轮，这样能按需控制。
48. 作为用户，我想让“本会话内始终允许”在 Agent 进程重启或续接后依然有效，并能在会话菜单里查看和撤销，这样授权的范围符合直觉。
49. 作为用户，我想为每个会话选择审批档位：每次询问、自动接受工作区内修改、全部自动（需要二次确认，并持续显示警示），这样能在安全和效率之间权衡。
50. 作为用户，我想在后台会话出现待审批请求时看到侧栏标记和系统通知，点击通知直接跳到审批卡片，这样不会让 Agent 一直干等。
51. 作为用户，我想让待审批的请求一直等我处理、不会超时，并且不会因为闲置而被断开，这样回来后可以接着做。

### Agent 的发现、登录与续接

52. 作为用户，我想让 aibo 自动找到我安装的 `claude` 和 `codex`（即使从 Dock 启动，也能找到 shell PATH 里的那些），这样不用手动配置。
53. 作为用户，我想在设置里手动指定可执行文件，并能“重新检测”，这样能处理不常见的安装方式。
54. 作为用户，我想在 Agent 版本过低时看到“请升级到 X 或更高版本”，这样知道问题出在哪里。
55. 作为用户，我想在 Agent 未安装时看到官方安装说明的链接，aibo 不替我执行安装命令。
56. 作为用户，我想在 Claude 未登录时，能一键在终端里打开 `claude` 自己完成登录，再回来点“重新检测”，这样登录过程不经过 aibo。
57. 作为用户，我想在 Codex 未登录时，直接在 aibo 里用 ChatGPT（系统浏览器）或设备码登录，这样更方便。
58. 作为用户，我想在登录失效时看到登录横幅：Claude 那条回复标为“出错：未登录”，登录后可以重试；Codex 的消息不会发出，输入的内容保留。
59. 作为用户，我想在重新打开 aibo 后，直接在旧会话里继续对话，由 aibo 在我发出第一条消息时续接对应的原生会话。
60. 作为用户，我想在原生会话丢失或不兼容、续接失败时，看到 Agent 返回的错误原文，并能选择：新开原生会话并引用之前的内容（推荐）、新开原生会话但不带引用、或暂不处理（只读），这样会话不会就此作废。
61. 作为用户，我想在新开原生会话后，同一个 aibo 会话里出现一条“已切换到新的 Agent 原生会话”的分隔线，这样会话的历史保持连贯。
62. 作为用户，我想在退出 aibo 时，如果有会话正在运行，先看到提示，这样不会意外中断工作。

### 外壳与设置

63. 作为用户，我想要一个三栏布局：左侧是浮动的 Liquid Glass 侧栏，中间是会话区，会话详情需要时以 glass 面板浮出，这样 aibo 看起来像 macOS 原生应用。
64. 作为用户，我想在会话详情里看到 Agent、模型、工作区、原生会话、审批档位、始终允许的规则、可读的源工作区，以及会话操作，这样会话相关的控制都集中在一处。
65. 作为用户，我想用侧栏底部的齿轮或快捷键 ⌘, 打开全局设置弹窗（通用、Agent、高级三页），这样能调整全局配置。
66. 作为用户，我想把数据目录改到自己方便找的位置；改的时候 aibo 会迁移数据，并对 iCloud Drive、Dropbox 这类同步盘给出警告，这样能管理磁盘空间。
67. 作为用户，我想在自定义的数据目录不可用时，看到“重试 / 重新选择位置 / 退出”三个选项，而不是被悄悄换成一个空库，这样数据不会看起来像丢了。
68. 作为用户，我想让界面的文字和图标跟随系统的浅色、深色模式，这样任何时候都清晰可读。
69. 作为用户，我想把一个会话拆到独立窗口里（低优先级），这样能同时盯着两个会话。
70. 作为用户，我想让 aibo 同一时间只运行一个实例，再次启动时直接激活已打开的窗口，这样数据不会冲突。

## Implementation Decisions

### 总体架构

- 工作台本体用 Go 编写，UI 用 MyGO 原生 `ui`，glass 用插件的着色器 glass，在合适的位置使用系统 Liquid Glass；不用 WebView。
- v1 只支持 macOS，最低支持 macOS 26（Liquid Glass）。
- 构建时使用 `CGO_ENABLED=0`。MyGO 是纯 Go 实现；在实测机器上，Command Line Tools 的链接器解析不了 macOS 27 SDK。
- 核心按下面几个深模块划分，界面只调用工作台核心对外的操作：
  1. **Agent 适配器**：每家 Agent 一个实现，对外是统一的接口。这也是测试的主接缝。
  2. **Agent 发现**：负责可执行文件、版本、登录状态和登录流程。
  3. **会话存储**：SQLite 加附件目录。
  4. **会话运行时**：负责进程生命周期、发送、续接与兜底、闲置断开、审批的路由与记忆。
  5. **引用服务**：负责创建引用、生成概要，以及引用的读取、分页和搜索。
  6. **工作台 MCP server**：把引用服务以 MCP 工具的形式提供给接收方 Agent。
  7. **工作台外壳 UI**。

### Agent 适配器

- 统一接口提供以下操作：
  - 启动或续接一个原生会话。参数包括工作区、模型、MCP 配置（URL 和 token）、额外可读目录、审批档位、本会话的放行规则。
  - 发送一个轮次的用户输入。
  - 中断。
  - 压缩上下文。
  - 回复审批请求。
  - 关闭。
  - 探测能力。
- 适配器输出统一的事件流。事件分类参照 ACP：消息增量、思考、工具调用开始和结束（带结果）、计划、审批请求、压缩、轮次结束、错误、未登录、原生会话 ID 变化。
- **Claude**：
  - 每个会话一个常驻的 `claude -p --input-format stream-json --output-format stream-json --verbose` 进程，以 NDJSON 交互，不需要 Node。
  - 用 `--resume`、`--session-id` 续接；用 `--mcp-config` 加 `--strict-mcp-config` 注入工作台的 MCP server，token 通过 `${VAR}` 从环境变量传入。
  - 审批走 **control 协议**：`--permission-prompt-tool stdio`，先在 stdin 上发 `initialize`，之后接收 `can_use_tool` 请求。请求里的 `permission_suggestions` 就是原生的权限建议。这个协议没有公开文档，实现时以官方 Python SDK 的源码为准。
  - aibo 自己的四个工具通过 `--allowedTools 'mcp__aibo__*'` 免审批。
  - 跨工作区时，用 `--add-dir <源工作区>` 授予读取权限；`--add-dir` 接收多个参数，命令行里要放在提示词之后。
  - 不使用 `--bare`。
- **Codex**：
  - 一个 `codex app-server` 进程（stdio JSONL）承载多个 thread，用 `thread/start`、`thread/resume` 管理会话。
  - MCP 通过 `config.mcp_servers.aibo` 按 thread 注入（已实测，每个 thread 的配置相互隔离）。token 用按 thread 设置的 `http_headers` 传，不用 `bearer_token_env_var`。
  - 在 aibo server 的配置里写 `default_tools_approval_mode = "approve"`，让 aibo 的工具免审批。
  - 审批来自 app-server 推送的命令、文件修改、权限审批，以及 MCP elicitation。
  - Go 类型由 `generate-json-schema` 生成。
- 工作台**只调用用户本机安装、未经修改的 `claude`**，不读取、不转交 `~/.claude` 里的凭据。

### Agent 发现

- **查找可执行文件**，按以下顺序：
  1. 用户指定的路径；
  2. 固定位置：`~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin`、npm 全局目录；
  3. 执行 `$SHELL -lic`，超时 3 秒，输出前后加标记以便解析。

  找到的路径和 shell PATH 缓存下来。启动 Agent 进程时传入这份 PATH，因为 npm 安装的 Codex 需要 node。
- **最低版本**：Claude Code 2.1.318，codex-cli 0.169.0。版本号用 `--version` 读取。低于最低版本时，该 Agent 不可用。版本更高时照常使用；遇到不认识的字段或方法时，显示具体错误。
- **登录状态**：
  - Claude：用 `claude auth status`（输出 JSON，退出码 0 表示已登录、1 表示未登录）检查，在启动时，以及某个轮次返回 `authentication_failed` 时检查。
  - Codex：启动时调用 `account/read`，之后订阅 `account/updated`，遇到 401 时重新检查。不做每轮检查，代价是极少数情况下用户要多等约 18 秒。
- **登录引导**：
  - Claude 只能在终端里完成登录。aibo 提供复制命令，以及用 `open -a Terminal` 打开 `claude`。
  - Codex 在应用内调用 `account/login/start`，支持 `chatgpt`（系统浏览器）和 `chatgptDeviceCode` 两种方式；API Key 用户引导到终端操作。
- **未安装**：只提供官方安装说明的链接和“手动指定路径”，不替用户执行安装。

### 会话模型与存储

- **会话**：只追加、不修改。
  - **元数据**：标题（手动设置的优先；Agent 生成的标题实测两家都不提供，保留这一档；否则取第一条用户消息的开头）、Agent 类型、工作区、模型、创建时间和最后活跃时间、审批档位、本会话放行规则、额外可读目录、原生会话 ID 历史。同一时刻只对应一个原生会话，历史上可以有多个。
- **消息**：
  - 会话内用单调递增、永不复用的**序号**编址。
  - 类型有四种：用户消息、Agent 回复、工具调用（调用和结果合为一条）、计划。
  - 思考内容附属在回复上；子代理的消息嵌套在父工具调用里；审批结果作为工具调用的属性记录；中断或出错的消息算已结束，标记为“已中断”。
  - 每条消息另外保存原始事件 JSON，供内部使用。
  - 单条工具输出最大约 1 MB，超出的部分截断并标记。
  - 附件存为文件。
  - 用户消息只保存原文和引用列表，不保存拼接了引用块之后的文本。
- **标记**：压缩标记和上下文重置标记挂在“第 N 条消息之后”。它们不算消息，不占序号，也不能被引用。
- **引用**：字段包括全局唯一的短随机 ID（例如 `ref_7Kq2xP`）、源会话、起始序号和结束序号、接收方会话、概要文本（创建时生成并固定）、状态（草稿或已交付）、创建时间。只有已结束的消息才能被引用。
- **存储**：
  - 一个全局的 SQLite 数据库，使用纯 Go 驱动 `modernc.org/sqlite`，加一个附件目录。默认放在 `~/Library/Application Support/aibo/`；“数据目录在哪里”这项设置固定存放在默认位置的一个小配置文件里。
  - 项目目录里不写任何文件。
  - 更改数据目录前，必须先关闭所有会话。新目录为空时，复制数据并校验，再删除旧数据；新目录里已有 aibo 数据时，可以直接使用；新目录在同步盘上时给出警告。
  - 数据目录不可用时，提供“重试 / 重新选择 / 退出”，绝不新建空库。
  - 数据库结构有版本号。升级前先备份数据库文件。
  - 对数据目录加文件锁，保证只有一个实例运行。
- **删除**：
  - 删除源会话会彻底删除它，指向它的引用随之失效，读取工具返回“引用的源会话已被删除”。
  - 删除接收方会话时，交给它的引用记录一并删除。
  - 移除工作区时，它下面的会话转为归档。

### 会话运行时

- **启动**：aibo 启动时不启动任何 Agent 进程。用户在某个会话里发出第一条消息时，才续接对应的原生会话。
- **闲置断开**：会话闲置 30 分钟后断开（Claude 结束进程，Codex 卸载 thread）。有待审批请求的会话不会被断开。
- **续接**：每次续接都重新生成 MCP token，注入新的端口和 token，旧 token 立即作废。同时重新带上额外可读目录和本会话的放行规则。
- **跨工作区引用**：会话中途收到跨工作区的引用时，Claude 需要先用 `--resume` 加 `--add-dir` 重启进程，再发送消息。授权在会话的整个生命周期内有效。
  - 源工作区只读：Codex 不把源工作区加入可写目录；Claude 增加一条按路径禁止 Edit/Write 的权限规则（**待验证**）。如果做不到，就在审批卡片上醒目标注“写入其他工作区”。
- **续接失败**：Claude 的 `--resume` 报错或进程退出、Codex 的 `thread/resume` 返回错误，都判定为原生会话不可用，不预先检查 Agent 的本地存储。会话顶部显示横幅，附上错误原文，提供三个选项：
  1. 新开原生会话并带上自引用草稿（范围是重置之前的全部消息）；
  2. 新开原生会话，不带引用；
  3. 暂不处理，会话只读。

  选择新开原生会话时，记录一个上下文重置标记。
- **退出**：正在进行的轮次以“已中断”保存，未处理的审批视为拒绝。有会话在运行时，先提示用户。
- **斜杠命令**：输入以 `/` 开头的 Agent 斜杠命令时，不转发，提示“暂不支持”。压缩只能通过菜单或快捷指令触发（Claude 发送 `/compact`，Codex 调用 `thread/compact/start`）。
- **压缩事件**：Claude 的 `system/compact_boundary` 带有 `trigger`、`pre_tokens`、`post_tokens`；Codex 的 `contextCompaction` 条目只有时间戳。两者都转换成压缩标记。

### 引用服务与引用概要

- **发送时注入**：每个引用渲染成一个 `<aibo-reference>` 块，按顺序放在用户正文之前，一起作为本轮输入。
- **概要格式**：以下样例来自“引用概要的生成规则”的讨论。

```
<aibo-reference id="ref_7Kq2xP">
用户交给你一段来自另一个会话的引用（只读快照）。当用户的请求依赖其中的内容时，
请先调用 <接收方看到的 read_reference 工具名> 读取，不要凭概要猜测细节。
- 来源：「数据库迁移方案讨论」· Claude Code
- 源工作区：/Users/…/shop-api（不是你当前的工作区；其中的相对路径都相对于它，你只能读取不能修改）
- 范围：#7–#10，共 4 条消息（2026-11-18 14:02–14:09）
- 首条用户消息：#7「……」
- 末条 Agent 回复：#10「……」
- 可用工具：read_reference(ref_id="ref_7Kq2xP")、read_message、search_reference、list_references
</aibo-reference>
```

- **概要规则**：
  - 源工作区这一行只在跨工作区时出现。
  - 摘录取范围内的第一条用户消息和最后一条 Agent 回复，各截取 200 字以内；被中断的标注“（已中断）”；缺少其中一种时，改取首尾两条消息。
  - 工具名按接收方 Agent 实际看到的写法：Claude 是 `mcp__aibo__read_reference`；Codex 的写法**待实测**。
  - 读不读由 Agent 自己判断。
  - 自引用时，首句改为“这是本会话较早的一段内容，你的上下文中可能已不再保留其细节”，并省略来源和源工作区两行。
  - 固定文字使用界面语言（v1 是中文），摘录保留原文。
  - 每个块不超过 1500 字，超出时先缩短摘录。
- **选区规整**：不连续的选区规整为“最小序号到最大序号”的连续范围，并向用户展示规整结果。

### 工作台 MCP server

- 用官方的 `modelcontextprotocol/go-sdk` 实现 streamable HTTP，跑在工作台进程内，监听 `127.0.0.1` 的随机端口。
  - 校验 `Origin`。
  - 每个会话分配一个 bearer token，映射到对应会话。
  - `getServer` 为每个会话返回只绑定该会话的 server。
- **四个只读工具**：
  - `list_references()`
  - `read_reference(ref_id, from_seq?, cursor?, include_thinking=false)`
  - `read_message(ref_id, seq, include_thinking=false)`
  - `search_reference(query, ref_id?, regex=false, include_thinking=false, cursor?)`
- **边界**：
  - 只能读取交给当前会话的引用，其他引用 ID 一律拒绝。
  - 只能读取引用范围内的消息；越界时报错，并写明有效范围。
  - 源会话已被删除时，返回明确的错误。
- **输出**：
  - 给大模型读的文本，不返回 JSON。每条消息以 `### [序号] 角色 · 时间` 开头。
  - 工具调用写成“工具名、参数摘要、结果”；中断的消息标注“（已中断）”；附件写成 `[图片: 文件名]`；不包含压缩标记。
  - 开头附两行：源工作区（跨工作区时）和“文件可能已修改”的提醒。
- **分页**：
  - `read_reference` 每页约 8k token，页内单条工具输出最多保留约 2k token，页尾写明剩余条数和 cursor。
  - `read_message` 每页约 25k token。
  - 这些数值在“高级”设置里可以调整。
- **搜索**：
  - 逐条扫描引用范围内的消息，不建全文索引。
  - 默认按关键词匹配，不区分大小写，多个词必须同时出现；`regex=true` 时按正则匹配。
  - 覆盖正文、工具参数、完整的工具输出和附件文件名；思考内容只有在 `include_thinking=true` 时才搜。
  - 每页最多 20 个命中，每个命中带约 200 字的片段。

### 审批

- **审批档位映射**。来自“审批请求的通道与交互”；两家 Agent 的语义只能近似一致。

| 档位 | Claude | Codex |
|---|---|---|
| 每次询问（默认） | `default` | `approvalPolicy: on-request` + `sandbox: workspace-write` |
| 自动接受工作区内修改 | `acceptEdits` | 同上（Codex 在工作区内写入本来就不需要审批） |
| 全部自动（二次确认 + 持续警示） | `bypassPermissions` | `never` + `danger-full-access` |

- **选项以 Agent 原生的为准**：
  - **批准本次**：Codex 回 `accept`；Claude 回 allow。
  - **本会话内始终允许**：Codex 回 `acceptForSession`；Claude 采纳 `permission_suggestions`，但把 destination 改成 `session`。aibo 另外记下这条规则：Codex 下由 aibo 自动回复同类请求；Claude 下在下次启动时通过 `--allowedTools` 带上。规则可以在会话详情里查看和撤销。
  - **永久允许**：只在 Agent 提供永久选项时显示，即 Codex 的 execpolicy 或网络规则，以及 Claude 的 `localSettings` 建议。按钮上写明写入位置，并要二次确认。
  - **拒绝**：可以附一句说明。Codex 的 decline 不支持附带说明，所以说明会随下一条消息发出。
  - **拒绝并停止**：Codex 回 `cancel`；Claude 回带 `interrupt` 的拒绝。
- **审批卡片**挂在对应的工具调用下面。命令显示全文、工作目录和理由；文件修改用 `editor.DiffView` 显示 diff；MCP 工具显示参数。同一轮里的多个审批按出现顺序排列。
- **提醒**：审批不设超时。后台会话出现待审批请求时，侧栏显示标记并发送 macOS 系统通知（可以在设置里关闭）。

### 工作台外壳 UI

- **窗口**：`Transparent`，使用 `VibrancySidebar`，标题栏为 `TitleBarHiddenInset`。
- **左侧浮动侧栏**：
  - 系统 Liquid Glass（`glass.Glass{Native: true}`），圆角，四周留 8 的边距。实现时要在外层加 padding，不能对 `Fill()` 的元素用 margin。
  - 按工作区分组，显示状态标记，最下方是“已归档”。
  - 侧栏底部是设置按钮（⌘,）和搜索按钮。
- **中间会话区**：
  - 不透明的面板，左侧和侧栏之间留缝。
  - 顶部是浮动的 glass 标题栏：Agent 图标、标题、工作区，以及“在新窗口打开”和“会话详情”两个图标按钮。
  - 消息列表在标题栏下方滚动，顶部用 `ScrollEdge` 渐隐。
- **会话列表**：用 `ui.List`，每条消息占一行，`Key` 是序号，开启 `FollowEnd` 和 `Smooth`。
  - 流式输出时用 `markdown.Stream` 渲染，完成后改用 `markdown.View`。
  - 工具调用放在 `Collapsible` 里。输出超过 4 KB 时，用只读的 `editor.View` 显示。
  - 选择基于 `ListState.Selection`，并开启 `DragSelect`。默认的选中样式要自定义。
- **会话详情**：一块浮出的 glass 面板，内容包括 Agent 和模型、工作区、原生会话、审批档位、始终允许规则（可以撤销）、可读的源工作区，以及压缩、重命名、归档、删除操作。
- **设置**：全局弹窗，面板用 glass，分三页：
  - 通用：数据目录、新会话默认审批档位、待审批系统通知；
  - Agent：路径、版本、登录状态、认证方式、“选择其他可执行文件”、“重新检测”；
  - 高级：两个分页预算、单条工具输出保留长度、闲置断开时长。
- **输入框**：
  - 一张 glass 卡片，里面是多行输入，引用草稿以胶囊形式显示。
  - 底部是一排图标按钮：附件、@ 引用、模型（只显示）、审批档位（点击切换）。右侧是圆形按钮，空闲时为“发送 ↑”，运行时为“停止 ■”。
  - 上方是染色 glass 徽标：
    - 状态：终端进程、子 Agent、待审批、收到的引用；数量为 0 时隐藏。
    - 快捷指令：压缩上下文、引用会话。
- **卡片和横幅**：审批卡片用橙色染色 glass，引用卡片用蓝色染色 glass，提示横幅用橙色染色 glass。
- **Agent 标识**：自绘 SVG 图标（不使用官方 logo），用 `ui.Image` 显示，鼠标悬停时显示全名。
- **颜色规范**：
  - 所有文字和图标的颜色都取自主题的颜色值，不写死。
  - 染色 glass 的色调分浅色和深色两套透明度（浅色约为深色的 45%）。
  - 自带颜色的 SVG 用 `ui.Image` 显示；单色图标用 SF Symbols 或 `ui.Icon`。
- **拆出独立窗口**：低优先级。拆出的窗口只显示会话区。

## Testing Decisions

- **什么是好的测试**：只验证从外部能观察到的行为，包括工作台核心对外的操作及其结果、MCP 工具返回的文本、持久化后重新打开看到的状态，以及界面上看得到的元素和交互。不对内部结构、表结构细节或私有函数做断言。
- **主接缝：Agent 适配器接口**：
  - 测试时只把适配器换成按脚本输出事件的**假 Agent**。其余部分全部用真实实现：放在临时目录里的 SQLite、本机的 MCP HTTP server 和 token 校验、引用和概要的生成、持久化与续接逻辑。
  - 测试只通过两种方式驱动：工作台核心对外的操作，以及一个按真实 Agent 方式调用 MCP 工具的 MCP 客户端。
  - 重点覆盖以下内容：
    - 消息归一化与编址：流式、中断、子代理、计划、思考、审批属性。
    - 引用的创建、选区规整、快照语义、自引用。
    - 概要渲染：跨工作区、自引用、长度上限、工具名。
    - 四个工具的边界、分页、搜索和错误。
    - 删除会话和移除工作区对引用的影响。
    - 压缩标记和上下文重置标记。
    - 续接失败后的三种兜底选择。
    - 闲置断开，以及有待审批时不断开。
    - token 在续接时轮换。
    - 审批档位与放行规则在进程重启后重新生效。
    - 数据目录迁移，以及数据目录不可用时的处理。
    - 单实例锁。
    - 数据库升级前的备份。
- **辅助接缝 1：界面测试**：用 MyGO 自带的无窗口 Tester 驱动真实界面，底下接同一套“核心加假 Agent”。只覆盖关键流程：在源会话推送引用、用 `@` 拉取引用、引用卡片展开、审批卡片的各个选项、续接失败横幅、登录横幅、侧栏状态标记。
- **辅助接缝 2：真实 Agent 契约测试**：
  - 默认不跑，通过环境变量开启，会调用本机真实的 `claude` 和 `codex`。
  - 验证内容：stream-json 和 control 协议审批、app-server 按 thread 注入 MCP 并且相互隔离、免审批配置、压缩事件、登录状态检测、跨工作区读取（`--add-dir`）、Claude 按路径禁止写入的规则（待验证项）、Codex 侧的 MCP 工具名（待验证项）。
  - 每次 Agent 升级后都要重跑。
- **参考做法**：仓库里还没有正式的测试代码。路线图留下的测试脚本可以作为契约测试的起点：`research/08-probes`（Codex 按 thread 注入、审批、标题、压缩）、`research/13-probes`（Claude 的 MCP 审批工具与 control 协议）、`research/14-probes`（安装、版本、登录检测）。另外，`spike/mygo-session-view` 分支里有用 `CapturePage` 和 `MYGO_FRAME_STATS` 做性能验证的方法。

## Out of Scope

- Agent 之间的自动编排或互相对话。v1 只支持由人手动发起引用。
- 云同步与多设备。
- Windows 和 Linux 的打包与适配（以后再手动验证 glass 的效果）。
- 实时引用（引用跟随源会话的后续内容更新）。
- 用 LLM 生成引用概要。工作台不持有模型 API key，也不做语义搜索。
- 会话导出为 Markdown，以及一键备份与恢复。
- 分屏同时浏览两个会话，以及在两栏之间拖拽引用。
- 导入 aibo 之外产生的原生会话。
- 支持 Agent 自带的斜杠命令。
- 会话进行中切换模型（只能在新建会话时选择）。
- 回退或编辑历史消息，以及从某一轮 fork 出新会话。
- 接入 Claude Code 和 Codex 之外的 Agent，以及走 ACP 的统一通道。
- 使用 Agent 的官方 logo。

## Further Notes

- **待验证项**（实现时确认，并据结果补充规格）：
  1. Codex 侧的模型看到的 MCP 工具名是什么样子，关系到概要里写哪个工具名。
  2. Claude 能否按路径禁止对源工作区执行 Edit/Write。
  3. 终端进程数和子 Agent 数能否从事件流里实时统计。如果做不到，徽标只显示“有 / 无”。
  4. Claude `--permission-prompt-tool stdio` 的响应字段（`updatedPermissions`、`interrupt`）在当前版本上的完整行为。
  5. 系统材质（窗口 vibrancy、原生 Liquid Glass）在浅色和深色模式下，文字是否清晰。
  6. 代码块里的长行能否横向滚动。
- **条款约束**：只调用用户本机未经修改的 `claude`；不提供 claude.ai 登录，不接触 `~/.claude` 里的凭据；不把 Claude Code 的名称或 logo 用作产品名。
- **调研与原型**：
  - 调研结论在 `research/` 下（01、02、03、08、11、14 号）。
  - 原型与验证程序分别在三个一次性分支上：`prototype/reference-ux`（HTML，发起和呈现引用的交互）、`spike/mygo-session-view`（MyGO 渲染与性能）、`prototype/window-layout`（MyGO 窗口布局）。
- **建议的实现顺序**：先做适配器接口和假 Agent，再做会话存储和运行时，接着是引用服务和 MCP server，然后是两家 Agent 的真实适配器与契约测试，最后是外壳 UI。拆出独立窗口排在最后。
