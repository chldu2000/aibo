# 实测：MyGO 会话视图原生渲染

任务：[用 MyGO 验证会话视图的原生渲染](../issues/11-mygo-native-spike.md)
实测日期：2026-11-20。环境：macOS 27，Apple Silicon，Go 1.27.3，MyGO `641de152`。
验证程序和截图在一次性分支 `spike/mygo-session-view`，位于该分支的 `spike/mygo-session-view/` 目录。所有数据都是假的，没有接入 Agent。测试由脚本自动执行（`AIBO_AUTO=1`），帧耗时来自 `MYGO_FRAME_STATS=8`，只记录超过 8 ms 的帧。

## 结论

调研“MyGO 原生 UI 能否渲染 Agent 会话”的结论在真机上成立，可以继续采用“原生 UI + 着色器 glass”。

| 检查项 | 结果 |
|---|---|
| 1. 流式 Markdown | 2.5 KB 的回复每次追加 12–36 字节，1.7 秒内流完，**没有一帧超过 8 ms**。代码块高亮、表格、引用块和列表都正常；流式结束后列表仍停在末尾（`AtEnd() == true`）。 |
| 2. 长列表 | 3000 条和 10000 条变高消息（`Key` = 序号）表现一样：`ScrollTo` 跳到中间后定位准确（可见区域从目标行往上偏 2 行左右，这是预构建行造成的）。连续 120 次跨越整个会话的跳转**没有慢帧**。首帧 27–34 ms。10000 条消息时进程内存峰值约 246 MB，其中含约百条 340 KB 的日志。 |
| 3. 着色器 glass | 浮动标题栏用 `glass.Glass{}`，顶部渐隐用 `glass.ScrollEdge{}`，下方滚动的原生内容能被正确模糊（见截图）。默认跟随系统的深色模式。 |
| 4. 按整条消息选中 | `ListState.Selection`（`ui.Selection[int]`，键为序号）能记住**从未构建过的行**，从数据模型生成复制内容不受虚拟列表的限制。**需要注意**：Cmd+点击会产生不连续的选区，Cmd+A 会选中全部。aibo 必须把选区规整为“最小序号到最大序号”的连续范围，并在发出前展示规整结果。例如选中 #10、#14、#2996 会被补齐成 2987 条消息、约 4 MB。默认的选中样式是整行强调色填充，内容高的行会显得很重，需要自定义样式。 |
| 5. 超大工具输出 | 超过 4 KB 的输出改用只读的 `editor.View`（`ReadOnly: true`，限高 320），里面有行号，可以内部滚动。展开 340 KB、6000 行的输出时只有 1 帧达到 12–13 ms，之后的帧都在 8 ms 以下。4 KB 以内直接用 `Text` 显示。 |

## 其他发现

- **构建**：在这台机器上必须用 `CGO_ENABLED=0`，否则外部链接器（Command Line Tools 自带的 clang/ld）解析不了 macOS 27 SDK 的 tbd 文件。MyGO 本身是纯 Go，不受影响。二进制约 19.6 MB。
- **代码块里的长行**：超出代码块宽度的部分会被截掉，比如截图里的 SQL 那一行。没有验证能否横向滚动。
- **没有验证的部分**（需要人手动操作）：真实的滚轮惯性和拖选手感、输入法、浅色模式、“减少透明度”时的退化效果，以及 Retina 和外接屏的切换。

## 对规格的影响

- 会话视图的实现方式：用一个 `ui.List` 显示，每条消息一行，`Key` 是序号，开启 `FollowEnd` 和 `Smooth`；流式消息用 `markdown.Stream`，结束后改为 `markdown.View`；工具调用放进 `Collapsible`，输出超过 4 KB 时用只读编辑器显示。
- 引用范围的选择：基于 `ListState.Selection`，同时开启 `DragSelect`；选区规整成连续范围后，由操作栏显示“#a–#b · n 条”。“发起和呈现引用的交互”里的方案 A 本来就是这样设计的，只需要补上“不连续选区会自动补齐”的提示。
