# 引用概要的生成规则

Type: grilling
Status: resolved

## Question

引用概要由 aibo 按规则生成，随会话引用一起交给接收方 Agent，同时显示在卡片上。要决定：
- 包含哪些字段：引用 ID、来源会话的标题和 Agent、工作区、范围和条数、开头和结尾摘录、工具名，还有没有别的？
- 摘录取多少：取哪几条消息，每条多长？
- 用什么措辞告诉接收方去调用读取工具？“验证 Codex app-server 按 thread 注入工具与审批行为”发现，Claude 要先通过 ToolSearch 发现 MCP 工具，所以概要里要写明完整的工具名。
- 跨工作区的提示怎么写？
- 自引用（为了找回压缩前的内容）时，措辞是否要不一样？
- 概要整体的长度上限是多少？

## Answer

**样例**：把“数据库迁移方案讨论”的 #7–#10 引用给另一个工作区里的 Codex 会话时，Codex 收到的内容如下。

```
<aibo-reference id="ref_7Kq2xP">
用户交给你一段来自另一个会话的引用（只读快照）。当用户的请求依赖其中的内容时，
请先调用 MCP 工具 aibo 的 read_reference 读取，不要凭概要猜测细节。
- 来源：「数据库迁移方案讨论」· Claude Code
- 源工作区：/Users/chldu/work/shop-api（不是你当前的工作区；其中的相对路径都相对于它，你只能读取不能修改）
- 范围：#7–#10，共 4 条消息（2026-11-18 14:02–14:09）
- 首条用户消息：#7「好，那就定方案：双写 + 回填。」
- 末条 Agent 回复：#10「方案已写进 docs/migration.md。关键决策：……」
- 可用工具：read_reference(ref_id="ref_7Kq2xP")、read_message、search_reference、list_references
</aibo-reference>

回填脚本按这个方案写
```

**规则**：
- **注入方式**：用户发送消息时，每个引用渲染成一个 `<aibo-reference>` 块，按顺序放在用户正文之前，一起作为这一轮的用户输入。会话记录只保存用户原文和引用列表，不保存拼接后的文本。
- **字段**：引用 ID；来源会话的标题和 Agent；源工作区（只在跨工作区时出现，附带只读提示）；范围、条数和时间段；两段摘录；可用工具清单。
- **摘录**：取范围内的第一条用户消息和最后一条 Agent 回复，各截取最多 200 字，被中断的回复标注“（已中断）”。如果范围内缺少其中一类，就改用第一条和最后一条消息。
- **工具名**：按接收方 Agent 实际看到的名字来写。Claude 写完整名 `mcp__aibo__read_reference`，方便它通过 ToolSearch 找到。Codex 的工具名格式要在实现时实测确认。
- **措辞**：由 Agent 自己判断要不要读取（“当用户的请求依赖其中的内容时，先调用工具读取”），不要求它每次都读。
- **自引用**：第一句改为“这是本会话较早的一段内容，你的上下文中可能已不再保留其细节”，并省略来源和源工作区两行。
- **语言和长度**：固定文字使用 aibo 的界面语言（v1 为中文），摘录保留原文。每个引用块不超过 1500 字，超出时先缩短摘录。
- **生成时机**：概要在创建引用时生成，与引用一起保存，之后不再重新生成。源会话后来改了标题，概要里仍保留原标题。
- **卡片**：默认显示一行“Agent · 标题 · #a–#b（n 条）”；展开后显示 Agent 实际收到的完整文本。
