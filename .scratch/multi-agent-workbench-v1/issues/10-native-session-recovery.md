# 续接原生会话与续接失败时的兜底

Type: grilling
Status: resolved
Blocked by: 05

## Question

应用重启或重新打开一个会话时，aibo 如何续接对应的 Agent 原生会话？原生会话丢失（用户删了 `~/.claude` 下的文件）或不兼容（Agent 升级后格式变了）导致续接失败时，如何发现，又让用户看到什么？候选兜底方案是新开一个原生会话，再把旧会话作为会话引用交给它。注意它与“规范会话模型”中“一个工作台会话一一对应一个 Agent 原生会话”的冲突：兜底后是在同一个 aibo 会话里换一个原生会话（变成一对多），还是另开一个新的 aibo 会话并引用旧会话？

## Answer

- **按需启动**：aibo 启动时只加载会话列表，所有会话显示为“未连接”。用户打开会话并发出第一条消息时，aibo 才续接对应的原生会话。连续 30 分钟没有交互的会话会断开：Claude 结束进程，Codex 卸载 thread。下次发消息时重新续接。
- **续接时重新注入工具**：每次续接都为会话重新生成 MCP token，并注入新的端口和 token，旧 token 立即作废。Claude 通过 `--resume <id>` 加 `--mcp-config` 实现；Codex 的 `thread/resume` 接受 `config`，已从 schema 确认。
- **判定续接失败**：只要续接调用失败，就判定为“原生会话不可用”。Claude 的情况是 `--resume` 报“找不到会话”或进程退出，Codex 的情况是 `thread/resume` 返回错误。aibo 不预先检查 Agent 的本地存储。原生会话丢失和不兼容都按这条规则处理，并向用户展示 Agent 返回的错误原文。
- **兜底后仍是同一个 aibo 会话**：aibo 会话改用一个新的原生会话，并在切换处记一个**上下文重置标记**。这个标记和压缩标记一样不算消息，在会话视图里显示为分隔线：“已切换到新的 Agent 原生会话 · 原因：……”。“规范会话模型”里的对应关系相应修改为：同一时刻只对应一个原生会话，历史上可以先后对应多个。
- **续接失败时的界面**：会话顶部显示横幅“无法续接 Agent 原生会话：<错误原文>”，提供三个选项：
  1. 新开原生会话，并引用之前的内容（推荐）。aibo 生成一个自引用，范围是重置之前的全部消息，以草稿形式放进输入框，用户可以编辑或移除后再随消息发出。
  2. 新开原生会话，不带引用。
  3. 暂不处理。会话保持只读，可以浏览，也可以被引用，但不能发消息。
- **退出 aibo 时**：正在输出的轮次被中断，那条回复按“已中断”保存；还没处理的审批请求视为拒绝，记在对应的工具调用上。如果有会话正在运行，退出前先提示“有 N 个会话正在运行，退出会中断它们”。
