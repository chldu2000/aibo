# 跨工作区引用中的文件路径

Type: grilling
Status: resolved

## Question

一个会话引用交给另一个工作区里的会话时，被引用的内容常会提到源工作区里的文件，比如 `docs/migration.md`。目前的做法只是在引用概要里提示一句。还要决定的是：
- 要不要让接收方能读到源工作区的文件？可选做法有：Claude 用 `--add-dir`，Codex 用 `runtimeWorkspaceRoots` 或沙箱可读目录；也可以让读取工具附带文件快照。
- 如果允许读，权限是只读还是可写，是否需要用户确认，持续多久？
- 引用里的相对路径要怎样表述，接收方才不会误认为是自己工作区里的文件？

## Answer

**实测**（2026-11-20，codex-cli 0.169.0，Claude Code 2.1.318）：
- **Codex**：在默认沙箱和 `read-only` 沙箱下，都能读取工作区之外的文件，也不需要审批。沙箱只限制写入。
- **Claude**：读取工作区之外的文件会被直接拒绝（`permission_denied`）。加上 `--add-dir <目录>` 后可以直接读取；但对这个目录的 Edit 仍然需要审批，在 `-p` 模式下会被拒绝。
- **注意**：`--add-dir` 可以接收多个参数，拼命令行时要把它放在提示词之后。

**决定**：
- **授予读取权限，不做文件快照。** 一个会话收到跨工作区的引用后，就能读取源工作区。
  - Claude：启动或续接时加上 `--add-dir <源工作区>`。
  - Codex：不需要处理。
- **会话中途收到引用时**：先用 `--resume` 加 `--add-dir` 重启这个 Claude 进程，再发送消息。
- **授权持续时间**：在会话的整个生命周期内有效。aibo 在会话中记录这些额外目录，每次续接时重新加上。
- **源工作区只读**：
  - Codex：不把源工作区加入沙箱的可写目录。
  - Claude：另加一条权限规则，禁止对该路径执行 Edit/Write。这种按路径禁止的规则写法还没有实测，要在实现时验证；如果做不到，就在审批界面上醒目地标注“写入其他工作区”。
- **路径原样保留**：读取工具每次返回内容时，开头加一行“源工作区：<绝对路径>；下文中的相对路径都相对于它”。
- **文件可能已经变了**：读取所有引用时（不只是跨工作区的），开头都加一行“引用中提到的文件可能在引用之后被修改过，直接读取得到的是当前版本”。
