# 会话持久化

Type: grilling
Status: resolved
Blocked by: 04

## Question

会话记录与引用如何存储（格式、位置、按工作区还是全局）？源会话被删除或被引用的消息不存在时，已有引用如何表现？

## 已知前提

- 来自“规范会话模型”：会话只追加；每条消息另存原始事件 JSON；工具输出单条上限约 1 MB；附件保存为文件。
- 用户要求：会话内容占用空间可能很大，数据存储位置要能自定义，默认放在系统 App Data 目录，也可以改到用户自己指定的位置。还要决定改位置时如何处理已有数据。

## Answer

- **存储方式**：会话元数据、消息、原始事件和引用都放在一个 SQLite 数据库里。驱动用纯 Go 实现的 `modernc.org/sqlite`，因为 MyGO 不使用 cgo，`mattn/go-sqlite3` 用不了。附件单独存成文件，放在 `attachments/` 目录。
- **搜索**：`search_reference` 逐条扫描引用范围内的消息，不建全文索引。FTS5 对中文和子串匹配支持不好，也不支持正则。
- **全局数据目录**：所有数据只放在一个全局目录（`aibo.db` + `attachments/`），项目目录里不写任何文件。
- **默认位置**：`~/Library/Application Support/aibo/`。“数据目录在哪里”这项设置存在默认位置下一个固定的小配置文件里，数据目录搬走后这个文件也不动。
- **修改数据目录**：
  - 必须先关闭所有正在运行的会话。
  - 新位置为空时，默认迁移数据：先复制，校验通过后再删除旧数据。
  - 新位置已有 aibo 数据时，可以选择直接使用。
  - 新位置在 iCloud Drive 或 Dropbox 这类同步盘里时给出警告，因为同步工具和 SQLite 同时写文件有损坏风险。
- **数据目录不可用**：弹窗提供“重试 / 重新选择位置 / 退出”三个选项，绝不悄悄新建空库。
- **删除被引用的源会话**：先提示“该会话被 N 个引用使用，删除后这些引用将失效”，确认后彻底删除。此后读取工具对这些引用返回“引用的源会话已被删除”。删除时不保留被引用的那一段。
- **删除接收方会话**：交给它的引用记录一并删除，源会话不受影响。
- **数据库结构升级**：数据库里记录结构版本号；新版本启动时如果发现结构较旧，先备份数据库文件，再自动升级。
- **单实例**：一个数据目录同一时间只允许一个 aibo 实例使用，用文件锁保证；再次启动时直接激活已经打开的窗口。
- **范围之外**：导出 Markdown、一键备份与恢复。
