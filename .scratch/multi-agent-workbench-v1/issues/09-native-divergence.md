# aibo 记录与 Agent 实际上下文不一致时的处理

Type: grilling
Status: resolved
Blocked by: 08

## Question

aibo 的会话记录表示“发生过什么”，Agent 原生会话表示“Agent 现在还记得什么”。两者会出现偏差，比如 Claude 自动压缩上下文、Codex 做 context compaction。aibo 要不要感知这类偏差，在会话视图里怎么标出压缩边界？用户读这个会话、把它引用给别的 Agent、或者接收方调用 `read_reference` 时，它们看到的内容应当分别对应哪一份？压缩边界是否在两家的事件流里提供，由“验证 Codex app-server 按 thread 注入工具与审批行为”确认。

## Answer

aibo 的会话记录“发生过什么”，Agent 上下文是 Agent“现在还记得什么”。两者因上下文压缩产生偏差时，aibo 只把偏差标记出来，不去同步：

- **压缩标记**：压缩记为挂在“第 N 条消息之后”的一个标记，不算消息，不占用序号，也不能单独被引用，所以“引用范围 = 一段连续消息”的含义不变。标记中保存触发方式（手动或自动）和压缩前后的 token 数（只有 Claude 的 `compact_boundary` 提供 token 数；Codex 的 `contextCompaction` 只有时间戳）。
- **会话视图**：在压缩发生的位置显示一条分隔线，例如“上下文已压缩 · 自动 · 19.7k → 6.3k tokens”。分隔线以上的消息照常显示，不做淡化。
- **三种场景看到的内容**：用户浏览会话时看到完整记录和压缩标记；会话引用指向完整记录；接收方的读取工具返回完整记录，但不包含压缩标记。
- **允许引用给自己**：会话引用的源会话和接收方可以是同一个会话。这样可以把压缩之前的内容引用回来，让 Agent 按需重新读取。“接收方只能读取交给自己的引用”这条规则不变。
- **由 aibo 发起压缩**：会话菜单里提供“压缩上下文”。Claude 通过发送 `/compact` 实现，Codex 通过调用 `thread/compact/start` 实现。
- **Agent 自带的斜杠命令**：v1 不转发给 Agent，输入框提示“暂不支持”，原因是 `/clear`、`/rewind` 这类命令会让 aibo 的记录与 Agent 上下文对不上。以后是否支持、如何支持，已列入路线图的“暂未明确”。
