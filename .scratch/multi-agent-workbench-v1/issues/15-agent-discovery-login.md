# Agent 的发现、版本兼容与登录引导

Type: grilling
Status: resolved
Blocked by: 14

## Question

根据“检测 Agent 的安装、版本与登录状态的方式”的结论，决定以下几件事：
- aibo 启动时，以及新建会话时，要检查哪些状态？
- 用户可以手动指定可执行文件的路径吗？
- 最低支持的版本怎么定？遇到不支持的版本，提示什么？
- 未安装或未登录时，界面上怎么呈现，又怎样引导用户？
- Agent 升级后，已有会话怎么处理？续接失败的情况已经交给“续接原生会话与续接失败时的兜底”处理。

## Answer

依据“检测 Agent 的安装、版本与登录状态的方式”的调研结论，决定如下：

- **查找可执行文件**：按以下顺序查找。
  1. 用户在设置里指定的路径。
  2. 固定位置：`~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin`、npm 全局目录。
  3. `$SHELL -lic`，超时 3 秒，输出前后加标记以便解析。

  找到的路径和 shell PATH 都缓存起来。启动 Agent 进程时把这份 PATH 传给它，因为 npm 安装的 Codex 依赖 node。只有出错或用户点“重新检测”时才重新查找。
- **检查时机**：
  - aibo 启动时，在后台检查两家 Agent 的路径、版本和登录状态，不阻塞界面。
  - 新建或续接会话时，只按缓存做一次快速确认。
  - Claude 的登录状态在启动时用 `claude auth status` 检查；之后只在某一轮返回 `authentication_failed` 时重新检查。
  - Codex 的登录状态在启动时用 `account/read` 检查；之后订阅 `account/updated` 通知，遇到 401 失败时再检查一次，**不做每轮检查**。代价是：如果登录状态在 app-server 不知情的情况下失效，用户最多会多等约 18 秒的重试才看到报错。
- **最低版本**：Claude Code 2.1.318、codex-cli 0.169.0，即本路线图实测用的版本。
  - 低于最低版本：这个 Agent 不可用，提示用户升级。
  - 高于最低版本：正常使用；遇到不认识的字段或方法（例如 `-32600 unknown variant`）时，显示具体的错误信息。
- **未安装**：“新建会话”里该 Agent 显示为灰色，注明“未找到 X”，并提供官方安装说明的链接，以及“手动指定路径”“重新检测”两个按钮。aibo 不替用户执行安装命令。
- **登录引导**：
  - **Claude 未登录**：提供三个操作：复制命令 `claude`；“在终端中打开”（用 `open -a Terminal` 启动未修改的 `claude`，由用户自己登录，aibo 不经手）；登录后点“重新检测”。
  - **Codex 未登录**：应用内提供两种登录方式：“用 ChatGPT 登录”（`account/login/start`，用系统浏览器打开 `authUrl`）和“设备码登录”。登录完成后，aibo 收到 `account/login/completed` 或 `account/updated` 通知就自动刷新状态。使用 API Key 的用户，引导到终端运行 `codex login`，aibo 不经手 Key。
- **会话进行中掉线**：
  - **Claude**：那条回复标为“出错：未登录”，同时显示登录横幅。登录后可以点“重试”，把刚才的消息重新发出。
  - **Codex**：如果在一轮开始前就发现未登录，消息不发出，输入框里的内容保留，并显示登录横幅。
- **Agent 升级**：启动时如果发现版本号变了，就重新探测能力、记下新版本号，不打扰用户。已有会话不受影响；续接失败的情况按“续接原生会话与续接失败时的兜底”处理。
- **设置里的 Agent 页面**：每个 Agent 一个区块，显示路径、版本、登录状态和认证方式，提供“选择其他可执行文件”和“重新检测”两个按钮。这一页也计入“工作区与会话列表的管理（含配置项清单）”的配置项清单。
