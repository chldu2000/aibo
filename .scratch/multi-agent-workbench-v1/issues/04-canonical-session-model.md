# 规范会话模型

Type: grilling
Status: resolved
Blocked by: 01

## Question

工作台保存的会话记录包含哪些内容（用户消息、Agent 消息、思考、工具调用与结果、权限请求、附件），哪些可以被引用和读取？消息如何编址，使引用范围稳定可复现？两家 Agent 的事件如何归一到同一模型？

## Answer

- **消息**是会话时间线上的一个条目，分为四类：用户消息、Agent 回复、工具调用（调用和结果合为一条）、计划（Codex plan / Claude TodoWrite）。**轮次**是一条用户消息加上 Agent 对它的全部处理，只用于分组显示；界面上可以“选中整轮”，但引用边界仍落在消息上。
- **思考内容**附属于它后面的那条回复，会保存并显示；`read_session` 默认不返回，可以显式请求。
- **工具输出**完整保存，单条超过上限（约 1 MB）就截断并加标记，界面上默认折叠。按 token 预算截断属于读取工具接口的问题。
- **编址**：每条消息有会话内单调递增、永不复用的序号；引用记为“会话 ID + 起始序号 + 结束序号”。只有已结束的消息能被引用；中断或出错的消息也算已结束，读取时标注“已中断”。
- **会话只追加**，不支持回退或编辑，所以快照引用始终有效。以后要“从某一轮重来”，靠 fork 出新会话。
- **子代理**的消息嵌套在父工具调用里，不能单独引用；引用父工具调用时连同子代理的最终结果一起带上。
- **审批**（请求和用户的批准/拒绝/本会话始终允许）作为工具调用的属性记录，不单独成为消息。
- 一个工作台会话**一一对应**一个 Agent 原生会话（Claude session id / Codex thread id），只保存这个 ID 用于续接；内容以工作台自己的记录为准，不读 Agent 的本地存储。
- 每条消息另存**原始事件 JSON**，只在内部使用（重新解析、排查问题），不对外暴露。
- **附件**保存为文件，消息里引用；`read_session` 只返回“[图片: 文件名]”这样的占位文字。
- **会话元数据**：
  - 标题：手动改过的优先，其次用 Agent 生成的标题（接口是否提供，由“验证 Codex app-server 按 thread 注入工具与审批行为”确认），都没有就取第一条用户消息的开头
  - 其他字段：Agent 类型、工作区、所用模型、创建时间、最后活跃时间、Agent 原生会话 ID
