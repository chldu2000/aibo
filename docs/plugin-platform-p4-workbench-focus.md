# P4 第三十七批：重排后的可用焦点恢复

浏览器探针复现：没有稳定标识的导航按钮获得焦点后，切换专注布局会移除该按钮，焦点落到页面根部。原实现只保存标识，无法区别“工作台从未获得焦点”和“焦点来自没有标识的控件”。

现在额外记录工作台是否曾获得焦点。恢复时优先尝试原标识，并跳过禁用、隐藏、inert、aria-hidden 或没有布局区域的元素；如果原目标无法聚焦，依次寻找可用控件。调用 focus 后核对实际 activeElement，避免有 aria-label 的非交互容器被误认为已恢复。宿主区域暂停工作台时不抢焦点。

`pnpm run verify` 通过：25 项架构测试、类型检查、165 项 Node 测试及生产构建。

## 证据

`node probes/workbench-lifecycle.mjs` 在修复前以“移除导航后应聚焦草稿”断言失败，修复后通过。扩展验证覆盖两套皮肤：

- 无稳定标识的导航按钮被移除后，焦点进入主内容草稿。
- 保存的草稿目标随后被禁用或隐藏时，焦点转到可用按钮。
- Tab 继续导航，不停留在 body。
- 既有草稿、插件表单、流式更新、挂载失败恢复、旧代际/会话回调拒绝继续通过。

[浏览器证据](./baselines/plugin-platform-p4/workbench-focus-browser.json)。该批修复键盘焦点问题，不将浏览器焦点断言等同于完整屏幕阅读器或原生桌面验收；P4 整体退出条件仍未完成。
