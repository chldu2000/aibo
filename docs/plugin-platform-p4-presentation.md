# P4 第一批：呈现描述与降级协商

默认工作台和语义视图的预检已接入可信 default-presentation 模块。描述符明确核心语义版本、四种必需语义和可选专业呈现；缺少核心类型、未知版本、重复或越界的可选声明均拒绝预检。

专业呈现按 ID、版本及核心类型匹配，匹配失败退回当前 renderer 的核心视图。两条路径接收完全相同的规范快照副本，不能通过替换成缩减数据来隐藏必需字段或动作。非法语义快照直接拒绝，不伪装成可降级内容。

本批没有实现实际专业 renderer，也没有把默认 App 的全部布局拆成槽位。P4 剩余的布局装配、专业呈现实例、独立可信恢复入口、写入审批及副作用验收继续推进；此批只作为可独立提交的合同基础。

| 边界 | 当前支持与所有者 |
| --- | --- |
| 默认呈现实现 | dev.aibo.ui-default 1.0.0，构建期可信模块 |
| 核心语义契约 | 1.0.0，四种核心语义全部必需；旧实验数据继续独立读取 |
| 可选专业呈现 | 精确 ID/版本/核心类型匹配；默认实现暂不声明专业类型 |
| 布局与视觉 | 布局归表现插件；控件视觉归当前 skin，业务模块不获样式权 |
| 执行与恢复 | 宿主拥有状态、审批和恢复；描述符不授予新的执行权限 |

描述符预检独立于完整语义验证器，避免工作台首屏为了检查版本而加载整个语义 schema；完整快照校验仍在语义视图加载时执行。

验证：pnpm run verify 覆盖 23 项架构检查、143 项 Node 测试、类型检查和生产构建；新增 renderer-negotiation 测试验证核心要求、专业版本不匹配、完整数据/动作保留和类型约束。架构测试现已递归扫描 workbench 子目录，没有降低原有规则。

node probes/semantic-ui-browser.mjs 通过两套皮肤和两种 renderer 的显示、动作、焦点及恢复回归。本批没有 Rust 改动。

### 宿主恢复入口（第二批）

工作台在可替换内容之外始终提供「恢复默认呈现」按钮，并在窗口捕获阶段响应
Ctrl/Cmd + Shift + Backspace。恢复请求可以覆盖正在排队的布局切换；旧切换的
完成回调不能清除新请求的 busy 状态，过期挂载不能写入布局偏好或恢复焦点。
错误提示仅报告「呈现错误」，避免在默认呈现也失败时误报已经恢复。

验证：`pnpm run verify` 通过；`node probes/workbench-recovery-browser.mjs`
使用真实 WorkbenchPresentation 验证常驻按钮、快捷键、挂载失败回退和再次恢复。
此批仅完成恢复控制路径；插件管理、授权、历史的独立宿主区域及完整布局装配仍待完成。

### 独立宿主区域（第三批）

重新挂载；恢复控件在插件管理打开时仍可操作。工作台暂时隐藏但保持实例，
关闭管理后继续显示。插件操作捕获宿主工作区/会话上下文，拒绝旧上下文回调；
不再依赖 renderer generation。`workbench-contract.ts` 仍只描述可替换区域的
快照与动作，宿主控件不会作为插件可调用的动作注册进去。

授权、独立历史浏览与完整布局装配尚未完成，本批不据此勾选整项 P4 验收。

第三批验证：`pnpm run verify`；`node probes/git-plugin-native.mjs` 的两次真实

### 独立宿主审批（第四批）

Agent 审批从时间线移入宿主区域，显示所有待审批会话及请求内容。可替换工作台
不再获得审批决定回调。插件管理打开、呈现切换及后台会话审批均使用同一宿主
区域。审批控制器拒绝失效/内容改变的请求和重复提交；迟到响应不会删除同键但
属于新 turn 的替代请求。原生宿主仍执行最终有效性检查。

本批是 Agent 审批入口隔离，不等同于完成 Capability 写入审批或非 never 的
PluginView 动作确认；这些通路、独立历史及完整布局装配仍在 P4 待办中。

第四批验证：完整 `pnpm run verify` 通过（23 项架构检查、144 项 Node 测试、

### PluginView 原生确认（第五批）

非 `never` 动作由 Rust 宿主打开原生确认对话框，展示插件、会话、工作区、
视图、动作、能力和本次参数。插件 DOM 不获得“已确认”标志或免确认 token。
`when-sensitive` 暂与 `always` 一样要求确认：目前没有足以安全跳过确认的
通用敏感性分类。取消、对话框不可用或超过五分钟均不执行。

输入 schema/manifest/capability 先通过校验，再请求确认。确认后重新核对当前
视图文档、runtime generation、会话状态、安装版本、包摘要、执行配置、启用/
安装状态及工作区信任；变化时拒绝执行，不自动重试。一次只接纳一个 PluginView
确认/派发，重复请求返回 busy；取消任务会释放并发许可。该门仅覆盖 PluginView
动作，不把它等同于未来 Broker 写入任务的幂等、审计与结果未知协议。
动作输入上限为 16 KiB，确认时完整显示参数，不截断后批准隐藏部分。

真实 Echo 子进程测试覆盖 never 兼容、always 拒绝、when-sensitive 批准、重复
提交、无桌面确认端口、确认期间信任撤销和视图变化。原生对话框的人工点击尚未
验收；旧 v1 IPC 尚不携带调用者所见的 revision/generation，当前复核比较的是
宿主本次确认前后的上下文。因此确认清单仍不勾选完成，后续补 caller freshness
和原生对话框验收，不将此批视为整个 P4 审批完成。

第五批验证命令：`cargo test --manifest-path src-tauri/Cargo.toml`（140 通过），
`pnpm run verify`（23 项架构检查、144 项 Node 测试、类型与构建通过）。

### 原生对话框验收（第七批）

动作 IPC 由 Tauri 注入发起调用的 WebviewWindow，宿主将它设置为原生确认的
父窗口。该窗口不是插件提供的参数。没有发起窗口时不打开独立的系统级通知
对话框；这一点使多窗口确认的归属明确。macOS 库的无父窗口分支使用系统通知，
有父窗口分支使用应用内原生 sheet，本批用实际运行验证并切换到后者。

`node probes/view-confirmation-native.mjs` 创建隔离工作区及 Echo 安装包，将测试
动作声明为 always，通过真实 IPC 发起确认。Swift 辅助功能工具只在该隔离进程
中定位包含指定测试标记的对话框，实际点击取消和批准。取消返回
confirmation_cancelled 且不更新视图；批准返回操作结果并更新视图。没有模拟
确认返回值，也没有操作用户的其他应用窗口。此 probe 适用于已授予辅助功能
权限的 macOS；其他平台的原生对话框外观不据此宣称已经验收。

结合第五批真实子进程的拒绝、信任撤销、上下文变化和重复提交检查，以及第六批
真实 IPC 的 revision/generation 检查，PluginView confirmation 清单项现已完成。
[原生按钮验收结果](./baselines/plugin-platform-p4/view-dialog.json)仅包含布尔结果
和按钮名称。完整 P4 的布局、独立历史、专业呈现和 Broker 写入仍待完成。

第七批完整回归：`cargo test --manifest-path src-tauri/Cargo.toml` 140 通过；
`pnpm run verify` 的 23 项架构检查、144 项 Node 测试、类型检查及构建通过。

### 项目任务领域服务（第八批）

项目任务的定义校验、保存/删除/查询、执行与历史读取从 `lib.rs` 提取到
`src-tauri/src/project_actions.rs`。五个 IPC 命令只转发参数；服务依赖数据库和
artifact 根目录，不接收 AppState、窗口或 Tauri State，也不调用 Tauri runtime。
因此后续受控执行入口可以复用同一份领域逻辑，不需要再复制 IPC 实现。

保留既有信任检查、会话所属工作区校验、cwd 边界、进程组终止、输出限额和脱敏。
直接服务测试使用隔离数据库与真实子进程，覆盖保存/查询、stdout/stderr、持久
运行记录、禁止 cwd 越界，以及撤销信任后拒绝执行且不新增运行记录。

本批是接入 Broker 写入前的项目任务服务提取。Git 服务仍待提取；旧执行语义
仍在执行结束后记录结果、超时标为 timed_out、删除定义会级联删除运行记录。
后续持久任务接纳、审批、幂等、取消、结果未知与历史保留必须独立实现，不能
以当前服务可调用代替 P4 写入验收。相关整项清单继续保持待办。

第八批验证：完整 Rust 测试 141 通过；`pnpm run verify` 的 23 项架构检查、

### 有界进程执行（第十批）

新增 `controlled_process`，项目任务使用该执行器。退出等待和 stdout/stderr 回收
共用一个期限：主进程退出而子进程继续占用管道时，不再无限等待输出。保留期限
内读到的部分输出，单流内存有上限，超额数据仍持续排空，避免反压卡住进程。
结束、超时或执行 Future 被取消时清理进程组；退出后的回收等待也有期限。

Unix 真实进程测试覆盖“主进程退出、子进程持有管道”、大量输出及取消后子进程
不得继续写文件。Windows 保留 taskkill 清理路径，尚未做 Windows 原生验收。
此执行器约束进程生命周期，不是文件系统/网络沙箱。项目任务 v1 暂继续返回
原有 timed_out 状态，持久接纳、确认、取消入口、结果未知和 Broker 写入仍待接入。

首次完整 Rust 运行中新增三项进程测试通过；既有 PluginHost 综合测试出现一次
idle/interrupted 状态断言失败，与此前基线记录同形。该次失败保留为回归记录，
不因随后复跑通过就宣称其原因已经修复。

第十批最终验证：完整 Rust 复跑 145 通过；`pnpm run verify` 的 23 项架构检查、
144 项 Node 测试、类型及构建通过。首次既有 PluginHost 状态失败的原因仍未确认。

### 项目任务持久运行记录（第十一批）

迁移 0029 在执行前写入 running 记录与任务定义快照，完成后更新同一 run ID。
新记录为 `aibo.project-action-run/v2`，运行期间 completedAt 为 null。超时、执行
错误及启动恢复发现的未结束记录标为 outcome_unknown，不自动重放。当前执行器
错误尚未区分 spawn 前后，所以错误分支保守标为结果未知；后续可在保留证据的
前提下细分明确未开始的失败，不能默认认为所有错误都没有副作用。

移除任务定义与运行记录之间的级联删除，保留任务名称，删除定义后仍可读历史。
旧 v1 记录保持原 schema、输出和时间。迁移补充的定义明确标为
migration-current-definition，不能当作旧执行时的完整快照；新记录的 admission
快照才表示本次接纳时的定义。工作区删除仍按原数据清理规则删除该工作区记录。

启动恢复只将 running 转为结果未知，不重试，重复恢复不重复修改终态。终态更新
要求记录仍为 running，避免覆盖并发恢复结果。UI 显示“执行中”和“结果未知”，
且晚到结果不会混入用户已经切换到的其他工作区。

直接服务测试覆盖执行期间记录可见、取消执行 owner 后关闭并重开数据库、恢复
幂等、删除定义后保留名称和记录，以及执行错误仍留下可读取结果；独立迁移测试
证明旧 v1 记录不丢失。本批仍未接入审批、用户取消入口、幂等键或写冲突门，P4
受控写入整项保持待办。

本批验证还定位到既有 PluginHost 状态偶发失败的一条明确路径：日志捕获 SQLite
错误 517（BUSY_SNAPSHOT），事件投影因此停止插件并将会话中断。投影事务改为
BEGIN IMMEDIATE，在读取状态前预留写锁，避免与其他连接写入之间的事务升级
冲突。新增并发测试验证其他写入必须等投影提交，且两次更新均保留。没有通过
重放插件命令来规避争用；不能据此断言此前所有同形历史失败都只有这一种原因。

第十一批最终验证：完整 Rust 测试 148 通过；`pnpm run verify` 的 23 项架构检查、
144 项 Node 测试、类型及构建通过。投影争用修复单独提交，任务记录与迁移另行提交。

### 项目任务持久请求身份（第十二批）

迁移 0030 为任务记录增加 request_id 与独立 request_json，并以
(workspace_id, request_id) 建立唯一约束。旧记录保留空请求身份，不参与去重。
宿主 IPC 要求请求 ID；前端 API 默认为新执行生成 UUID，也允许调用者显式保留
原 ID 查询同一请求。ID 限制为 1–128 个 ASCII 字母、数字、连字符或下划线。

同一工作区、同一请求 ID 的并发提交只有数据库接纳成功的一次可以启动进程。
重复提交返回已有 running 或终态记录，不等待或重新执行；同一 ID 改换任务或
session 则拒绝。输入身份独立保存，避免 session 删除后的外键置空改变去重含义。
重放先检查工作区存在且仍受信任，然后读取原记录，不重新解释已编辑或删除的
任务定义。因此重复请求不会因任务修改执行新命令；需要新执行时必须使用新 ID。
工作区删除仍按原规则清理记录，此去重保证限于记录保留期间。

直接服务测试用真实 shell 追加文件，验证并发相同请求只产生一次副作用、返回
同一运行 ID、不同输入不能复用 ID、删除定义并重开数据库后仍返回原结果。
中断恢复测试额外验证重放 outcome_unknown 仍返回原记录，不启动进程。

本批只是受控写入的持久去重基础。每次独立 UI 点击当前仍生成新 ID，尚未实现
按钮级重复点击合并；不同请求之间的工作区写冲突、调用者身份传播、审批、用户
取消和 Git 写入接入仍待完成，不据此勾选 P4 的完整写入验收。

第十二批验证：完整 Rust 测试 149 通过；`pnpm run verify` 的 23 项架构检查、
144 项 Node 测试、类型及构建通过。
