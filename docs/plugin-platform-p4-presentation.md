# P4 第一批：呈现描述与降级协商

默认工作台和语义视图的预检已接入可信 default-presentation 模块。描述符明确核心语义版本、四种必需语义和可选专业呈现；缺少核心类型、未知版本、重复或越界的可选声明均拒绝预检。

专业呈现按 ID、版本及核心类型匹配，匹配失败退回当前 renderer 的核心视图。两条路径接收完全相同的规范快照副本，不能通过替换成缩减数据来隐藏必需字段或动作。非法语义快照直接拒绝，不伪装成可降级内容。

本批没有实现实际专业 renderer，也没有把默认 App 的全部布局拆成槽位。P4 剩余的布局装配、专业呈现实例、独立可信恢复入口、写入审批及副作用验收继续推进；此批只作为可独立提交的合同基础。

| 边界 | 当前支持与所有者 |
| --- | --- |
| 默认呈现实现 | dev.aibo.ui-default 1.0.0，构建期可信模块 |
| 核心语义契约 | 1.0.0，四种核心语义全部必需；旧实验数据继续独立读取 |
| 可选专业呈现 | 精确 ID/版本/核心类型匹配；默认实现暂不声明专业类型 |
| 布局与视觉 | 布局归表现插件；控件视觉归当前 skin，业务模块不获样式权 |
| 执行与恢复 | 宿主拥有状态、审批和恢复；描述符不授予新的执行权限 |

描述符预检独立于完整语义验证器，避免工作台首屏为了检查版本而加载整个语义 schema；完整快照校验仍在语义视图加载时执行。

验证：pnpm run verify 覆盖 23 项架构检查、143 项 Node 测试、类型检查和生产构建；新增 renderer-negotiation 测试验证核心要求、专业版本不匹配、完整数据/动作保留和类型约束。架构测试现已递归扫描 workbench 子目录，没有降低原有规则。

node probes/semantic-ui-browser.mjs 通过两套皮肤和两种 renderer 的显示、动作、焦点及恢复回归。本批没有 Rust 改动。

### 宿主恢复入口（第二批）

工作台在可替换内容之外始终提供「恢复默认呈现」按钮，并在窗口捕获阶段响应
Ctrl/Cmd + Shift + Backspace。恢复请求可以覆盖正在排队的布局切换；旧切换的
完成回调不能清除新请求的 busy 状态，过期挂载不能写入布局偏好或恢复焦点。
错误提示仅报告「呈现错误」，避免在默认呈现也失败时误报已经恢复。

验证：`pnpm run verify` 通过；`node probes/workbench-recovery-browser.mjs`
使用真实 WorkbenchPresentation 验证常驻按钮、快捷键、挂载失败回退和再次恢复。
此批仅完成恢复控制路径；插件管理、授权、历史的独立宿主区域及完整布局装配仍待完成。

### 独立宿主区域（第三批）

标题栏、插件管理、设置与诊断移出可替换工作台。插件面板不再因为呈现切换而
重新挂载；恢复控件在插件管理打开时仍可操作。工作台暂时隐藏但保持实例，
关闭管理后继续显示。插件操作捕获宿主工作区/会话上下文，拒绝旧上下文回调；
不再依赖 renderer generation。`workbench-contract.ts` 仍只描述可替换区域的
快照与动作，宿主控件不会作为插件可调用的动作注册进去。

授权、独立历史浏览与完整布局装配尚未完成，本批不据此勾选整项 P4 验收。

第三批验证：`pnpm run verify`；`node probes/git-plugin-native.mjs` 的两次真实
桌面启动均通过（含双皮肤宿主管理实例保留、Git 视图与重启恢复）；
`node probes/host-shell-browser.mjs` 使用真实 App 与鼠标点击验证双皮肤入口可达，
没有以 DOM `.click()` 代替遮挡检查。隐藏工作台的动作通道也暂停，防止迟到的
界面回调在管理区域打开时继续触发。

### 独立宿主审批（第四批）

Agent 审批从时间线移入宿主区域，显示所有待审批会话及请求内容。可替换工作台
不再获得审批决定回调。插件管理打开、呈现切换及后台会话审批均使用同一宿主
区域。审批控制器拒绝失效/内容改变的请求和重复提交；迟到响应不会删除同键但
属于新 turn 的替代请求。原生宿主仍执行最终有效性检查。

本批是 Agent 审批入口隔离，不等同于完成 Capability 写入审批或非 never 的
PluginView 动作确认；这些通路、独立历史及完整布局装配仍在 P4 待办中。

第四批验证：完整 `pnpm run verify` 通过（23 项架构检查、144 项 Node 测试、
类型与构建）。`node probes/p2-native.mjs` 两次真实桌面启动通过；实际 Codex 与
Pi 请求均通过宿主按钮批准，覆盖后台会话、插件管理同时打开、审批区域跨呈现
切换保留及批准后完成。Echo 流式切换、草稿、焦点、Agent 不重启、真实进程重启
后的模型配置/历史和双窗口隔离回归也通过。

### PluginView 原生确认（第五批）

非 `never` 动作由 Rust 宿主打开原生确认对话框，展示插件、会话、工作区、
视图、动作、能力和本次参数。插件 DOM 不获得“已确认”标志或免确认 token。
`when-sensitive` 暂与 `always` 一样要求确认：目前没有足以安全跳过确认的
通用敏感性分类。取消、对话框不可用或超过五分钟均不执行。

输入 schema/manifest/capability 先通过校验，再请求确认。确认后重新核对当前
视图文档、runtime generation、会话状态、安装版本、包摘要、执行配置、启用/
安装状态及工作区信任；变化时拒绝执行，不自动重试。一次只接纳一个 PluginView
确认/派发，重复请求返回 busy；取消任务会释放并发许可。该门仅覆盖 PluginView
动作，不把它等同于未来 Broker 写入任务的幂等、审计与结果未知协议。
动作输入上限为 16 KiB，确认时完整显示参数，不截断后批准隐藏部分。

真实 Echo 子进程测试覆盖 never 兼容、always 拒绝、when-sensitive 批准、重复
提交、无桌面确认端口、确认期间信任撤销和视图变化。原生对话框的人工点击尚未
验收；旧 v1 IPC 尚不携带调用者所见的 revision/generation，当前复核比较的是
宿主本次确认前后的上下文。因此确认清单仍不勾选完成，后续补 caller freshness
和原生对话框验收，不将此批视为整个 P4 审批完成。

第五批验证命令：`cargo test --manifest-path src-tauri/Cargo.toml`（140 通过），
`pnpm run verify`（23 项架构检查、144 项 Node 测试、类型与构建通过）。
