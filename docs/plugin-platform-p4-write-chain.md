# P4 插件间写调用

窗口直接写入之上，新增经 Broker 的插件间写调用。每个子写入都有独立宿主意图、
原生审批和终态；它们共享根请求持有的工作区占用。没有把父插件的批准直接当作
对子插件的批准，也没有要求子调用重新竞争父调用已经持有的锁。

## 调用与授权

沿用 runtime 2.0 的 `capability.call`。插件只能提交父 invocation/generation、
目标 plugin/contribution、能力版本和输入；不能提交权限、scope、原始调用者、
安装 release、写入许可或审批结果。Broker 检查声明依赖并选择已固定的 release，
子调用不读取工作区的 UI provider 偏好。父包及目标包、原始窗口、活动 invocation
链、工作区目录身份和依赖选择在批准后再次核对。

每层权限收紧为该操作声明的权限，并且必须是父层有效权限的子集。根 read
操作不能取得写权限；write → read → write 同样被拒绝，不能借调用链上更早的
write 祖先恢复已经丢弃的权限。循环、深度和输入校验在显示子审批前执行，沿用
8 层、每 invocation 最多 32 个子请求及全局 32 个活动 invocation 的上限。

原生确认仍由最初窗口提供的不可反序列化宿主回调构造。子确认展示自身完整输入、
精确安装与贡献、权限、原始窗口及调用链，并说明父写入已经获准、可能已产生
影响。子插件入口、初始化及其依赖版本程序都在子批准和复核之后运行。父插件
在等待期间仍属于已批准的执行，宿主没有声称冻结或沙箱化任意本机代码。

## 共享占用与持久关系

`workspace_write_runs` 的执行上下文持有宿主内部共享占用对象，绑定规范化根目录、
工作区和原窗口。只有活跃父写入发出的上下文可以创建同作用域子写入；上下文
不能由前端 JSON 构造。共享对象一直保留到所有调用与结算结束，其他受控工程
任务、Git、恢复及独立能力写入仍会遇到 busy。

迁移 0038 增加 nullable `parent_write_run_id`、`root_write_run_id`。新根请求的
root 指向自己，子请求记录最近的写祖先与同一 root；旧记录保持 NULL，不推测
历史关系。若中间经过 read 操作，实际直接调用者由 capability invocation 的
parent/root 关系及子意图中的 `parentInvocationId` 保留。独立工作区执行历史
返回父/根 ID，离开呈现页面不会丢弃这些记录。

子请求 ID 是宿主对父 invocation ID 与子 JSON-RPC ID 的确定性哈希；输入身份
还包含父 invocation、父 write run、精确安装及贡献。重复子 JSON-RPC ID 在
Broker 边界拒绝，不能再次执行。根请求重放返回根的持久结果，不重新启动父插件
或重走子调用；卸载、重绑及重启不改变这个规则。审批拒绝也保存为子终态，但
不会伪造一次已经运行的 capability invocation。

## 取消、期限与结果未知

子审批同时等待自身持久取消、祖先取消/终止及父 deadline。子运行可从独立
执行历史按 run ID 停止；原窗口权限不变。停止根会停止整条分支，停止子会停止
它的后代。子 timeout 从其批准后的执行开始计时，但上限仍是父 deadline；子
审批等待会消耗父执行时间，不能通过逐层弹窗延长总期限。

子审批被拒绝或在开始前失效时，父插件可以处理这一结构化失败并返回自己的
结果。父已经产生的文件变化保留，不宣称整个根请求没有执行。父取消、超时或
崩溃时，未批准子请求结算为 rejected；父执行按结果未知处理。

一旦子写入进入批准执行后结果不确定，整条写链设置不可清除的未知标记。即使
父插件准备忽略失败并返回成功，Broker 也会停止继续调用、清理进程，并把根及
有关调用记为 outcome_unknown。子结算失败同样不能由父输出掩盖。各级记录保留
已知终态：已经完成的兄弟或子写入不会被改写成“没有执行”，更不会自动回滚。

runtime 2.0 的结构化错误集合增加 approval_rejected、outcome_unknown，保持旧
信封与 Agent v1 不变。权限、审批和最终未知判定仍由宿主掌握，不依赖插件给出的
错误文字或 idempotent 声明。启动恢复仍分别拒绝未批准记录、将未结算执行记为
未知，不恢复执行、不自动重试。

## 边界与下一步

本批仍使用已有 Unix 进程组执行边界，不提供针对任意本机代码的操作系统沙箱，
也不冻结外部编辑器或整个工作区文件系统。原生验证范围为 macOS。

安装语义视图的写动作仍须接到这一审批链，保留呈现 revision/generation 与确认
后复核；完整工作台装配、专业呈现降级、历史兼容和整体交互验收继续推进。本批
不据此勾选 P4 总退出条件或通用写入全部验收。
