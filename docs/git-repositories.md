# 工作区内的多个 Git 仓库

Git 面板自动发现工作区本身及内部仓库。首次发现一个仓库时直接进入；多个仓库时默认显示「所有仓库」。仓库选择、折叠状态、文件选择按工作区保存；提交草稿、分支草稿和历史选择按仓库分别保存。

所有仓库视图按仓库分组显示变更，干净仓库默认折叠。每个文件的 diff 和暂存操作携带所属仓库身份，分组内的全部暂存只作用于该仓库。提交、历史、分支、远端同步和 stash 在单仓库视图操作。切换仓库会撤销旧的界面操作凭据，清除旧历史，并使未完成的详情请求失效。

## 发现范围

- 支持普通仓库、嵌套仓库、submodule 和 worktree；同时识别 `.git` 文件和目录。
- 子模块在父仓库中的指针变更和子模块内部文件变更分别保留。
- 不跟随目录符号链接；跳过 `.git`、`node_modules`、`target`、`dist`、`build`、`.next`、`.venv`、`vendor`、`.cache`。
- 默认检查最多 2,000 个目录，深度上限 9，仓库数量上限 125。「继续扫描」扩大扫描预算，最多 100,000 个目录。触及范围限制或目录读取失败时明确显示提示。
- 工作区处于已有仓库内部时保留所属仓库的原有行为，并标记仓库根目录位于工作区外。
- 刷新会重新发现仓库。状态读取逐个发布；单仓库读取失败不阻断其他仓库。

## 宿主接口

`list_workspace_git_repositories(workspaceId, scanBudget?)` 返回仓库 ID、名称、相对路径、类型及扫描限制、警告。仓库 ID 是工作区内的相对目录，工作区自身为 `.`。

现有工作区 Git 命令增加可选的 `repositoryId`。每次读写均由后端验证规范化路径仍位于工作区内，并验证目录仍是指定仓库的边界。省略参数保留原有调用语义。写入继续使用原工作区的信任、互斥、确认和持久化记录；仓库身份加入写请求身份，确认前后指纹检查作用于目标仓库。

内置侧栏和插件呈现共用同一宿主状态与接口。独立的旧版只读 semantic 示例和 fixtures 不属于此 Git 面板接口。
