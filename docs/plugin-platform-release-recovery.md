# Release 回滚与数据恢复验收

本记录区分已经验证的恢复行为与仍需完成的升级失败路径；P5 release 退出项尚未完成。

## 已验证：并存数据与显式代码回滚

`capability_broker::tests::explicit_code_rollback_reopens_old_private_data_after_database_and_broker_restart` 使用两个实际安装、启用的 release 和真实 Node 子进程。各子进程通过初始化的 `privateData.path` 写入自己的版本标记，再由实际能力调用读取标记作为输出。测试依次验证：

1. 绑定旧版，读取旧版数据；显式绑定新版，读取新版数据，instance 身份不同。
2. 停止两个 runtime，卸载新版代码，显式选择仍安装的旧版并调用，确认回滚绑定。
3. 关闭并重开实际 SQLite 数据库，执行 Broker 启动恢复并重建 Broker，再调用旧版；installation、instance 与旧版数据均恢复。
4. 新旧数据文件均保留，卸载新版未清除其私有数据。

这覆盖宿主提供的 release/instance 存储隔离与持久绑定恢复，不是假设旧版可以读取新版格式，也不宣称操作系统进程隔离能阻止恶意插件越权访问任意文件。

## 代码回滚路径

停止故障 release 的新调用并处理既有执行后，明确选择旧安装版本作为提供者。旧包若已卸载，可从保留的同一包重新安装；注册表按插件 ID、版本与包摘要恢复原 installation 身份。先检查该版本与已锁定依赖仍可用，再启用、显式绑定并验证调用。不能仅凭版本字符串将不同摘要的包当作原 release。

停用不会自动选择另一个提供者；安装新版本也不自动覆盖已有能力绑定。故障期间历史通过宿主持久化接口读取，不依赖重新启动故障插件。活动 session 的锁定版本不能通过普通能力换绑绕开。

旧包回收还受恢复引用约束，已存在的注册表回归覆盖“卸载后仍被引用则保留、同包重装恢复原身份、引用消失后可回收代码但保留数据”。旧依赖的完整升级失败组合仍须专项核对。

## 数据恢复路径

当前选用并存版本，目录结构为 `plugin-data/<pluginId>/<installationId>/v1/<instanceId>`，包代码位于另一目录。`v1` 是宿主管理的存储格式与所有者标记，不代表任意插件业务数据都互相兼容。

切回旧 release 后继续使用其旧目录；不把新版目录覆盖到旧目录。新版目录保留供诊断或插件专门的数据迁移工具处理。当前没有通用的跨 release 数据导入、共享数据迁移或一键数据备份恢复接口，不能把手工复制目录描述为已支持的迁移。

代码回滚不会撤销插件已经对工作区或外部系统造成的副作用；写入结果与审批记录继续由宿主历史保留，按具体操作的恢复能力处理。

## 已实现：候选初始化后提交绑定

替换已有能力绑定时，宿主将新选择写入 `capability_binding_candidates`，保留原 `capability_provider_bindings`。选择本身不启动 runtime。下一次调用使用候选的权限、输入契约和审批上下文；写能力仍在持久准入、可信批准与上下文复核之后才运行依赖探测和子进程。

候选成功完成 `capability.initialize` 的协议、插件、release、generation 与操作协商后，宿主才在事务中删除候选并更新绑定，然后发送业务调用。初始化崩溃、不兼容或超时会删除该候选并保留旧绑定，本次请求明确失败，不在同一请求里偷偷调用旧版。后续新的请求可使用原绑定；写入的失败请求继续按持久记录重放 `outcome_unknown`，不能因旧绑定恢复而重新执行。

这里的提交点是 runtime 初始化成功，不是业务操作成功。已通过初始化的新版若在业务操作中失败，不会因此自动回退代码或重做操作。首次选择没有旧绑定可保留，仍直接建立初始选择；候选机制处理已有绑定的替换。

每次重新选择生成独立 candidate ID，进入写入审批上下文。过时的初始化完成或失败只能操作自己的 ID，不能提交或删除后来的选择。宿主启动恢复清理尚未提交的候选，原绑定与历史保留；用户需重新选择才能再尝试该新版。候选 release 同样计入代码回收引用。

新增回归覆盖：真实子进程初始化崩溃、不兼容和超时；成功初始化提交绑定；写候选在拒绝批准时无启动或版本探测，批准后失败保留原绑定，重复失败请求不执行旧版；重新选择后的旧候选无法提交或删除新选择，以及启动恢复撤销候选。

## 尚待核对

P5 仍需完成旧依赖保留的升级组合、原生宿主恢复复验及整体退出核对。候选实现与上述回归尚不能替代全部 release 退出证据，因此清单整项保持待完成。
