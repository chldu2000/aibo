# Presentation 插件重构

目标确认于 2026-09-13。决策依据：[ADR-0008](adr/0008-unified-presentation-plugins.md)。

## 产品目标

用户通过一个皮肤插件入口安装、选择、升级、禁用和卸载 Presentation 包。同一包可以只定制主题，也可以提供控件、语义视图和整个工作台；宿主补全未提供的范围。shadcn 与 Material 3 最终作为可独立构建的包验证这条路径，宿主始终保留可用的默认呈现。

成功标准不是移动文件或改名：仓库外构建的包必须能进入实际 App，切换后生效，并且能升级、卸载和从故障中恢复。

## 必须保持的约束

- 会话、草稿、导航、历史与执行结果由宿主持有；呈现卸载不删除业务数据。
- 插件发出语义动作，宿主验证权限、上下文和代际后执行。审批及恢复入口不受可替换代码控制。
- UiKitAdapter 仍是完整内部合同；插件可以省略定制，宿主组合后不能缺少必需控件或核心语义。
- 应用层仅通过 UI kit 使用视觉实现，不按插件或皮肤 ID 分支，不引入视觉 CSS。
- 能力插件无需为换皮肤修改业务协议。新业务数据需求单独进行兼容演进。
- 不把同 WebView 执行或 CSS 作用域宣称为安全隔离。外部可执行包上线前必须确定信任模型及验证证据。

## 实施阶段与验收

### P0：统一术语与内置注册

- [x] 记录统一产品概念、ADR 与本实施文档。
- [x] 建立本地 Presentation 定义与默认继承，现有外观入口消费统一注册。
- [x] 验证主题独立定制、控件继承与不合法主题拒绝；保持双皮肤构建及架构门禁通过。

### P1：稳定包合同与加载设计

- [x] 定义版本化纯数据 manifest、包身份、入口、资源清单、完整性和宿主兼容声明。
- [x] 区分发布版本、可执行接口版本、核心语义版本和快照版本。
- [x] 决定可执行代码的信任与隔离方式，覆盖网络、文件、IPC、样式及资源权限；记录 ADR。
- [x] 定义主题、控件、renderer、工作台的缺省继承及兼容规则，不增加第二插件类型。

### P2：宿主安装与运行生命周期

- [ ] 实现外部包发现、验证、安装、启用、切换、禁用、卸载与升级。
- [ ] 候选加载成功后提交选择；失败恢复上一可用版本或内置默认呈现。
- [ ] 单一选择驱动主题、控件和工作台；持久化选择并迁移旧外观设置。
- [ ] 处理迟到动作、资源释放、重复切换、重启、丢失包和损坏包。
- [ ] 固定管理、审批与恢复区域在恶意或故障呈现下保持可达。

### P3：迁移内置实现并开放外部开发

- [ ] shadcn 与 Material 3 迁为独立构建包，提取资源与样式并消除宿主源码依赖。
- [ ] 提供纯主题和完整呈现两种样例，使用同一包合同和安装入口。
- [ ] 完成开发文档、打包工具与仓库外构建、安装、展示、升级、卸载验收。

### P4：回归与退出审计

- [ ] 实际 App 验证双皮肤、布局、核心语义、键盘、焦点、滚动、草稿和会话保留。
- [ ] 验证不兼容、初始化失败、运行故障、升级失败、卸载和重启恢复。
- [ ] 每次交付运行 `pnpm run verify`；涉及原生生命周期时补充对应 Rust 与真实 App 检查。
- [ ] 更新 UI 架构与插件支持矩阵，注明实际平台证据，不将内置模块注册当作外部加载完成。
