# 工作区偏好与宿主操作确认

本文件定义新增工作区的信任设置、宿主操作确认策略与持久化行为；整体 UI 边界见 [UI 架构](ui-architecture.md)。

宿主“工作台设置 → 工作区”提供“新增工作区默认信任”，初始开启。
原生 `workspace_preferences` 单例表保存该偏好，`read_workspace_preferences` /
`save_workspace_preferences` 只由宿主管理界面调用。界面仅在原生保存成功后确认开关值；
读取失败时禁止修改并提供重试，浏览器预览不保存原生设置。

`add_workspace` 在插入时直接读取这项数据库偏好；所有添加入口共用此行为，不接收呈现插件传来的信任值。
迁移、修改偏好、重复添加已有目录均不改变已有工作区的信任或权限代际。单个目录仍可在“更多”中调整信任，
上下文保留信任说明，侧栏名称旁不再显示状态圆点。默认信任不替代运行时能力、执行配置或逐操作审批检查。

`test/workspace-preferences.test.mjs` 验证读取、保存、失败回退和异步竞争；
`probes/workspace-preferences-browser.mjs` 验证真实 App 的开关与创建入口（替身 IPC）；
Rust `workspace_preferences::tests` 使用临时 SQLite 数据库验证迁移、重启、重复添加和手动撤销后的状态保留。

## 宿主操作确认

“工作台设置 → 工作区”在信任设置下方提供“宿主操作确认”。Git 操作、工程动作、
恢复本轮变更、插件能力写入、插件视图写入分别选择“始终允许”或“每次询问”。
五项均为应用级设置，适用于所有工作区；新安装和升级安装的初始值均为“始终允许”。
归档和会话树切换等普通确认、插件启用与 Agent 会话权限审批不属于此设置。

迁移 0053 新建 `host_confirmation_preferences`，不改动已有工作区信任、权限代际或
会话执行配置。管理界面通过 `read_host_confirmation_preferences` 读取，通过
`save_host_confirmation_preference` 单独保存一项；并发修改其他类别不会被覆盖，
同类别以最后成功保存为准。保存后返回全部当前值，界面只显示宿主确认后的结果。
设置每次打开重新读取，读取失败禁用编辑并提供重试；预览模式不保存。

原生宿主在进入操作确认阶段时读取对应类别的数据库策略，不接受动作或插件传来的批准值。
“始终允许”自动作出该次确认决定；“每次询问”显示原有原生弹窗，保留取消、超时与拒绝行为。
改变设置适用于后续进入确认阶段的请求，不自动批准已经打开的弹窗。数据库读取失败拒绝执行，
不回退到允许。只读能力调用不进入此流程，Agent 会话及其工具审批继续使用原有会话权限路径。

自动允许仍经过原有工作区信任、路径边界、插件权限、状态复核、互斥、请求去重、取消与持久化执行记录。
执行记录中的 `approved` 表示宿主准入成功，可能来自设置自动允许或手动确认，不代表一定显示过弹窗。
同一请求重放只读取原有结果，不会因策略变化重新执行。

`test/host-confirmation.test.mjs` 覆盖界面状态和异步竞争；
`probes/host-confirmation-browser.mjs` 验证设置入口、独立保存、重载、失败重试和浅深主题（替身 IPC）；
Rust `host_confirmation::tests` 覆盖默认值、迁移、SQLite 重启持久化、按类别询问与真实 Git 的执行、拒绝、重放和信任门禁。

`probes/host-confirmation-native.mjs` 使用隔离的应用标识、临时仓库与仅限测试进程的原生弹窗点击，
验证默认 Git 暂存/提交与工程动作直接执行、询问模式的取消/允许、类别独立及信任撤销。
浏览器探针验证键盘焦点可达；macOS 无头 Chromium 的原生 select 方向键提交在独立最小页面也不可用，
因此选项保存由 `selectOption` 验证，不将其视为真实键盘弹出菜单的验收。
