# P4 第三十五批：实际工作台重排与宽度调整

新增 review 布局：辅助区域在左、会话主内容居中、导航在右。标准、专注和 review 的槽位顺序均由可信呈现模块决定；布局按窗口保存，独立恢复按钮和快捷键返回标准布局。

重排暴露了 App 列宽逻辑中“导航固定在左、辅助固定在右”的假定。本批以槽位上下文传递实际增长方向，鼠标与键盘调整都使用该方向。重新挂载工作台会清理旧拖动监听，避免恢复布局后旧指针事件继续改变宽度。辅助面板关闭时，导航最大宽度不再预留不可见辅助面板的空间。

`pnpm run verify` 通过：25 项架构测试、类型检查、165 项 Node 测试及生产构建。

## 证据

`node probes/workbench-reorder.mjs` 加载实际 App 浏览器预览，在两套皮肤下检查：

- 导航的实际坐标移到右侧。
- 两侧分隔条的箭头键和鼠标方向均正确。
- 拖动中通过宿主快捷键恢复布局，旧拖动停止。
- 页面重载保留 review，恢复默认按钮仍可用。

[重排证据](./baselines/plugin-platform-p4/workbench-reorder-browser.json)。探针请求 reduced-motion，但本批不把该设置本身视为所有动画规则已经通过验证。

重新运行核心语义浏览器探针，覆盖 collection/detail/settings/inspector、两套皮肤、中央/侧栏、键盘操作、返回焦点、空/错误/加载/截断状态，以及工作区隔离和恢复；[结果](./baselines/plugin-platform-p4/core-semantic-views-browser.json)。旧探针对详情固定 textarea 的断言已更新为识别核心文本框或专业只读文本框。

工作台生命周期探针继续通过，覆盖草稿、插件表单、流式更新、焦点、失败回退及旧回调拒绝。这里是浏览器证据，不等同于原生桌面完整退出矩阵；P4 的整体验收仍未完成。
