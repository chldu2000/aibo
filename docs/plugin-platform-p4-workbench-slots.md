# P4 第三十三批：默认工作台命名槽位

App 原先传入整个 main 和浮层，呈现模块通过业务组件 CSS 类名隐藏区域。这使布局所有权仍留在 App 内。本批将导航、主内容、辅助区域、两个宽度调整控件和浮层拆成六个命名槽位，工作台 main 与列装配由呈现模块持有。

标准布局按默认呈现模块定义的顺序装配实际存在的槽位。专注布局只装配主内容，浮层仍可达。恢复默认会重新装配导航和辅助区域。宽度、当前会话、草稿及执行状态仍归宿主；槽位只接收已校验的回调门，不获得运行 Agent 或可信审批的入口。

接口为可信构建中的 Svelte 本地接口，不进入纯数据能力 SDK，不是任意安装包注册前端代码的通道。没有将 UiKitAdapter 的必需成员改为 optional。

`pnpm run verify` 通过：25 项架构测试、类型检查、163 项 Node 测试和生产构建。

验证：

- 架构测试逐个识别六个槽位，检查内部回调与可写绑定的上下文/代际门，同时检查独立宿主区域。
- `node probes/workbench-lifecycle.mjs` 在两套皮肤下验证标准 → 专注 → 恢复，导航和辅助区域确实卸载/重新装配，浮层操作保持可达。
- 同一探针继续验证挂载失败回退、草稿和插件表单状态、焦点恢复、流式更新、旧代际与旧会话回调拒绝。
- [浏览器证据](./baselines/plugin-platform-p4/workbench-slots-browser.json)。本批没有原生桌面槽位验收证据，不将浏览器结果宣称为完整桌面退出验收。

P4 仍需真实专业呈现及其核心语义降级、更多整体布局和完整键盘/无障碍退出矩阵。本批完成默认工作台的结构迁移，不单独宣告 P4 完成。
