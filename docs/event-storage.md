# 事件存储策略

本规范落实 [ADR 0010](adr/0010-event-storage-and-search.md)。首批迁移为 0066；下表区分目标策略与当前保留行为，避免将尚未实现的清理描述为已经生效。

| 数据用途 | 目标策略 | 当前实施 |
| --- | --- | --- |
| 业务历史 | 消息、工具结果、子代理消息与重要变化随会话保留 | 原表保留，不删除原始 agent_events |
| 授权与操作事实 | 独立保存批准依据、执行身份、目标、结果、因果关联 | 审批、写入、迁移记录及能力审计全部保留 |
| 恢复与可靠投递 | 活动操作和未知结果不得清理，责任结束后才可压缩 | 绑定、队列、投递证据、调用及序号行为不变 |
| 过程与诊断 | 有时间和容量上限，失败可延长诊断窗口 | 本批不新增原始事件自动过期策略 |
| 重复观察 | 最新状态、变化记录、聚合计数，异常另存 | 本批只停止完整调用事件的搜索复制，不删除观察审计 |
| 搜索投影 | 可重建，只索引用户需要查找的内容 | 能力调用摘要可搜索；原始能力事件 JSON 不索引 |

## 生产与消费

- Broker 持久化能力调用，生命周期触发器及流事件写入 capability_events。审计历史和游标接口继续读取它；窗口身份由可信 IPC 注入。
- SessionHost 原子提交消息/会话状态和 agent_events 后才发布事件。主会话历史读取 messages，子代理历史及分叉仍读取 agent_events，审批校验与上下文重置也有事件读取。
- Broker 回合结束时先撤下控制入口，等待已准入控制返回，再进行写调用的进程清理。暂停等控制可能自行结束回合，不能靠搜索写入延迟保证控制确认先于插件停止。
- 全局搜索只读取 search_documents/FTS 派生数据；能力调用保留原有标题、状态和作用域摘要。事件正文中的词不再命中全局搜索，事件详情通过能力调用历史查看。
- 0066 移除能力事件的搜索触发器和已有派生行；重建 FTS，保留其余来源的插入、更新和删除同步。search_file_state 与已有文档 rowid 均保持稳定。

## 后续减少原始事件的准入条件

1. 子代理消息具有独立持久投影，保留首次顺序、最新正文、终态、会话/Agent/消息身份和分叉语义；不能因一次 streaming 快照过期丢失正文。
2. 审批、上下文重置、恢复位置、幂等依据、序号高水位脱离可清理的原始事件。不得使用清理后可能回退的 MAX(sequence) 分配新序号。
3. 观察分类由宿主校验的合同和实际输入确定；同一 goal.manage 中的读取与修改分开。未知第三方合同保守保留，不能只检查 capability 名称后缀或 effect=read。
4. 清理只处理已完成且无恢复、授权、调用链或其他业务引用的明细；活动、未知结果、父子调用引用必须保护。支持崩溃后重试和小批次执行。
5. 持久分页接口明确返回历史保留起点/游标过期，不能把已清理的数据冒充“从未发生”。产品界面明确展示可用历史范围。
6. 保留期限、容量上限与例外需单独确定并验证，再追加迁移；旧数据不能凭推测归类后批量销毁。

## 升级与空间回收

新建数据库和历史库通过真实 open_database 执行追加迁移。0066 在单个 SQLx 迁移事务内撤销旧 FTS 同步触发器、移除旧 FTS、删除能力事件搜索副本、创建并重建新 FTS、恢复同步触发器。先移除派生索引，避免逐条删除百万级事件时为旧索引生成无用删除项。

不改写业务正文、事件 JSON、授权、绑定、草稿或已有迁移记录。重复打开不重复重建。新旧 0051 版本仍经已有精确 checksum 兼容路径收敛。

迁移后空闲页可供后续写入使用。文件大小和逻辑占用必须分别报告。启动不自动 VACUUM；需要缩小文件时在应用关闭后备份、验证备份，再执行独立维护及完整性检查。开发启动仍只迁移 development 数据目录，不触碰正式库。

## 验证要求

- 从冻结的 0065 及之前迁移建库，写入原始调用/事件、用户消息、草稿、子代理历史和文件缓存，再通过 open_database 升级、重开。
- 校验原始数据与旧 checksum 保持、原始审计可读、窗口隔离保持；只有事件 JSON 搜索命中消失，调用摘要及其他历史内容继续命中。
- 校验新调用及新事件不恢复旧搜索副本，其他来源的插入/更新/删除同步正常，FTS 与外键/完整性检查通过。
- 执行 pnpm run verify、pnpm run test:migrations 和完整 Rust 库测试。
- `goal_resume_and_pause_use_host_execution_ownership_and_policy` 覆盖恢复后立即暂停；索引写入减少后该路径暴露了控制确认被进程清理抢先中止的竞争，Broker 必须等待已准入控制完成。
