# Aibo ak-ui 现行界面规范

本文件记录 Aibo 默认工作台已确认的 ak-ui **system** 强度规则，适用于当前唯一注册的内置 `ak-ui` kit 的浅色和深色主题。它是 Aibo 的产品规范，不改写通用 ak-ui 令牌或公开的 `UiKitAdapter` 合同。[改版设计稿](ak-ui-redesign.html)是初版交互示例，[修复进度](ak-ui-repair-progress.md)是按时间记录的实施过程；两者与此处冲突时，以此处的后续决定为准。架构和实现边界见 [UI 架构](../ui-architecture.md)。

## 密度与排布

| 区域 | 可见尺寸 | 规则 |
| --- | --- | --- |
| 工作区、会话行、页签、工具组摘要 | 至少 44px 高 | 保持文字和状态可读，不套用 Git 文件行密度。 |
| Git 仓库选择、提交输入、分支创建输入 | 36px 高 | 保留 ak-form 的边框和焦点反馈。 |
| Git 刷新、分支同步、审查、提交等紧凑按钮 | 32px 高 | 已实现的工具栏按钮用外扩区域增加命中高度；可见高度不等于点击区域。 |
| Git 文件分组与暂存栈标题、文件行 | 36px 高 | 标题带通栏色带，文件行单行排布；分组标题的 1px 边线计入总高度。 |
| Git 文件状态标记 | 18px 方形 | 与 36px 文件行配套，不沿用其他列表的 24px 标记。 |
| Git 提交历史 | 两行、至少 44px 高 | 提交标题与相对时间在第一行，短哈希、作者在第二行；高度随内容保持可读。 |

上述是组件角色尺寸，不修改全局 `--ak-density-control-height: 44px`。菜单项等未列出的普通交互控件继续遵守其现有点击区域要求。Git 文件行目前实际只有 36px 高，不能把工具栏已实现的外扩命中区域推论为文件行也满足 44px 触屏点击区域。

Git 面板从上到下为仓库选择/刷新、分支/上游/同步、变更/历史/Agent 审查、提交输入、文件分组；暂存栈在文件列表之后。单仓库仍显示选择器。提交输入常驻变更页，没有已暂存文件时禁用提交。面板窄时优先保留文件名和操作，目录从左侧截断，增删统计有数据才显示；完整路径通过提示和操作的可访问名称获取。

## 状态与交互

- 会话仅在运行、启动、压缩等活动执行状态绘制圆环动效；其余状态只改变 Agent 图标颜色。条目不显示“空闲”“运行中”等常态文案。待审批、待输入、失败、已中断等阻塞或异常状态显示标签并占用时间位置；其他状态显示相对时间。所有状态在条目和状态标记的可访问名称、悬浮提示中保留文字；减少动态效果时圆环静止。
- 标签页选中使用底部信号条和文字强调；列表及导航选中使用左侧信号条与底色；`aria-pressed` 开关只使用选中底色。普通按钮悬停仅改变底色或文字，不绘制下方信号条；键盘焦点仍有独立可见反馈。
- Git 文件行和提交历史由整行负责悬停反馈。文件内部的差异按钮、历史内部按钮不得再绘制第二条悬停信号；选中行的左侧信号条与底色在悬停时保持。历史条目通栏排布，以细边线分隔。
- Git“更改”“未跟踪的文件”等分组平时显示数量；鼠标悬停或键盘焦点进入标题时，批量暂存按钮在同一位置覆盖数量，避免标题宽度跳动。已暂存分组提供对应的取消暂存操作。文件行的“暂存/取消暂存”使用文字按钮。
- 历史提交标题过长时在相对时间前省略；时间不被挤出面板。第二行短哈希和作者保留，作者过长时省略。标题与时间保留完整值提示，按钮可访问名称保留完整提交标题。
- 提交历史展开文件与 Git/会话变更列表共用 `FileChangeMark`：18px 直角细边框，M/A/D/R/U 对应修改/新增/删除/重命名/冲突，文字及颜色由 UI kit 统一定义。历史文件采用 36px 通栏直角行、文件名与弱化目录分列；粗指针设备为 44px。重命名前后的完整路径和查看提交差异操作保持可达。

## 会话阅读区

- 沿用设计稿的 760px 阅读栏、24px 消息间距和 14/13/12px 正文、界面、元信息层级。用户正文采用四边 1px 细线、raised 底色、12×16px 内边距；助手正文直接排在画布上。二级标题为 17px/650，列表项间距为 4px。
- 用户和助手消息头显示真实创建时间；助手图标和名称来自会话绑定的插件声明，声明缺失时保留通用图标和身份回退。分支操作保持可访问，不撑高消息头；桌面悬停或键盘焦点进入消息时显示，触屏常显。
- 连续工具记录保持现有分组和完整输出，外框为四边 1px 细线。摘要显示展开箭头、终端图标、数量、失败/进行中/中断统计。展开行显示状态符号、工具名、内容首行预览及可用耗时，原始调用参数、输出和 diff 仍可展开。内容预览不是从工具输出猜测出的文件路径。
- 工具耗时来自记录创建至最后更新的完整正向间隔，并非提供者报告的执行时间。仅当组内每条记录都有完整且已结束的间隔时显示累计值；缺失、无效、快照同刻或仍进行中的记录不显示虚构耗时。重叠记录的累计值不代表整组墙钟时间，提示说明其含义。
- 运行提示放在消息流末尾，采用无框文字行和 Agent 状态标记。运行环为蓝色，待审批/待输入不旋转；减少动态效果时圆环静止。保留宿主的真实活动文案；设计稿中的文件名、42s 等示例不是固定内容。尚无消息时仍保留活动提示。
- 阅读历史时活动变化不抢回底部；窄窗口允许正文和摘要换行，工具内容单行省略并提供完整提示，输入区独立保持可见。

## 所有权与验收

会话“变更”标签页沿用上述阅读栏，文件列表按以下规则呈现：

- 列表最大宽度 760px，桌面文件行 36px；粗指针设备增至 44px。单仓库省去仓库标题，多仓库保留名称、目录和各自文件数量。顶部只保留简短的工作区范围说明与刷新入口。
- 文件行显示 18px 状态方块（M/A/D/R/U）、文件名、弱化的目录及可用的增删统计。目录优先从左侧省略，文件名保留独立空间；完整路径、重命名前路径和暂存状态通过提示及可访问名称保留。
- 文件整行是展开按钮，Enter/Space 与点击一致；展开时使用左侧蓝色信号条和选中底色。预览直接放在该行下方，重复点击收起，打开其他文件切换唯一的预览。关闭预览后焦点回到对应文件行。
- 移除行尾“查看暂存/未暂存差异”按钮。仅暂存的文件直接打开暂存区，其余文件默认打开工作区；部分暂存文件在展开区提供“工作区/暂存区”切换。加载、错误、二进制等不可展示原因都留在该文件下方。
- 展开身份包含仓库与文件路径；切换会话/工作区、关闭或重新选择后，迟到读取不得恢复旧预览。刷新时关闭预览，后台更新删除文件或改变可用来源时清理或切换预览。
- 标签数量仅在仓库扫描完整且各仓库均成功读取时显示，按仓库内文件计数。增删数缺失时省略；部分暂存文件仅在两部分统计都可用时显示合计，并注明它不是净差异。冲突文件不展示未经确认的行数。

应用组件传递语义数据、状态和动作；共享 `base.css` 保留外部呈现及缺失 surface 的布局回退；`ak-ui.css` 负责默认 kit 的颜色、几何、密度和交互视觉。不要以应用层 CSS 或通用按钮规则覆盖文件/历史行的专用状态，也不要为这些局部紧凑控件改写全局密度令牌。

桌面改动至少检查浅色与深色主题、窄 Inspector、长中英文文件名与提交标题，以及默认/悬停/键盘焦点/选中/禁用/减少动态效果状态。涉及共享边界时还需检查外部呈现的继承和故障回退；回归入口见 [UI 架构](../ui-architecture.md)和[回归要求](../plugin-boundaries-and-regression.md)。

移动端与触屏密度仍是待完成的独立验收项：Git 文件行只有 36px，分组批量按钮依赖悬停或焦点显现。需要检查触屏下这些操作能否发现、触及且不误触，并决定是否调整命中区域或展示方式；在完成前不要宣称整个 Git 面板满足 44px 触屏目标。设计稿中“内容区大约多出 150px”也不是固定验收承诺。
