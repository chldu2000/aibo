# Aibo ak-ui 现行界面规范

本文件记录 Aibo 默认工作台已确认的 ak-ui **system** 强度规则，适用于当前唯一注册的内置 `ak-ui` kit 的浅色和深色主题。它是 Aibo 的产品规范，不改写通用 ak-ui 令牌或公开的 `UiKitAdapter` 合同。[改版设计稿](ak-ui-redesign.html)是初版交互示例，[修复进度](ak-ui-repair-progress.md)是按时间记录的实施过程；两者与此处冲突时，以此处的后续决定为准。架构和实现边界见 [UI 架构](../ui-architecture.md)。

## 密度与排布

| 区域 | 可见尺寸 | 规则 |
| --- | --- | --- |
| 工作区、会话行、页签、工具组摘要 | 至少 44px 高 | 保持文字和状态可读，不套用 Git 文件行密度。 |
| Git 仓库选择、提交输入、分支创建输入 | 36px 高 | 保留 ak-form 的边框和焦点反馈。 |
| Git 刷新、分支同步、审查、提交等紧凑按钮 | 32px 高 | 已实现的工具栏按钮用外扩区域增加命中高度；可见高度不等于点击区域。 |
| Git 文件分组与暂存栈标题、文件行 | 36px 高 | 标题带通栏色带，文件行单行排布；分组标题的 1px 边线计入总高度。 |
| Git 文件状态标记 | 18px 方形 | 与 36px 文件行配套，不沿用其他列表的 24px 标记。 |
| Git 提交历史 | 两行、至少 44px 高 | 提交标题与相对时间在第一行，短哈希、作者在第二行；高度随内容保持可读。 |

上述是组件角色尺寸，不修改全局 `--ak-density-control-height: 44px`。菜单项等未列出的普通交互控件继续遵守其现有点击区域要求。Git 文件行目前实际只有 36px 高，不能把工具栏已实现的外扩命中区域推论为文件行也满足 44px 触屏点击区域。

Git 面板从上到下为仓库选择/刷新、分支/上游/同步、变更/历史/Agent 审查、提交输入、文件分组；暂存栈在文件列表之后。单仓库仍显示选择器。提交输入常驻变更页，没有已暂存文件时禁用提交。面板窄时优先保留文件名和操作，目录从左侧截断，增删统计有数据才显示；完整路径通过提示和操作的可访问名称获取。

## 状态与交互

- 会话仅在运行、启动、压缩等活动执行状态绘制圆环动效；其余状态只改变 Agent 图标颜色。条目不显示“空闲”“运行中”等常态文案。待审批、待输入、失败、已中断等阻塞或异常状态显示标签并占用时间位置；其他状态显示相对时间。所有状态在条目和状态标记的可访问名称、悬浮提示中保留文字；减少动态效果时圆环静止。
- 标签页选中使用底部信号条和文字强调；列表及导航选中使用左侧信号条与底色；`aria-pressed` 开关只使用选中底色。普通按钮悬停仅改变底色或文字，不绘制下方信号条；键盘焦点仍有独立可见反馈。
- Git 文件行和提交历史由整行负责悬停反馈。文件内部的差异按钮、历史内部按钮不得再绘制第二条悬停信号；选中行的左侧信号条与底色在悬停时保持。历史条目通栏排布，以细边线分隔。
- Git“更改”“未跟踪的文件”等分组平时显示数量；鼠标悬停或键盘焦点进入标题时，批量暂存按钮在同一位置覆盖数量，避免标题宽度跳动。已暂存分组提供对应的取消暂存操作。文件行的“暂存/取消暂存”使用文字按钮。
- 历史提交标题过长时在相对时间前省略；时间不被挤出面板。第二行短哈希和作者保留，作者过长时省略。标题与时间保留完整值提示，按钮可访问名称保留完整提交标题。
- 提交历史展开文件与 Git/会话变更列表共用 `FileChangeMark`：18px 直角细边框，M/A/D/R/U 对应修改/新增/删除/重命名/冲突，文字及颜色由 UI kit 统一定义。历史文件采用 36px 通栏直角行、文件名与弱化目录分列；粗指针设备为 44px。重命名前后的完整路径和查看提交差异操作保持可达。

## 会话阅读区

- 标题栏操作按状态、分支/会话树、专注会话排列，不显示远端对话轮数。状态采用无框的 8px 方形信号点与 12px 文字；活动执行状态使用蓝色信号点轻微闪动，等待状态为警告色，失败/中断为危险色，其余为中性色。减少动态效果时信号点静止。
- 沿用设计稿的 760px 阅读栏、24px 消息间距和 14/13/12px 正文、界面、元信息层级。用户正文采用四边 1px 细线、raised 底色、12×16px 内边距；助手正文直接排在画布上。二级标题为 17px/650，列表项间距为 4px。
- 用户和助手消息头显示真实创建时间；助手图标和名称来自会话绑定的插件声明，声明缺失时保留通用图标和身份回退。分支操作保持可访问，不撑高消息头；桌面悬停或键盘焦点进入消息时显示，触屏常显。
- 连续工具记录保持现有分组和完整输出，外框为四边 1px 细线。摘要显示展开箭头、终端图标、数量、失败/进行中/中断统计。展开行显示状态符号、工具名、内容首行预览及可用耗时，原始调用参数、输出和 diff 仍可展开。内容预览不是从工具输出猜测出的文件路径。
- 工具耗时来自记录创建至最后更新的完整正向间隔，并非提供者报告的执行时间。仅当组内每条记录都有完整且已结束的间隔时显示累计值；缺失、无效、快照同刻或仍进行中的记录不显示虚构耗时。重叠记录的累计值不代表整组墙钟时间，提示说明其含义。
- 运行提示放在消息流末尾，采用无框文字行和 Agent 状态标记。运行环为蓝色，待审批/待输入不旋转；减少动态效果时圆环静止。保留宿主的真实活动文案；设计稿中的文件名、42s 等示例不是固定内容。尚无消息时仍保留活动提示。
- 阅读历史时活动变化不抢回底部；窄窗口允许正文和摘要换行，工具内容单行省略并提供完整提示，输入区独立保持可见。

## 会话变更列表

会话“变更”标签页沿用上述阅读栏，文件列表按以下规则呈现：

- 列表最大宽度 760px，桌面文件行 36px；粗指针设备增至 44px。单仓库省去仓库标题，多仓库保留名称、目录和各自文件数量。顶部只保留简短的工作区范围说明与刷新入口。
- 文件行显示 18px 状态方块（M/A/D/R/U）、文件名、弱化的目录及可用的增删统计。目录优先从左侧省略，文件名保留独立空间；完整路径、重命名前路径和暂存状态通过提示及可访问名称保留。
- 文件整行是展开按钮，Enter/Space 与点击一致；展开时使用左侧蓝色信号条和选中底色。预览直接放在该行下方，重复点击收起，打开其他文件切换唯一的预览。关闭预览后焦点回到对应文件行。
- 移除行尾“查看暂存/未暂存差异”按钮。仅暂存的文件直接打开暂存区，其余文件默认打开工作区；部分暂存文件在展开区提供“工作区/暂存区”切换。加载、错误、二进制等不可展示原因都留在该文件下方。
- 展开身份包含仓库与文件路径；切换会话/工作区、关闭或重新选择后，迟到读取不得恢复旧预览。刷新时关闭预览，后台更新删除文件或改变可用来源时清理或切换预览。
- 标签数量仅在仓库扫描完整且各仓库均成功读取时显示，按仓库内文件计数。增删数缺失时省略；部分暂存文件仅在两部分统计都可用时显示合计，并注明它不是净差异。冲突文件不展示未经确认的行数。

## 表面、文字与图标

- 默认使用 ak-ui system 强度。导航、阅读区、上下文与管理区域在每个主题下保持统一明暗；canvas 承载阅读区，muted 区分导航与分组，panel 承载内容，raised 区分编辑器和浮层。
- 颜色、字体、间距和几何来源为 `src/lib/ui-kit/kits/ak-ui/themes.json`；`ak-ui.css` 通过已打包的 ak-ui 令牌映射语义角色，不写原始色值。画布浅/深底为 `#e9ebe7` / `#111315`；信息蓝、主操作黄使用 `--ak-color-blue` / `--ak-color-yellow`，浅色焦点及蓝色文字使用 `--ak-color-dark-blue`，黄底按钮配深色文字。
- 选中与焦点、主操作、警告、成功、危险使用各自语义。已信任工作区使用成功语义，变更计数使用中性徽标；状态同时保留文字或图标，不仅靠颜色辨认。
- 正文、控件、元信息分别使用 `--aibo-type-body`、`--aibo-type-ui`、`--aibo-type-meta`，`base.css` 提供同值回退。皮肤 CSS 与组件字号不得小于 12px；标题层级沿用阅读区规则。
- 语义图标采用 24 单位网格、1.6 单位描边并继承文字颜色；发送为上箭头、插件为四格、设置为矩形滑块。Agent 品牌路径来自插件声明，kit 不维护品牌映射；按钮保留可访问名称。
- 不使用全局 `*` transition 覆盖。`ak-ui.css` 的同一媒体条件只出现一次，响应式声明排在会覆盖它的同选择器无条件声明之后；样式边界测试检查这些约束。

## 导航、上下文与响应式

- 侧栏以新建会话开始，不显示 Logo 或标语。工作区和会话行通栏排布，3px 选中信号条贴面板边缘；侧栏不留内边距，新建会话按钮留 12px 外边距，会话的 28px 缩进放在行自身。
- 每行预留真实 44px“更多”按钮，悬停、键盘聚焦和菜单打开时显示，触屏常显；名称不被操作覆盖，也不因悬停改变宽度。“在此新建会话”位于工作区菜单。
- 行内任意位置（含“更多”区域）触发整行 `--aibo-hover` 反馈，内部按钮不叠加底色或底部信号线；选中行悬停保留选中底色和左侧信号条。共享层与侧栏同色的 hover 值不能替代可见反馈。
- 次要操作使用原生 Popover 顶层菜单，避免滚动裁剪；Escape 返回触发器，点击外部关闭。Agent 选择器对齐触发器下沿；可展示不可用提供者及原因，但禁用其创建入口。
- 工作区/会话的“更多”菜单宽 240px、内边距 4px，使用 raised 表面、细边框和面板阴影；菜单项至少 44px 高，13px 文字、18px 图标、12px 水平内边距与图文间距。工作区依次为新建会话、打开目录、信任操作，分隔线后为危险色的移除操作；会话先显示改名与可用的读取线程操作，分隔线后为归档/取消归档。悬停只改变底色，键盘焦点在行内显示。
- “新建会话”的 Agent 选择菜单沿用 240px 宽、4px 内边距及细边框，不使用顶部强调线或单独的关闭行。标题显示目标工作区；选项至少 44px 高，20px 图标区域配 13px 名称和 12px 就绪状态/不可用原因。禁用项保持透明底色并禁止创建；前九项中的可用项显示对应数字快捷键，上下方向键在可用项之间移动，Escape 返回入口。菜单左侧对齐入口，空间不足时向上展开，长列表在菜单内滚动。
- 新建会话按钮通过 `clip-path` 切角，键盘聚焦或禁用时取消裁剪以保留完整轮廓。
- Inspector 使用 panel 表面和左侧分隔线，标签条内缩 8px、等分标签。各分区通栏，分隔线通铺，内容 `8px 16px 16px`；上下文保持单层分区与 16px 水平边距，能力标签和内容分列，长标识截断但保留完整值提示。
- 工作台与 kit 共用 `max-width: 760px` 断点。窄屏在区域间切换时保留内容挂载；区域切换条无内缩、等分、13px。会话标题独占一行，视图标签另起一行并可横向滚动。
- 桌面会话头部约 64px；底部状态栏为 28px 纯文本行，窄屏隐藏。增加交互元素时需恢复相应点击区域要求。发送、头部工具和其他分区刷新等普通控件保持真实 44px，不套用 Git 紧凑按钮尺寸。
- 执行记录采用统一的状态、命令/工具、耗时、时间四列；命令列伸缩截断，展开后显示完整参数或输出。时间使用真实 `createdAt`，耗时沿用已结束记录的正向观测间隔，缺失时显示“—”；展开身份包含会话和条目。

## 表单与 Composer

- 表单采用 ak-form：方角、1px 边框与 4px 左侧边，聚焦时整圈焦点色加 3px 光晕；嵌入容器的输入由外容器显示焦点，避免双层边框。复选框、单选项保留原生或 ARIA 语义，开关保留轨道形状。
- 消息、Composer 及目标/用量/队列/重试等次级条共用 `--workbench-content-width` 阅读栏并居中；水平留白使用固定 `--workbench-content-inset`，不通过随视口变化的 `clamp()` 挤占栏宽。消息流用 grid 与单一 gap 控制节奏，条目不再叠加外边距。
- Composer 是整体表单字段，无切角或额外装饰条。自身无内边距，文本区 `12px 16px`、工具条 `4px 8px 8px`、附件条 `8px 12px 0`；手机端 Composer 左右各留 8px，消息流留 12px。
- 文本区使用 `field-sizing: content`，限制最大高度并保留内部滚动。附件为 32px 方角 raised 芯片、22px 缩略图、30px 移除按钮；显示名称与应用层格式化后传入的 `sizeLabel`，不另加上下文汇总行。手机附件单行横向滚动，不能导致页面横向溢出。
- `@` 引用由 `.composer-mention-layer` 镜像层按 `@` 到下一空白的规则渲染为标签；文本区字形透明，保留光标和选区，并同步滚动。镜像层与文本区的内边距、边框、字体、行高、换行和滚动条槽必须一致，标签不增加水平内边距。共享机制位于 `base.css`，ak-ui 负责适配盒模型与配色；`probes/composer-input-browser.mjs` 检查对齐和滚动。

## 设置中心与主题选择

- 「工作台设置」和「插件与能力」共用同一个宿主设置窗口，分别定位到「外观」和「插件与能力」。窗口统一标题为「工作台设置」。
- 左侧分为外观、布局、工作区、插件与能力、运行与诊断；前三项与管理工具间用分隔线区分，切换分类从内容顶部开始。
- 外观只选择主题和已启用皮肤，并提供恢复内置皮肤与「管理皮肤插件…」跳转。安装、启停、卸载能力插件和皮肤插件统一在插件页；快捷链接聚焦皮肤管理区域。
- 布局管理侧边位置，恢复标准布局保留皮肤；恢复内置皮肤保留布局；恢复默认工作台同时恢复内置皮肤与标准布局，保留会话和草稿。全局恢复快捷键仍由宿主保有。
- 工作区只管理新增工作区默认行为；单个目录信任仍由工作区入口调整。插件自有参数留在插件页，明确全局、项目或会话作用域，沿用继承与显式保存。
- 关闭和切换分类不提交插件表单；宿主保留当前运行中的配置草稿并提示未保存状态。外观和布局即时应用。
- 窄窗口分类自动换行，所有入口保持可见且至少 44px 高；内容区独立滚动，不缩小正文或导航点击区域。


- 单一内置 kit 显示信息行。主题使用铺满卡片的原生 radio，视觉隐藏但保留键盘焦点与 `:focus-within`；卡片 64px，只显示主题名与可见色板，选中由边框、左侧信号条和勾选表达。
- 管理中心尺寸为 `min(880px, 100vw - 32px) × min(620px, 100dvh - 64px)`，顶部 3px 信号边；标题单行 20px，不用 muted 底色，关闭按钮为真实 44px。导航为 44px 单标签行，内容区 `16px 24px 24px`；设置行高 56px、内边距 `8px 16px`、方角 raised 表面，正文 13px。
- 关闭通过右上角按钮或 Escape，不增加“完成”页脚。普通关闭恢复触发焦点；更换呈现期间由宿主接管焦点和选区恢复，包括异步激活尚未完成的情况。

## 所有权与验收

应用组件传递语义数据、状态和动作；共享样式、默认 kit 与外部呈现的所有权见 [UI 架构](../ui-architecture.md#布局与视觉边界)。不要以应用层 CSS 或通用按钮规则覆盖文件/历史行的专用状态，也不要为这些局部紧凑控件改写全局密度令牌。

桌面改动至少检查浅色与深色主题、窄 Inspector、长中英文文件名与提交标题，以及默认/悬停/键盘焦点/选中/禁用/减少动态效果状态。涉及共享边界时还需检查外部呈现的继承和故障回退；回归入口见 [UI 架构](../ui-architecture.md)和[回归要求](../plugin-boundaries-and-regression.md)。

移动端与触屏密度仍是待完成的独立验收项：Git 文件行只有 36px，分组批量按钮依赖悬停或焦点显现。需要检查触屏下这些操作能否发现、触及且不误触，并决定是否调整命中区域或展示方式；在完成前不要宣称整个 Git 面板满足 44px 触屏目标。设计稿中“内容区大约多出 150px”也不是固定验收承诺。
