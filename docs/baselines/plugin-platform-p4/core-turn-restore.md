# Core 整轮恢复验收

本批将整轮恢复接入宿主意图、原生审批、上下文复核、持久去重和取消。Git 与
非 Git 工作区均受支持；修改、新增、删除和重命名恢复后保留无关文件。整轮恢复
不修改 Git 暂存区，与整文件 Git 撤销的语义不同。

## 验证结果

- `cargo test --manifest-path src-tauri/Cargo.toml`：185 项通过。
- `pnpm run verify`：25 项架构检查、157 项 Node 测试、类型检查及构建通过。
- `node probes/core-hunk-native.mjs turn-git`：通过，见 [Git 原始结果](./core-turn-restore-git.json)。
- `node probes/core-hunk-native.mjs turn-plain`：通过，见 [非 Git 原始结果](./core-turn-restore-plain.json)。
- `node probes/execution-history-browser.mjs`：两套皮肤浏览 42 条混合记录、翻页、
  返回最新及切换工作区通过；这是组件/读取端口探针，不是原生恢复按钮验收。

## Rust 行为证据

真实仓库/目录、checkpoint 和 SQLite 证明恢复四类变更，Git 已暂存内容保持
原样。原请求成功后产生的用户新编辑不会被请求重放覆盖，恢复审计和系统消息
各写一次。旧版本 Git、非 Git 和重命名恢复测试继续经过新实现。

原生审批回调服务测试覆盖拒绝、持久取消、异窗口不能取消，以及确认期间文件、
变更元数据、checkpoint、信任和会话变化导致失效。整轮预检遇到任一冲突、脏
基线或损坏 checkpoint 时，不先恢复其他文件。Unix 目录链接在预检后改指向时，
执行前的 scope 复核阻止写入原目录和新目录。

执行器测试在第一文件完成后、第二文件前发出真实持久取消，或由上下文门返回
权限失效，证明部分结果保留，宿主写入记录为 outcome_unknown，旧审计包含已
完成路径及失败原因。这是受控的步骤间时序，不声称能强行中断单次内核写入。

消息插入失败的数据库触发器证明恢复审计与系统消息的事务原子性；文件已经
恢复时将审计失败记为结果未知，修复数据库后重放原请求也不会再次写文件。

## 原生桌面证据

两次运行使用独立应用 identifier、SQLite 数据库和临时工作区；非 Git 模式没有
初始化仓库，所有基线由应用数据目录中的 checkpoint 提供。fixture 只植入已
完成轮次，不启动 Agent，也不触碰用户工作区。

每次运行通过生产前端 API、Tauri IPC 和实际原生按钮，完成一次拒绝和一次批准。
外部探针逐个核对修改/新增/删除/重命名/无关文件；Git 模式额外比较整份 index
diff，证明没有改变暂存区。缺请求 ID 被拒绝，重复点击和重放不增加记录。
撤销信任后，宿主执行记录、旧恢复审计及只读 Core 系统消息仍可读取。

## 边界

当前保护不是跨进程锁或文件系统事务。多个文件与重命名两步可能部分完成，
外部进程仍可在复核后修改资源；取消/超时在下一步骤检查，当前文件系统操作
等待完成。进程崩溃时可能留下临时文件，启动恢复只标记未知、不自动回滚。
文件清单、预检时间和内容大小有明确限额，不将超限计划拆成未经批准的批次。

本批未验收任意第三方 Capability 写入、完整工作台布局装配、所有旧审计格式
浏览或跨平台权限恢复。主包仍有超过 500 KiB 的既有构建警告，未提高阈值。
