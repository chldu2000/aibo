# Core hunk 宿主写入验收

P4 第二十六批将局部暂存、取消暂存、撤销接入统一意图、审批、去重、取消和结果
记录。整文件撤销与整轮恢复不属于本批完成范围。

## 自动验证

- `cargo test --manifest-path src-tauri/Cargo.toml`：173 项通过。
- `pnpm run verify`：25 项架构检查、157 项 Node 测试、类型检查和构建通过。
- 新增真实 Git 仓库测试：双 hunk 只修改所选部分；暂存/取消暂存/撤销及原请求
  重放；含中文、空格、引号、反斜线和换行的文件名；新增与删除文件。
- 原生审批回调的服务测试：拒绝、同窗口取消、异窗口不能取消、确认期间文件/
  变更元数据/会话变化导致失效、等待审批时共享写锁占用、被拒绝请求不再弹框。
- 拒绝覆盖后续编辑、拒绝脏基线、拒绝应用超过 256 KiB 的截断 diff。
- 前端测试直接调用生产 API，证明相同 hunk 点击合并、不同轮次/hunk 分离，
  IPC 携带生成或显式传入的 requestId。

## 原生桌面

运行 `node probes/core-hunk-native.mjs`，结果见 [原始证据](./core-hunk.json)。
探针使用独立应用 identifier、数据库和临时 Git 仓库；数据库只植入一条已完成
轮次的变更记录，不启动 Agent。macOS 辅助功能脚本仅点击该隔离进程的原生
确认框，实际完成一次拒绝和三次批准。

探针通过生产前端 API → Tauri IPC → 原生确认 → 领域服务执行 hunk 操作。
外部 Git 检查每步 index，最终检查工作区只撤销第一个 hunk、第二个仍保留；
同时验证重复请求、缺失请求 ID、改变输入复用 ID、持久结果及撤销信任后的读取。
该探针未覆盖 Inspector 按钮布局、全平台运行、进程写入中途的 hunk 专用取消
时序或本批请求跨重启重放；公共执行器、取消和启动恢复由现有 Rust 回归覆盖。

## 已知边界

工作区占用只协调宿主受控写入，无法阻止外部编辑器或其他进程并发修改。
源读取有独立时间/大小限制，取消在后续 Git 步骤检查；不承诺瞬时停止所有读取。
主包仍有超过 500 KiB 的既有构建警告，后续按宿主视图分包处理，没有提高阈值。
