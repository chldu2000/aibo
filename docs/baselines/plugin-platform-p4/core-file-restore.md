# Core 整文件撤销验收

P4 第二十七批覆盖所选轮次的整文件撤销，以及 Core 文件暂存/取消暂存服务入口。
整轮、多文件及重命名恢复仍走待迁移路径，本批没有将它们标为完成。

## 验证结果

- `cargo test --manifest-path src-tauri/Cargo.toml`：179 项通过。
- `pnpm run verify`：25 项架构检查、157 项 Node 测试、类型检查和构建通过。
- `node probes/core-hunk-native.mjs file`：隔离 macOS 桌面验证通过，见
  [原始结果](./core-file-restore.json)。

## 实际行为证据

Rust 测试使用真实 Git 仓库与 SQLite 写入记录，验证已暂存结果恢复到轮次基线、
字面路径、新增/删除文件、二进制内容和 Git 执行位。对工作区外的硬链接保留
原内容及权限，证明文件替换没有沿硬链接修改另一个文件；正常退出清理临时文件。

拒绝确认、确认期间轮次记录变化、已有后续编辑、脏基线及损坏 checkpoint 均不
改写目标。原请求完成后产生的新编辑，在重放请求时仍然保留。

真实 `.git/index.lock` 使后续暂存区更新失败：文件已恢复而 index 保持原内容，
结果持久化为 outcome_unknown；删除锁后重放原请求也不会重新更新 index。
另一测试让 Git clean filter 仅在读到恢复后的基线时启动延迟子进程，然后撤销
信任并取消；原窗口可取消、其他窗口不能取消，部分日志/文件影响和取消记录
保留，延迟子进程未产生后续文件。这验证了实际写入中途取消，而非仅取消等待。

原生探针复用隔离 identifier、临时仓库及仅植入已完成轮次的 fixture。生产前端
API 经真实 Tauri IPC 和原生按钮，完成拒绝撤销、批准暂存、批准撤销三次交互；
外部 Git 逐步核对 index，最终文件和 index 都回到基线。重复点击/重放不产生
额外执行；撤销工作区信任后仍可读取记录。没有启动 Agent 或触碰用户仓库。

## 验证范围

本批未验证跨平台权限/ACL 恢复、Inspector 布局、进程崩溃时临时文件清理或所有
外部并发写入时序。单次文件系统调用会等待完成，取消不会强行中断内核操作；
当前内容复核与 rename 之间仍可能有外部写入竞态。宿主占用不等同跨进程锁，
工作区与 index 的更新也不是一个原子事务。主包超过 500 KiB 的既有构建警告
仍保留，未提高阈值。
