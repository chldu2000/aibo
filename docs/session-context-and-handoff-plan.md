# 会话上下文与 Agent 交接：两阶段交付

## 阶段一：用户通过 @ 引用会话（本次实现）

- 同一个 @ 选择器展示工作区文件和当前工作区的其他会话；按标题、Agent、会话 ID 搜索，包含归档会话。
- 选择时从 Aibo Core 保存的消息创建不可变快照，记录来源会话、Agent、消息边界、时间、快照 ID 和内容哈希。原 Agent 无需运行。
- 用用户选择的全部或最近 N 条用户/助手消息提供上下文（默认 N=12，合计计数，1–10000）；明确标注 extractive 及截断状态，不冒充模型生成的总结。
- 引用作为待发送上下文附件持久化，可移除，随普通发送及队列消息传递。新引用 v3 保存选中消息正文，不做逐条字符截断；旧版引用保留原摘录语义。引用不受源会话后续修改影响。默认不读取或保留工具输出正文、系统消息和嵌套引用；记录省略数量及截取标记。
- 直接内联选中的对话消息正文。对话卡片中默认折叠引用内容，展开后显示可读摘录；兼容历史完整快照消息。单份引用上限 128 KiB，合计上限 128 KiB（包含序列化元数据），同时遵守消息及传输包长度限制；超限阻止添加或发送并说明原因；引用明确标注消息范围与省略数量。不读取工具正文；所选用户/助手消息自身超限时明确拒绝，不静默裁剪。
- 来源明确为 persisted-core，不保证包含导入前的原生会话历史。引用内容是参考资料，不转移用户授权或执行责任。
- 验证：范围校验、归档来源、快照稳定性、持久化与移除、大小限制、发送/队列及异步切换会话隔离、两套界面和 pnpm run verify。

### 设置与兼容

“工作台设置 → 工作区 → 会话引用”保存应用级默认值，作用于之后创建的引用。
`session_reference_preferences.message_limit` 为 null 时选择全部，正整数时选择最近 N 条。
宿主在创建引用的同一读事务中读取设置；前端不提交条数覆盖。迁移 0054 默认 12，
不改写历史附件、队列或消息。设置读取失败禁用编辑，保存失败保留上次确认值。
引用 UI、普通发送、steer 和 followUp 都消费已捕获内容，不在发送时按新设置重新裁剪。
新引用保留所选正文，包括空白，仅去除嵌套引用/上下文附件；v1/v2 延续旧的有限摘录兼容。
128 KiB 限制包括序列化元数据，发送前再次检查合计；为限制原生分配，捕获前还保守检查
所选原始正文和逐条元数据预算，因此包含巨大嵌套引用的原始消息也可能要求减少条数。

### 后续上下文增强

后续工具的具体接口、传输、授权和插件接入方案见[完整会话查询工具设计](session-history-tool-design.md)（待实现）。后续提供按会话及消息边界分页读取/搜索的 Agent 工具，以补充目前省略的上下文。当前引用不保存工具输出快照；后续读取若使用可变原文，必须标注其时间与版本，不能承诺重现已省略内容在引用时的状态。随后可增加由系统生成、绑定消息边界的模型摘要缓存。不能在尚未提供读取工具时声称 Agent 能按需读取原文。

## 阶段二：可调用的交接接口（待实现）

1. 定义结构化交接记录：任务目标、约束、已完成和验证结果、关键决策、产物、阻塞、下一步、来源快照、目标 Agent。
2. Aibo 提供列出可用接收方、提交、查询、确认接手、完成/失败/取消接口；请求带幂等 ID，状态持久化。
3. 区分 delegate（源 Agent 保留任务责任、等待子任务结果）与 transfer（目标确认接手后源 Agent 暂停）。处理启动失败、重复请求、超时与进程重启。
4. 通过 MCP 或 CLI/脚本暴露同一套接口；各 Agent 的 Skill/能力包仅指导调用，不各自实现路由和状态机。
5. 主动交接说明由源 Agent 生成，系统补入可验证产物与状态；离线来源可用 Core 历史生成兜底版本并标明来源。
6. 验证不同 Agent 之间交接、无运行时来源、去重、状态恢复、取消及失败反馈，再交付能力包示例。
