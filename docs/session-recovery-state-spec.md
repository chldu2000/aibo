# 会话恢复状态与错误分类目标规格

状态：待实现。日期：2026-10-25。本次仅定义目标行为与验收条件，不表示运行时代码已修改。

## 问题与依据

当前 Broker 在同一判断中将请求 ID 无效、作用域/能力/版本绑定不一致、输入过大统一返回 `invalid_input`，显示“贡献项绑定不匹配”。发送消息前若需要恢复插件会话，`aibo.session.open` 也经过该判断。

只读检查一个故障会话得到：恢复 JSON 为 68,450 字节，其中 `backgroundTasks` 为 68,198 字节。恢复数据本身已超过普通能力输入默认的 65,536 字节，尚未计入执行配置。该证据证明当前保存状态无法通过恢复输入校验；不代表已验证原生 Agent 的恢复成功与否。

当前 Codex 将整个后台任务列表写入 recovery。共享任务实现最多保存 128 项，单项 output 保留末尾 12,000 个字符。数量和字符限制不保证总 UTF-8 JSON 字节数符合 Broker 输入、输出或传输限制。任务详情响应还可能同时携带 tasks 和 recovery，重复包含同一批输出。

实现依据：[Broker](../src-tauri/src/capability_broker.rs)、[SessionHost](../src-tauri/src/session_host.rs)、[Codex recovery](../src-tauri/capability-plugins/codex/engine.mjs)、[后台任务存储](../packages/acp-adapter/background-tasks.mjs)。历史限额来源见 [Broker 实施记录](archive/plugin-platform-p3-broker.md)；该记录不是本规格的目标合同。

## 目标与范围

1. 明确区分请求身份错误、真实绑定不一致、输入超限与恢复状态故障。
2. 恢复入口的大小不随聊天历史、任务数或任务输出累计增长。
3. 已接受的恢复入口必须能通过后续恢复请求的格式和容量校验；原生数据被外部删除等情况仍可明确失败。
4. 已有超限会话能够迁移并续接同一原生会话，保留 Aibo 历史和任务记录。
5. 适用于共享宿主、内置 Codex/Pi、ACP 公共适配器及第三方插件；共享层不按 Agent 名称或插件 ID 分支。

本规格不改变模型上下文窗口，不将宿主历史重放为全量 prompt，不自动重发失败消息，不引入新的插件权限。永久提高所有能力额度、截断恢复 JSON、清除原生绑定或新建空会话不能作为修复方案。

## 状态所有权

沿用[领域词汇](../CONTEXT.md)和[宿主/插件边界](plugin-boundaries-and-regression.md)。

| 数据 | 所有者与用途 |
| --- | --- |
| Aibo 会话身份、固定 release 绑定、消息投影与投递证据 | 宿主持有，用于展示、审计、路由与恢复准入 |
| 原生线程/会话历史 | 原生 Agent 或 SDK 持有，由插件按原生协议加载 |
| recovery | 插件定义的版本化续接入口，宿主持久化并交回插件，不作为聊天历史正文 |
| 插件辅助恢复状态 | 插件私有持久数据，例如任务关联、状态快照及输出引用 |

Codex 继续通过 threadId 恢复线程，Pi 继续加载原生会话文件，ACP 继续按协商能力加载 sessionId。恢复辅助状态不替代原生恢复。宿主不解析厂商 recovery 的业务字段。

## 错误分类与展示

采用稳定的结构化原因，不通过英文/中文错误字符串匹配。优先保留现有顶层错误码兼容性，例如前三类仍可归于 `invalid_input`，增加可区分的 reason 与安全 details；若公开合同需要新字段，应同步 schema、SDK、验证器、持久化和消费者。

| 原因 | 判定 | 显示要求 |
| --- | --- | --- |
| `request_id_invalid` | ID 为空或超过其字节限制 | 请求标识无效，不显示绑定错误 |
| `binding_mismatch` | scope、capability、contract version 与选定绑定不同 | 功能调用与会话绑定不一致；可诊断字段名，不泄露正文 |
| `input_too_large` | 序列化输入超过该能力预算 | 包含能力、实际字节数和上限；恢复入口注明“恢复请求过大” |
| `recovery_version_unsupported` | 插件无法读取状态版本 | 提示版本不兼容，保留原状态 |
| `recovery_state_missing` | 引用对象不存在 | 提示恢复状态缺失，不新建会话冒充恢复成功 |
| `recovery_state_corrupt` | 校验、解析或归属验证失败 | 提示恢复状态损坏或不属于当前会话 |
| `recovery_state_write_failed` | 新状态无法可靠保存 | 提示状态保存失败，不发布尚未持久化的引用 |
| `native_resume_failed` | 状态入口有效，但原生恢复失败 | 保留插件返回的安全原因，与宿主输入拒绝分开 |

传输帧超限与业务输入超限也必须可区分。多项校验同时失败时保持确定顺序：请求身份、绑定一致性、输入预算；不访问插件即可完成的拒绝不启动原生回合。

错误经 IPC、回合事件和界面传播后保留原因。日志仅记录阶段、能力、原因、字节数/上限及已有安全身份字段，不记录恢复正文、命令输出或凭据。历史错误记录不重写；旧错误缺少细分原因时保持通用提示，不能猜测为超限。

恢复失败发生在回合创建前，不伪造回合；已有回合按[发送失败终态规格](session-failure-convergence-spec.md)收敛。未投递保持 `not_sent`，可能已投递保持原证据；恢复与重试不自动重复执行用户消息。

## 小型恢复入口与独立存储

新格式 recovery 只保留原生会话身份、必要的有界配置、状态格式版本和私有状态引用。禁止嵌入随任务累计增长的列表、完整命令输出或历史全文。原生已有可靠持久化的数据无需重复复制。

插件通过已有私有实例目录保存辅助状态。引用使用实例内相对逻辑键和不可变修订标识；具体存储格式由插件/共享适配库实现。引用不能携带任意绝对路径，读取须验证路径范围、对象完整性、会话归属，防止跨实例、路径穿越和符号链接逃逸。相对引用在私有目录复制后仍然有效。

提交顺序：

1. 在插件私有存储中写入新修订，完成原子提交及所需的落盘保障。
2. 插件发布指向该修订的新 recovery。
3. 宿主通过合同与预算检查后持久化新入口；失败保留上次入口。
4. 宿主提交前崩溃时，旧引用仍可用；提交后崩溃时，新引用必须已可读取。

不得原地覆盖宿主仍可能引用的修订。孤立修订可以回收，但回收必须能证明当前绑定、升级回滚及备份所需修订已不再引用；缺少提交确认机制时不得靠年龄推断可删。实施时应补齐通用确认/引用生命周期，或明确采取保守保留并对磁盘预算显式报错。

恢复时先校验入口并加载辅助状态，再执行原生恢复和状态核对。重连后运行任务降为 unknown，不能依据历史状态确认进程仍在运行；任务消失不能视为成功。

## 容量与任务读取

所有合同预算使用完整序列化 UTF-8 JSON 字节数，而不是字符数。必须分别约束 recovery 入口、open 输入（含执行配置）、业务输出和传输封装；输入预算与封装预算之和不得超过传输上限。

新入口应适配现有 64 KiB 普通输入预算，不以提升该默认值为目标。实施前应固定入口与配置各自的预算及封装余量，并由同一合同/共享定义驱动生产、保存和消费检查。不得只在保存时检查 recovery，而忽略恢复时附加配置的开销；配置修改也需要重新验证可恢复性。

后台任务存储与面板读取分开：列表返回有界摘要，任务输出按任务 ID 分页或分块读取，每页受总字节预算约束。需要输出时按需加载，不在 tasks 与 recovery 中重复传递。新增读取合同按正常版本协商发布，旧插件沿用已声明的输出变体，不能静默改变旧 schema。

运行中和 unknown 任务的身份、父回合关联及待核对状态不得被容量淘汰策略随意删除。终态记录可归档，输出可采用明确的保留策略；用户必须能分辨完整输出与截断输出。持久存储也须有容量控制：容量耗尽明确失败，不能无限落盘或破坏最后可恢复状态。

## 旧数据与发布迁移

新宿主继续识别合法旧 recovery；新插件提供旧内联格式到私有存储格式的版本化转换。转换须幂等，保留原生会话身份、任务稳定 ID、父回合和已有终态。不得要求用户手改数据库。

超限旧入口必须有独立的有界兼容通路。仅在会话恢复/迁移合同中使用，不能放开普通能力输入或绕过绑定、权限、scope 校验。允许把旧 JSON 作为实例内受控迁移对象交给已协商支持的插件，避免再次通过同一个超限输入；小于完整帧预算的旧入口也可通过临时兼容额度读取。超出可处理范围时明确报告迁移所需条件，保持原数据。

迁移先可靠保存辅助状态并验证新入口，再确认原生会话身份一致，最后提交新绑定。失败保留旧绑定及恢复数据，不切换 Agent、不清空历史、不重发消息。磁盘写满、进程退出、重复迁移均须可恢复。

不修改已安装 release 的不可变包。新版插件通过现有宿主管理的升级/会话迁移路径部署；旧 release 不支持新格式时，不把新入口回传给它。保留旧绑定及其私有数据以满足已有撤销升级语义。

备份、恢复、升级复制与回滚须包含引用闭包：入口及其引用的辅助状态必须一致。数据目录更换不得破坏相对引用。原生 Agent 在插件目录之外的持久数据仍遵循原生恢复边界，不能声称复制插件数据即可备份全部原生历史。

## 实施顺序与受影响边界

1. 拆分 Broker 校验，更新结构化原因、国际化、诊断与失败展示；覆盖 invoke_bound、授权写入、普通调用及控制入口中的相同校验。
2. 建立私有恢复状态存储与容量合同，先验证提交/崩溃语义。
3. 更新 Codex 与 ACP 共享任务恢复；Pi 保留原生文件引用方式并通过兼容回归。
4. 增加任务摘要/详情读取合同及按需展示；保留旧插件协商路径。
5. 实现旧内联状态迁移，验证安装升级、撤销、备份及原会话继续发送。

涉及生产者：Codex、Pi、ACP 适配器及第三方插件；消费者：SessionHost、Broker、恢复/升级流程、任务投影与两套皮肤。共享 SDK 或合同变更须同步发布与兼容验证。数据库如需变更，按[迁移规则](database-migrations.md)新增迁移，不修改历史迁移。

## 验收条件

| 场景 | 必须证明的结果 |
| --- | --- |
| 空/过长 ID、scope/能力/版本错配、输入超限 | 原因各自准确，超限包含实际字节数和上限，拒绝前不执行原生回合 |
| 中文、多字节字符、JSON 转义、预算边界 | 按完整 UTF-8 序列化计量，边界前后结果确定 |
| 合法保存后重启恢复 | 同一入口通过恢复输入/帧预算，不出现接受后无法加载的容量倒挂 |
| 大量任务与持续输出 | 恢复入口大小有界且不随任务数量增长；列表和详情每页有界 |
| 运行任务、unknown、终态、乱序通知 | 恢复不误判成功、不复活终态、不静默丢掉待核对任务 |
| 写状态、发布入口、宿主提交各阶段强杀 | 旧或新引用均指向完整修订；不会指向半写入对象 |
| 磁盘满、对象缺失/损坏、越界引用 | 明确分类，保留最后有效入口，不创建替代会话 |
| 旧内联状态大于 64 KiB | 经兼容通路迁移成功，thread/session 身份不变，任务记录保留 |
| 迁移失败、重复迁移、升级撤销 | 幂等或安全回滚，旧绑定及引用数据保持可用 |
| 复制备份至新目录 | 引用完整、归属正确、恢复成功；缺少对象明确失败 |
| 原会话发送新消息 | 先恢复再发送一次增量；已有历史、原生身份、投递证据保持一致 |
| Codex/Pi/ACP 与未知第三方身份 | 依据合同协商，不依赖品牌分支；不支持恢复时明确失败 |
| 旧插件、旧错误事件、双皮肤 | 兼容展示准确，任务详情可访问，不误报崩溃或持续运行 |

实施验收必须包含真实代码路径的 Rust/SDK 测试、故障注入、原生恢复探针及受影响界面的浏览器验证，最后运行 `pnpm run verify`。需区分模拟原生响应与真实 Agent 验证；不得仅凭构造合法 recovery 宣称原生续接成功。
