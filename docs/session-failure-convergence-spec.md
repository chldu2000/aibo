# 会话发送失败与终态同步目标规格

状态：本次修复已实现，验证范围见文末。日期：2026-10-14。

会话发送被拒绝或执行失败后，宿主持久状态和界面必须及时收敛到同一终态。用户应能看懂失败原因并手动重试，不需要等待其他会话结束、切换页面或重新启动应用。本规格约定修复目标和验收要求。

## 问题与证据

2026-10-14 的故障会话在北京时间 23:22:22 发送后约 213 毫秒被拒绝，原因是同一工作区存在尚未结束的写操作。宿主当场将会话和回合持久化为 `failed`，但把调用拒绝包装成 `adapter.crashed`。

前端对该事件显示了“进程已退出”提示，却既没有更新会话列表中的状态，也没有触发列表刷新。调用实际 `handleAgentEvent` 的最小复现得到 `notice: true, refresh: false, state: running`。另一个写入会话于 23:24:24 完成，会触发工作区会话列表刷新；这是延迟恢复显示的解释，与用户观察一致，但没有当时的浏览器事件轨迹证明具体刷新时刻。

## 本次范围

本次交付包括终态立即同步、工作区忙的准确分类与文案、手动重试保留，以及原生和界面的回归验证。保留宿主现有工作区写入互斥及执行授权规则。

自动等待后发送、占用者导航和独立 worktree 属于后续增强，不是本次完成条件。本次不增加等待状态、不自动重发失败消息，不改变已有消息队列的调度和暂停语义。

## 用户可见行为

| 场景 | 目标行为 |
| --- | --- |
| 工作区写入被占用，当前发送尚未投递 | 显示失败和“工作区还有未完成的写操作，请稍后重试”；不声称进程退出 |
| 已接受回合执行失败 | 显示失败及对应错误原因，保留已有输出和失败输入 |
| 用户取消 | 显示已中断，沿用既有取消体验，不误报崩溃 |
| 确认的适配器运行时故障 | 显示失败及准确的运行时故障提示；只有退出证据存在时使用“进程已退出” |
| 收到旧格式 `adapter.crashed` | 仍立即结束运行显示，按 `status` 和原因呈现；缺少原因时显示通用失败提示 |
| 失败后手动重试 | 重新经过宿主准入和授权；仍被占用则再次明确拒绝，不绕过互斥 |

终态处理必须在收到有效事件的同一次前端状态更新中生效，不等待异步刷新。会话列表、当前会话状态、运行指示和停止按钮一致结束当前回合的运行显示。输入框恢复可编辑；实际发送仍受归档、能力、权限和其他已有门禁约束。错误原因和重试入口可见，不覆盖用户随后输入的新草稿。

## 事件和持久化语义

1. 宿主区分调用拒绝、回合失败、用户取消与运行时故障。工作区忙通过结构化错误码分类，不通过错误字符串匹配或 Agent 身份分支分类。
2. 已建立回合但准入失败时，使用普通回合失败语义，优先复用 `turn.failed`；工作区忙不再生成 `adapter.crashed`。回合尚未建立时保留命令拒绝语义，不伪造回合或运行时故障。
3. 宿主原子持久化相关回合、会话和事件，再向界面发布；一个回合只有一个有效终态。失败后清理活动调用、审批和待输入等当前回合资源，保留现有队列结算职责。
4. 准入拒绝必须保持投递证据为 `not_sent`，不得调用提供者执行该回合。已经可能投递的失败保留 `possibly_sent` 或 `responded` 等实际证据，不推断为安全重发。
5. 取消保留既有 `interrupted` 终态语义，不因更换失败事件类型而统一归为 `failed`。成功路径、真实运行时故障和现有提供者事件保持兼容。
6. 结构化错误保留可诊断代码和原因，并提供本地化显示。展示字段不授予插件新的事件权限；插件提交的宿主专用显示字段继续按现行合同过滤。
7. 旧持久事件不改写。旧 `adapter.crashed` 的 `status=interrupted` 映射为已中断，`status=failed` 或缺省状态映射为失败；提示不根据事件名称推断物理进程已退出。

复用事件前须核对 schema、宿主来源校验、投影和各消费者。若需要扩展结构化错误或内部本地化字段，同步类型、验证器和合同文档，缺省值保持安全兼容。

## 前端状态收敛

有效的 `turn.completed`、`turn.failed` 和 `adapter.crashed` 均触发终态处理：先更新宿主业务层中的会话状态、活动状态和当前回合展示，再发起会话及必要历史刷新作为校准。

处理必须覆盖当前选中和后台会话。后台会话失败只能更新自己的状态，不替换当前会话的提示、草稿或重试输入。停止运行中的流式项只作用于对应回合，真实会话级故障则按其有效作用域清理。

重复终态事件幂等。旧 runtime generation、旧回合事件和迟到刷新结果不得把新回合覆盖成失败，也不得把已失败回合恢复成运行中。异步刷新失败不能撤销已经应用的终态；刷新结果必须服从现有身份与新旧结果保护规则。

Material 3、ak-ui 和外部呈现消费相同的宿主业务状态，不在皮肤中分别修复。错误提示、列表和 Composer 不应各自持有互相矛盾的执行事实。

## 影响链路与责任

| 层级 | 实现时需要核对的职责 |
| --- | --- |
| 工作区写入准入与 Broker | 结构化拒绝原因、投递前拒绝、互斥和授权保持 |
| SessionHost 与事件投影 | 正确分类、唯一终态、持久化顺序、活动调用清理 |
| 队列与投递记录 | 保留 `not_sent` 等证据、暂停与结算语义，不自动重发 |
| 前端事件处理与异步刷新 | 同步终态、刷新校准、回合及代际隔离 |
| 业务快照与呈现消费者 | 列表、运行指示、Composer、错误及重试一致 |
| 本地化与历史读取 | 新错误文案准确，旧事件安全展示，历史重载结果一致 |

相关入口包括 `src-tauri/src/session_host.rs`、`session_projection.rs`、`workspace_writes.rs`、Broker 写入路径，以及 `src/lib/app/agent-event-handler.ts` 和会话刷新控制器。以实际调用链决定改动范围，不要求每个入口都修改。

## 验收条件

| 编号 | 场景与必须断言的结果 |
| --- | --- |
| A1 | 同一工作区 A 持有写入，B 发送：B 不调用提供者，持久状态为失败、投递为 `not_sent`，原因是工作区忙，无崩溃提示；A 正常继续 |
| A2 | 前端预置 B 为运行中，回放失败事件：处理函数返回时已非运行中，即使刷新永不完成也成立 |
| A3 | 回放旧 `adapter.crashed` 的 failed、interrupted、缺省状态：分别正确收敛，错误和停止按钮不矛盾 |
| A4 | B 失败后 A 一直运行且无其他事件：B 无需切换页面或定时刷新即可呈现终态 |
| A5 | B 在后台失败：列表正确更新，当前会话的草稿、错误、重试和运行状态不被污染 |
| A6 | 重复终态、旧代际事件、旧回合事件及迟到刷新：不重复收尾，不覆盖新回合，不恢复错误的运行状态 |
| A7 | 解除写入占用后手动重试成功；未解除时继续明确拒绝；任何情况下都不静默自动重发 |
| A8 | 失败前已有消息、附件、审批或队列：按归属保存与结算，不丢输入、不消费其他草稿、不破坏 FIFO 或 uncertain 处理 |
| A9 | 真正的运行时故障、普通回合失败、用户取消和正常完成：各自终态与文案准确，历史重载与实时显示一致 |
| A10 | 不同提供者身份、只读路径及其他工作区执行：遵守原有权限与并发规则，无身份特判或互斥范围扩大 |

## 验证与完成门槛

先把原故障变成失败回归：直接运行真实事件处理函数，断言 `adapter.crashed` 后会话状态立即结束；再覆盖宿主准入拒绝到持久化和前端展示的完整链路。

实现阶段运行相关 Node 测试、SessionHost 与 Broker Rust 测试。按实际共享链路补充队列、投递、历史、取消和并发回归；生命周期跨模块变化按仓库规则运行完整 Rust `--lib` 测试。

浏览器验证覆盖真实 App 入口的错误提示、列表、Composer 和运行指示，包括 Material 3、ak-ui 浅深主题及受影响外部呈现。原生准入和持久化使用隔离数据与临时工作区验证，浏览器替身不替代原生证据。

交付前运行 `pnpm run verify`，报告实际结果与未覆盖边界。

## 实现与验证记录

宿主调用错误改用 `turn.failed`，取消使用 `turn.completed` 与 `interrupted`；错误码和本地化原因保留。终态事务同步关闭流式消息：现有消息表不支持 `interrupted`，取消的未完成消息继续保存为 `failed`，所属回合和会话均保存为 `interrupted`，不修改历史数据库迁移。

前端同步终态后刷新校准，并过滤重复序号和旧 runtime generation。发送接口回执通过状态事件修订号保护，不能把先到的失败事件覆盖回 `running`。修订号只跟踪实际改变会话状态的事件，普通用量更新不会阻止正常发送回执生效。

验证入口：

- `pnpm run verify`：通过迁移、SDK、架构、类型检查、685 项 Node 测试和生产构建；构建仍有现有大 chunk 提示。
- `test/agent-event-handler.test.mjs`：旧格式失败、后台会话、刷新挂起、迟到刷新和事件去重。
- `test/message-draft-ownership.test.mjs`：失败事件早于发送回执、取消和普通用量事件，并保留原草稿归属回归。
- `workspace_busy_turn_fails_without_dispatch_and_can_be_retried` 原生测试：真实工作区写入锁下，内置及第三方身份的提供者不收到回合；失败保持 `not_sent`，释放后手动重试成功，旧失败不覆盖新终态。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib`：425 项通过，4 项按既有条件忽略。隔离数据库与提供者子进程覆盖宿主执行链；未执行需要真实原生认证、安装包、下载或数据库备份的忽略项。
- `node probes/session-failure-browser.mjs`：Material 3 与 ak-ui 浅深主题、外部 shadcn 与 Material 3 工作台均通过。探针故意挂起会话刷新，断言会话立即失败、停止操作不可用、输入框可编辑及工作区忙原因可见。

浏览器探针使用替身 IPC；原生测试提供准入和持久化证据。本次不安装或替换用户当前运行的桌面应用。

## 后续增强

“等待后发送”需要独立规格定义可取消的等待状态、持久队列、公平调度、重启恢复、授权重新校验及重复投递防护。占用者提示需要宿主提供可验证的占用来源，兼容非会话写入，不能仅凭会话列表猜测。独立 worktree 并行修改另行设计工作区身份和合并流程。
