# P4 通用 Capability 写入：直接调用

本批开放窗口经 `invoke_capability` 发起的工作区/会话能力写入。插件仍声明
Manifest v2 的操作、schema、effect、permissions、timeoutMs 和 idempotent；
宿主不增加 Provider 专用分支。后续已接入[插件间写调用](./plugin-platform-p4-write-chain.md)；
安装语义视图的写动作仍待接入，通用写入整项验收尚未完成。

## 权限与审批

写操作必须声明 `effect: write`、包含 `workspace.write`，且只能另加
`workspace.read`。application 写入、其他权限、把写权限放在 read 操作上均不
支持。当前写入激活仅开放 Unix 进程组路径；macOS 有实际验收，Linux 尚未做
原生验证，Windows 需要补齐运行时进程树收尾后再开放。

生产 IPC 从真实窗口构造不可反序列化的审批对象，前端不能提交调用者身份、
权限或“已经批准”。只有持久意图接纳、原生确认及确认后复核通过，才开始插件
运行和依赖版本检查。确认框展示操作、完整输入、工作区、窗口、插件/贡献、
安装 release 和权限；不截断超长内容以换取放行。审批等待沿用 5 分钟上限，
消息最多 16 KiB、意图最多 64 KiB，写请求 ID 最多 128 个 ASCII 字母、数字、
短横线或下划线；只读请求保留原 160 字符限制。

预检只读取声明、数据库及包文件，不调用插件入口、初始化或依赖程序。
冻结规范化工作区路径与目录身份、信任/更新时间、会话状态/归档、turn 归属与
状态、绑定及更新时间、provider 操作、安装包 digest 和依赖 release 选择。
确认期间任一相关内容变化，原意图拒绝执行；不自动重弹审批或切换 provider。

通用操作没有统一的“目标文件版本”语义，因此这里不伪造整个工作区的原子快照。
插件操作若需要“仅在文件仍为某版本时修改”，应在自己的输入 schema 与实现中
定义并检查前置条件。宿主仍持有工作区写入占用，阻止其他宿主受控任务/Git/恢复
同时写入；它不是外部编辑器锁，也不是任意本机程序的操作系统沙箱。

## 执行、去重与取消

复用 `workspace_write_runs`，操作名为 `capability.invoke`。幂等身份是工作区内
的请求 ID，加上原窗口、scope、capability/version、turn 和原始输入。已接纳
请求先读取持久结果，再解析当前提供者：禁用、卸载、重新绑定或撤销信任后，
重放也不会变成另一次写入。修改输入或调用窗口被拒绝；并发重复请求返回 busy，
不会再次弹窗。插件的 `idempotent: true` 不授予自动重试权限。

审批前拒绝保留 rejected 和原因，不伪造 capability 执行事件。批准后才创建
invocation。迁移 0037 用 nullable `write_run_id` 将 invocation 关联到写入记录，
旧只读行保持 NULL，现有事件 v1 格式不变。成功结果仍携带 invocation、instance、
installation 和 generation ID；执行历史保存原输出，能力历史保存生命周期。

批准后的依赖 `--version` 查询使用受控异步进程，每项最多 2 秒且受操作总期限
约束，每路输出最多 8 KiB，可取消并清理后代进程。Broker 发现及依赖图预检只
解析元数据；每个实际启动的 runtime 在执行前检查自身必需可执行依赖。安装、
启用及管理页的既有依赖诊断仍独立存在，不把它们当作写入审批。

操作总期限从批准后的执行开始。取消沿用原窗口 request ID 或独立工作区写入
历史中的 run ID；信任撤销/停用插件同时触发持久取消。读子调用仍按父调用的
原始调用者、权限交集、scope、调用链和较早 deadline 运行，继承根写入取消。
子写调用没有批准凭据时明确拒绝，不能由插件自行放大权限或绕过宿主审批。

写入链中的 runtime 在成功或失败后都停止，并等待进程清理；不能把后台常驻
进程留在已结算的写入许可之后。进程组不能控制主动逃离进程组的本机代码。
进入批准执行阶段后，超时、取消、崩溃、非法输出或不能确认收尾均保守记录为
outcome_unknown；不根据插件错误文字声称“没有修改”。不会自动回滚或重试。
持久结算失败也返回结果未知，未结算记录继续占用，启动恢复后可查看且不重执行。
