# P4 第三十九批：旧能力调用快照

生命周期事件引入前，数据库已有 capability_invocations，但没有 capability_events。原历史入口仅按事件查询，导致这些调用不出现在目录中。

迁移 0039 将升级时没有任何生命周期事件的调用复制到独立的 capability_legacy_history，保留窗口、作用域、安装与贡献、合同版本、调用链、已知状态及时间字段。未知字段继续为 null；不推断缺失的根调用或生成代际，也不伪造 admitted/started/finished 事件。公开 capability-event v1 流及原表保持不变。

宿主历史提供“生命周期记录”和“旧调用快照”两个来源，各自分页。旧快照沿用原调用窗口隔离，即使原作用域删除、插件停用或不可执行也可读取。界面明确说明无法还原完整生命周期。刷新保留来源，切换来源清空旧页与游标，迟到响应或来源不匹配的响应不会覆盖当前页。

## 验证

- 从迁移 0027 的真实数据库开始，写入 55 条主窗口及 1 条其他窗口旧调用，再通过正式 open_database 升级。
- 确认未生成生命周期事件，旧调用按 50/5 分页且无重复；其他窗口只能读自己的记录，删除作用域显示原 ID。
- 确认原状态、时间、deadline 和未知字段保留，重复打开数据库没有重复导入。
- 升级后使用只读 SQLite 连接仍能读取，插件路径不存在且处于停用状态。
- 控制器测试验证来源隔离、迟到响应、错误来源以及刷新/关闭行为。
- [两套皮肤浏览器证据](./baselines/plugin-platform-p4/legacy-capability-history-browser.json)使用真实控制器和面板验证来源入口、说明、翻页和返回事件流。该浏览器夹具不冒充真实数据库升级，后者由 Rust 集成测试证明。

Rust 全量 208 项测试通过；`pnpm run verify` 的 25 项架构测试、类型检查、166 项 Node 测试及生产构建通过。

本批补齐 P4 已知的旧能力调用历史缺口。P4 仍需逐项核对版本合同及累计退出证据；P5 的完整发布、SDK 与数据迁移矩阵另行实施。
