# 0008：Agent 命令是结构化的，不是文本

**Status:** accepted

## Context

用户要在消息里调用 Agent 命令（`.scratch/agent-commands/`）。可以让消息保持纯文本，由适配器解析开头的 `/单词`；也可以像文件提及那样（ADR 0004），让命令作为结构化字段随轮次交给适配器。

实测（见 `.scratch/agent-commands/research/01-how-agents-expose-commands.md`）：

- Claude Code 只认消息开头的 `/名字 参数`。
- Codex 的 app-server 不解析 `/`。它的 skill 要用文本 `$名字` 调用，或者给一个 `{type:"skill", name, path}` 输入项；内置命令只能调用 app-server 的方法。
- 两家都不在协议流里回传展开后的提示词。

## Decision

Agent 命令作为轮次的结构化字段（`Command{Name, Args}`），不靠解析文本。

- 一条消息最多一个命令，放在开头，后面的文字是参数。这是两家都能保证的部分；Codex 能否在一条消息里带多个 skill，没有实测。
- 从 `/` 面板选中，或者手打的名字（别名也算）在 Agent 报告的清单里，输入框开头就变成命令 chip，名字换成正式名。
- 清单里没有的 `/单词` 拦下，不当作文本发出。
- 适配器负责翻译：Claude 拼成 `/名字 参数`；Codex 拼成 `$名字 参数` 文本，外加 skill 输入项，内置命令改为调用对应的方法。
- 用户消息存下命令名、参数，以及发送时清单里那条命令说明的快照。会话引用的读取工具返回命令和这段说明。

## Consequences

- 界面统一用 `/`，各家的写法差异由适配器吸收。
- `/Users/...` 这类路径和句中的斜杠不会被误认为命令。
- 存储要加字段，旧消息没有命令字段，照旧按文本显示。
- 展开后的提示词拿不到，aibo 不读 Agent 磁盘上的会话记录去找（ADR 0001）。所以会话引用里只有命令名、参数和说明，没有展开后的内容。
