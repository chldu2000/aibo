# 0005：界面文字只由外壳来写

**Status:** accepted

## Context

aibo 要跟随系统语言显示简体中文或英文（任务 03）。原来下层包直接写中文：`workbench` 的错误、适配器给的审批标题和按钮文字（“执行命令”“批准本次”）、Agent 检测的原因（“版本 0.168.0 过低……”）、权限模式的说明、重试提示（“第 2/10 次重试”）。这些文字一部分只在内存里，一部分随消息存进了数据库（审批卡片的标题和选项、会话的规则）。

可以让下层包也调用生成的 `locales` 函数；也可以让下层只给结构化的数据，由外壳措辞。

## Decision

只有外壳和 `cmd/aibo` 引用 `locales`，依赖方向测试管着。下层包：

- 错误用哨兵或类型（`workbench.ErrTurnRunning`、`agent.ErrStartFailed`、`workbench.Failure`、`agents.UnusableError`），附带的细节是系统或 Agent 的原话；错误文字用英文，写给开发者和日志看。
- 要显示的东西给结构：审批请求的 `Action` 和 `Tool`，选项只给 `Kind`（按钮文字由外壳按种类写），选项和规则允许什么用 `agent.Grant`，Agent 检测给 `Problem` 和 `Source`，重试给次数。
- 权限模式的名称是 Agent 自己的叫法，照旧不翻译；说明由外壳按 Agent 种类和模式 ID 查表，查不到时显示适配器给的英文说明。

已经存进数据库的旧数据不迁移：审批的 `Title`、选项的 `Detail`、规则的 `Label` 字段留着，新数据不再写；外壳遇到没有新字段的旧记录，就原样显示旧的中文。

## Consequences

- 下层可以在测试里比较结构，不再比较中文句子；措辞改动只动语言文件。
- 外壳多了一张错误对照表（`internal/shell/words.go`）。下层新加给用户看的错误，要同时在表里加一行，否则用户看到的是英文的开发者文字。
- 旧会话里的审批卡片和规则在英文界面下仍显示中文。
- Agent 未登录时，适配器不再另外报一条失败：会话的登录横幅已经说了怎么登录。
