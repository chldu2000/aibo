# 0004：文件提及只给路径，不做快照

**Status:** accepted

## Context

写消息时，用户要能把工作区里的文件指给 Agent（任务 07）。可以像会话引用那样，把文件内容在发送时存一份快照交给 Agent（ADR 0002）；也可以只给路径，让 Agent 自己读。

实测（Claude Code 2.1.318、codex-cli 0.169.0，见 `.scratch/aibo-v1-followups/research/07-file-mentions.md`）：

- Claude Code 在 stream-json 输入里认 `@路径`，不调工具就把文件读进来：相对路径、带空格加引号的路径、工作区以外的绝对路径都行。
- Codex app-server 的 `turn/start` 虽然有 `mention` 条目，但它不会把文件交给模型；Codex 只能拿着路径自己用工具读。

## Decision

文件提及只给路径。会话工作区里的文件给相对路径，可读的源工作区里的给绝对路径；目录也可以提及。消息里存的是路径，不存内容。适配器按各家认得的写法放在用户文字后面：Claude 写成 `@路径`（每个一行），Codex 写成一句说明加路径列表。

不做快照的理由：

- 文件在工作区里，Agent 本来就能读，而且应该读到最新的；快照会让 Agent 看到的和磁盘上的不一致，改文件时更容易出错。
- 大文件、目录、二进制文件都没法合理地做快照。
- 会话引用要快照，是因为被引用的会话会继续变、而引用要能复现（ADR 0002）；文件没有这个需求，用户想固定内容可以自己提交到 git。

## Consequences

- 起了一个新术语“文件提及”，和“会话引用”分开，免得混淆（`GLOSSARY.md`）。
- 历史消息里的提及只是路径：文件后来改了、删了，重看那条消息时看到的不是当时的内容。
- 只能提及会话工作区和它可读的源工作区里的文件；跨工作区的只读限制照旧由各家 Agent 的设置保证。
