# 0006：图片附件存快照，交给模型直接看

**Status:** accepted

## Context

用户要能把图片交给 Agent（后续任务 17）：粘贴截图、从 Finder 复制或拖入图片、用附件按钮选择。文件提及只给路径（ADR 0004），但图片和文件不一样：

- 剪贴板里的截图在磁盘上没有路径。
- Codex 拿着路径只能用工具读文件，读到的是字节，模型看不到画面。

实测（Claude Code 2.1.331、codex-cli 0.169.0，见 `.scratch/aibo-v1-followups/research/17-images.md`）：Claude Code 的 stream-json 输入接受 base64 的 `image` 块，Codex app-server 的 `turn/start` 接受 `localImage`（路径）和 `image`（data URL）。两家的模型都不用工具就看到了图片。

## Decision

图片作为“附件”存快照：复制到数据目录的 `attachments/<会话ID>/`，消息里只存元数据（显示名、相对于附件目录的文件名、类型、尺寸、字节数），不存绝对路径，这样数据目录搬家后仍然有效。适配器发送时让模型直接看到图片：Claude 读文件转成 base64 `image` 块，Codex 给 `localImage` 加文件路径，都放在文字前面。

- 只收 PNG、JPEG、GIF、WebP（按内容判断，不看扩展名）。超过 3.5 MB 或边长超过 8000 像素的图片先缩小到长边 2048，再编码成 PNG，仍然太大就用 JPEG（Claude API 对单张图片的上限是 base64 后 5 MB、边长 8000）。
- 工作区里的图片也存快照，不当作文件提及：要保证模型看到的是画面。
- 粘贴或拖入的非图片文件，在会话可读的文件夹里就转成文件提及，否则提示不支持。

## Consequences

- 起了新术语“附件”（`GLOSSARY.md`），和“文件提及”“会话引用”分开。
- 附件在用户选中时就写进数据目录（为了在后台缩小、显示缩略图），发送前移除会删掉文件；随会话一起删除。应用在发送前退出时，草稿里的附件文件会留在附件目录里，没有被引用。
- 会话引用里，附件写成 `[图片: 文件名]`，图片本身不交给接收方 Agent；搜索覆盖附件文件名。
- 以后接入的 Agent 不一定能看图片；到时适配器要声明这项能力，不能静默丢掉图片。
