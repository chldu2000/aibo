# 框架无关呈现：目标规格与实施清单

状态：目标规格，尚未实现。日期：2026-09-22。

本文确定下一阶段目标及验收门槛，不表示当前宿主已经支持 DOM 插件，不修改
[现行包合同](presentation-package.md)或替代 [ADR-0009](adr/0009-presentation-package-isolation.md)。
运行容器的具体选择须通过 P0 实验，再记录新的 ADR 并同步合同、架构约束和测试。
既有 P0–P4 完成结论仍属于[此前交付](presentation-plugin-exit-audit.md)，不覆盖本文。

## 1. 目标与范围

呈现作者能够使用 React、Vue、Svelte 或原生 JavaScript 及兼容的组件库，
在 Aibo 仓库外独立构建可安装包。宿主不理解框架组件，不要求把界面转换成
PresentationNode；插件在自己的运行文档内创建和更新 DOM。

框架自由限定于宿主允许的 Web 平台能力，不承诺任意组件库、网络服务、Node.js
模块或原生 UI 工具包无条件兼容。需要的系统能力经宿主受限服务提供。

本阶段必须交付：

- DOM 呈现运行时、框架无关消息 SDK、安装与恢复链路。
- 使用同一公共协议的 Svelte 和 React 完整工作台；Vue 与原生 JS 最小挂载样例。
- 默认完整外观使用公共呈现合同，可信内置恢复界面保留在宿主。
- 旧主题包与 Worker 视觉树包继续可用，旧 release 不被隐式转换或覆盖。

首版以完整 workbench 为 DOM 替换单位。既有 controls/semantic 的 Worker 合同
继续保留；跨插件面板插槽、按钮级混搭和 DOM controls 不作为首版发布条件。
不引入 Astro 作为宿主框架，不要求 SSR/hydration，不重写会话或能力运行时。

## 2. 当前基础与设计原则

当前 Worker 运行包脚本并输出受限视觉树，可信绘制桥管理 DOM 和真实事件。
`packages/web-presentation` 只有可信进程内的类型，不是外部 DOM 执行器。
安装摘要、不可变 release、候选事务、快照、动作目录和恢复机制可以复用。

借鉴 islands：每个呈现区域拥有独立渲染生命周期，框架细节留在区域内部。
Astro 的组件上下文独立不等于安全或 CPU 隔离，其项目内构建也不等于运行时安装。
Aibo 必须另外解决插件权限、安装身份和失控恢复。

外部协议只包含版本化数据与消息。宿主业务不得按框架名、皮肤 ID 或 Agent 身份
选择执行行为；内部 UiKitAdapter 可以继续服务可信宿主界面，不成为第三方要求。

## 3. 运行时与包合同

建议新增显式运行时区分（以下名称待版本化合同定稿）：

| 运行时 | 输出与执行 | 首版范围 |
| --- | --- | --- |
| declarative-worker | Worker 输出 PresentationNode，宿主绘制 | 保留现有 surfaces |
| web-document | 插件框架管理隔离文档内的 DOM | 完整 workbench |

旧 v1 缺少新字段时仍按旧语义运行。新的不兼容包格式必须使用显式新版本；旧宿主
明确拒绝，不猜测入口类型，不将 DOM 脚本放入可信主文档。

新包声明入口、协议范围、必需/可选特性及资源清单，运行握手验证实际支持。
必需项不匹配时拒绝候选，可选项缺失采用文档化降级。框架及依赖由插件携带，
宿主不依赖框架版本共享或单例注入。首版允许要求自包含 JS 与独立 CSS/资源；
动态 import、代码分包和远程加载不自动获得支持。

沿用不可变 release、安装及重载摘要检查、路径和大小限制；需要调整限额时提供
实际构建数据及有界替代值。资源解析不能访问清单外路径。主题和工作台原子激活。

## 4. 生命周期与公共 SDK

逻辑生命周期为 prepare → ready/preflight → activate → update/suspend → dispose。
dispose 必须幂等；超时、候选取消、激活后异常均有明确终态和资源回收。
候选在提交前不可发业务动作。旧实例保持有效至候选成功，失败保留上一可用版本。

插件文档内部可使用 mount(container, context) 返回 update/dispose 句柄。
HTMLElement 和回调仅存在于该文档内部，跨容器只传可序列化消息。
不能直接将现有 WebPresentationAdapter 当作跨进程协议。

SDK 必须定义：

- 握手、版本/特性协商、实例代际、工作区/会话作用域、请求 ID 和错误结构。
- 初始快照与订阅更新；全量快照先可用，增量更新需声明基准 revision 和重同步。
- 有界消息尺寸、更新合并、背压及快照重同步；可合并展示更新，不丢业务持久事件。
- 动作请求、接受/完成/失败/结果未知及取消语义。卸载不表示已发写操作被撤销，
  结果由宿主持有，不因界面重挂载自动重试写入。
- 草稿 editSequence 与宿主确认；旧快照不覆盖未确认输入。
- 受限资源服务、语义视图状态、挂起和恢复通知。

React hooks、Vue composables、Svelte bindings 只是同一 SDK 的薄适配。
公共数据包不得依赖 DOM、框架、宿主源码或 Tauri；DOM SDK 单独分包。

## 5. 状态、功能与动作权限

| 内容 | 权威所有者 | 切换要求 |
| --- | --- | --- |
| 会话、历史、队列、附件、执行与待审批 | 宿主 | 不重建、不丢弃、不重复执行 |
| Composer/回答/Git 等可恢复草稿 | 宿主 | 沿用既有作用域及持久化策略 |
| 选择、布局、阅读位置、语义焦点 | 宿主视图状态 | 匹配语义身份后恢复 |
| hover、动画、临时菜单和瞬时筛选 | 插件 | 可随卸载释放 |

消息位置使用消息身份与偏移，焦点使用 composer 等语义目标；不要求不同框架
拥有相同 DOM key。目标缺失安全降级，不抢夺宿主管理/审批焦点。
不把窗口内恢复扩大描述为跨应用重启持久化，新增持久化须单独定义。

完整工作台功能矩阵应覆盖当前导航、会话、Composer、队列、附件、模型/模式、
目标与子任务、Git/仓库选择、Inspector、能力视图和错误/恢复入口。
逐项标记公共投影是否已有、是否缺失，并为缺失项补合同，不能只复制旧样例功能。
协商能力可用、缺失、拒绝、忙碌与归档均有可理解的展示；专业视图缺失明确降级。

DOM 插件能主动调用 SDK，因此收到 token 或消息不能证明用户真实点击。
不得将插件提交的 isTrusted/userGesture 字段当作授权证据。

- token 仍是不透明、有限作用域的操作句柄；宿主重验实例、上下文、revision、
  当前目标、可用性、安装授权及业务权限。
- 逐类定义操作策略：本地编辑、只读请求、外部副作用和必须可信确认的操作。
  发送消息、Git 写入、打开链接和剪贴板等不得因 DOM SDK 引入而扩大原执行权。
- 若操作依赖真实用户意图，使用插件不可伪造的宿主交互/确认机制；P0 必须证明
  相应机制，不能只靠插件文档中的普通事件监听器或 token 保密假设。
- 管理、审批和恢复在宿主可信区域；插件不能授予权限、确认审批或调用通用 IPC。
- 本地输入的 revision 例外仅限宿主允许项，不扩展到发送、导航或跨会话操作。

## 6. 容器、交互与资源隔离

插件可管理自己的 DOM，但不能访问或覆盖宿主可信 DOM、存储、文件、Tauri IPC
与其他插件。CSS、字体、图片及 portal 的作用范围限制在插件区域。
宿主为文件选择、附件预览、打开链接及剪贴板提供最小作用域服务并校验输入。
DOM 插件能看到实际呈现的附件内容；不能继续宣称其具备 Worker 不接触图片数据的
同一保证。传递最小必要数据，禁止任意路径读取，网络和导航按容器策略拦截。

运行容器必须验证死循环、崩溃、消息洪泛和资源耗尽时的宿主可用性。
sandbox iframe、Shadow DOM 或“独立 WebView”名称均不构成进程隔离证据。
必要时采用更强隔离；若平台不满足门槛，该平台保留旧运行时并明确不支持 DOM 包。
不可通过削弱现有审批/恢复保证宣称成功。

交互必须覆盖中文 IME、连续输入、流式更新、键盘导航、焦点跨区域、菜单/弹层、
粘贴和拖放附件、窗口缩放、长历史与减少动画偏好。审批/管理打开时暂停插件动作，
宿主强制执行挂起，不能依赖插件配合。恢复入口在插件失控和持有焦点时仍可操作。

会话/输入首屏优先挂载，重型辅助视图可按需加载。定义启动、切换、输入延迟、
消息吞吐、内存及资源释放基线；P0 记录设备、数据规模和量化预算，P5 按同一基线验收。

## 7. 默认呈现与兼容迁移

默认完整外观通过公共 SDK 消费快照和动作，不读取宿主私有 store 或源码。
主宿主保留可信管理、审批及精简恢复界面；该界面不依赖外部包或完整框架运行时成功。
现有默认体验在新默认呈现通过功能等价验收前继续可用。

已有主题、双内置皮肤、Worker controls/semantic/workbench 和未覆盖 surface 继承
必须回归。新默认外观的视觉重构不改变能力协商、会话绑定、历史与草稿所有权。
新旧包切换、禁用、卸载、缺失、损坏、升级失败及重启恢复都保留可操作路径。

## 8. 实施 checklist

全部复选项表示待完成工作。勾选时附实现/测试/证据路径；文档存在不等于实现完成。

### P0：容器与授权可行性门槛

- [ ] 列出现有生产者、投影、消费者、动作执行者以及必须保留的行为，完成当前功能矩阵。
- [ ] 制作 Svelte/React 同区域挂载原型，使用同一快照和动作语义。
- [ ] 比较候选容器的权限、导航/网络限制、DOM 隔离、失控终止和跨平台差异。
- [ ] 在真实桌面环境验证死循环时管理、审批、恢复仍可操作；记录原生输入证据。
- [ ] 验证主动伪造 SDK 调用不能绕过各类动作策略，明确真实用户意图的证明方式。
- [ ] 记录 DOM 附件数据暴露变化、资源预算和性能基线及量化验收阈值。
- [ ] 根据实验确定支持平台和运行容器，新增 ADR；同步 ADR-0009 的适用范围和回归规范。

退出条件：容器与授权可行性有实测证据。不满足时停止扩大 DOM 实现，记录阻塞，
保持旧路径；不得将“可显示一个 React 按钮”当作此阶段完成。

### P1：公共合同与 SDK

- [ ] 定稿包格式、runtime、版本协商、必需/可选特性和旧包缺省语义。
- [ ] 同步 schema、类型、生成校验器、原生安装校验和协议兼容测试。
- [ ] 实现握手、生命周期、快照订阅/重同步、背压与错误模型。
- [ ] 实现动作请求与结果关联、过期拒绝、重复请求策略、取消和结果未知处理。
- [ ] 实现草稿确认、语义视图状态、受限资源服务和宿主强制挂起。
- [ ] 验证公共数据 SDK 无 DOM/框架依赖，框架封装无独立业务分支。

退出条件：支持、缺失、拒绝、不兼容与旧声明都有合同级测试。

### P2：宿主运行时与安装链路

- [ ] 实现 DOM 容器及资源加载，不向主文档注入第三方代码。
- [ ] 接入安装、选择、准备、预检、原子激活与取消，保持上一健康 release。
- [ ] 实现代际通道撤销、幂等释放、故障监测与强制恢复。
- [ ] 落实消息/资源上限、导航及网络策略、宿主服务授权和操作结果追踪。
- [ ] 验证旧主题/Worker 包及未覆盖 surface 的继承、禁用、卸载和重启恢复。

退出条件：真实 App 完成安装→激活→失败恢复→重新安装/挂载闭环。

### P3：独立插件与开发工具

- [ ] 提供 React/Svelte 构建模板和 Vue/原生 JS 最小挂载样例。
- [ ] 提供模拟快照、动作日志、能力组合和故障注入开发宿主。
- [ ] 在仓库外、无宿主源码的环境构建并安装 Svelte 与 React 完整工作台。
- [ ] 两个完整实现通过同一功能矩阵，含不支持能力和专业呈现降级。
- [ ] 完成插件作者文档、资源/组件库兼容限制及 SDK 离线安装验证。

退出条件：增加或更换框架不修改宿主业务代码，不能以两种配色替代两个框架证明。

### P4：默认呈现迁移

- [ ] 默认完整外观仅使用公共 SDK；添加禁止导入宿主私有实现的架构检查。
- [ ] 补齐功能矩阵中的公共合同缺口，保留内置可信恢复界面。
- [ ] Svelte↔React↔旧默认/Worker 切换保留草稿、附件、队列、审批和能力实例。
- [ ] 验证语义焦点、选区、消息锚点和布局恢复，以及目标消失时的降级。
- [ ] 验证连续输入/IME/流式更新、长历史、菜单、快捷键、拖放和窗口尺寸。

退出条件：默认外观无公共合同之外的业务特权，功能等价与交互证据完整。

### P5：发布验收

- [ ] 运行 pnpm run verify；原生改动运行对应 Rust 测试，跨模块生命周期变更跑完整 --lib。
- [ ] 实际 App 验证双内置皮肤、旧 Worker surfaces、新 DOM 完整呈现及所有受影响共享路径。
- [ ] 覆盖过期/跨会话/跨代际/伪造/重复动作、迟到读取和已发写入结果。
- [ ] 覆盖缺包、损坏、版本不兼容、启动失败、运行异常、死循环和资源压力。
- [ ] 按 P0 预算验证启动/切换/输入/流式性能与反复挂载后的资源回收。
- [ ] 逐支持平台记录真实 WebView、原生 IPC、安装升级、重启与宿主恢复证据。
- [ ] 更新支持矩阵、包合同、UI 架构、开发文档和交付审计；列明未验证平台及辅助功能范围。

最终完成条件：Svelte 与 React 的独立完整包通过同一协议和工作流验收；旧包兼容；
切换不改变业务事实；故障和恶意请求不能绕过宿主授权或使可信恢复失效。
浏览器替身 IPC、静态节点检查、文档或单一平台结果均不能替代对应原生验收。
